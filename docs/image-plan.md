# 教材の図を写真ふうの画像に替える計画（image-plan）

作成: 2026-11-04（Claude Code・設計担当）。教材ファイル（`content/*.js`）はまだ変更していない。この計画は、どの図を画像に替えるかの一覧と、画像の生成指示文をまとめたもの。

先生の指示: 「動物や植物などの解説は、図より写真のほうがよい。画像生成した図版の上に説明の文字を置く形にしたい。問題によっては写真ベースの図解のほうがよい場合もあるので、よく見直してほしい」

- 画像は ChatGPT の画像生成で作る（文字・ラベルなしの写真ふう、白背景、横長 4:3）。
- アプリでは画像を 320×240 の図の箱いっぱいに敷き、その上に今の部品（`text`・`line`（引き出し線）・`arrow`・`region`）を重ねる。
- 19 単元（`curriculum.js`・`readings.js` を除く）の解説カード 273 枚と、図のある問題すべてを見直した。

## 2. 選び方

### 画像にしたもの

- 生物のからだ・器官・細胞（顕微鏡で見たようす）・植物の各部・動物の姿、生態系の生物
- 岩石・鉱物・化石・地層・火山・雲や空・気象衛星の雲画像
- 天体（月の形・日食と月食・太陽・惑星・星の動き）
- 実験器具や装置の実物感（上皿てんびん・メスシリンダー・蒸留装置・電気分解装置など）、物質の色や結晶の形
- 「実物の見た目」を知ること自体が学習になるもの（入試や定期テストで写真が出るもの）

### 簡略図のまま残したもの

- 光線の作図（light のほぼすべて）、グラフ（溶解度曲線・飽和水蒸気量・P波 S波・体温と気温 など）、回路図、力の矢印、粒子モデル・原子や分子のモデル・イオンのモデル、化学反応式、計算の図、遺伝の表
- 分類の流れ図、食物連鎖のピラミッドや炭素の循環、気圧配置・前線の断面、天体の位置関係（北極側から見た図）など「しくみ・関係」が本質のもの
- 模式図のほうが正確に伝わるもの（細胞のつくりの模式図、心臓の 4 つの部屋、維管束の拡大、体細胞分裂の順序、染色体の数 など）

### 座標を使う問題の扱い

- `drag` と `ray-draw` の問題は、**すべて簡略図のまま**にした。判定が部品の座標（例: plants-1-p3 の柱頭 (160, 90)）と `samples`（tests/content-all.test.js で確かめる正解例・不正解例）に結びついているため。
- もし将来、drag の問題を画像に替えるときは「画像の上に同じ座標で部品を置く」前提で、画像の中の目的の部分が今の座標に来るように画像を作る（または座標と samples を書きかえてテストを直す）。この計画では行わない。
- `figure-choice`（region を選ぶ）の問題は、region を画像の上に置けばよいので、必要なものだけ画像にした。region の座標は画像ができてから決める。

## 3. 画像の作り方の決まり

### 生成と仕上げ

1. 下の生成指示文を、1 枚ずつ ChatGPT に貼る（1 回の会話で 1 枚。前の画像の影響を受けにくい）。
2. ChatGPT は 4:3 ちょうどの大きさで出せないことがあるので、横長（1536×1024 など）で作り、**左右を切って 4:3 にする**。指示文に「大事なものは中央に」と入れてある。
3. **640×480 px の PNG** に縮める（320×240 の箱の 2 倍。高解像度の画面でもぼやけない）。1 枚 200 KB 以下を目安に減色・圧縮する。
4. 保存先は `assets/images/<単元id>/<カードや問題のid>.png`（例: `assets/images/plants/plants-1-c1.png`）。1 枚のカードに 2 枚目を足す案だけ `-2` などの接尾辞を付けた。
5. 画像に文字・数字・矢印・枠線が入ってしまったら作り直す（ChatGPT は指示しても文字を入れることがある）。

### 指示文の決まり（全 113 枚に共通）

各指示文には次をかならず入れてある。

- 「中学理科の教材用の画像」
- 「写真のようにリアル」
- 「白い背景」（風景・空・夜空のものは「まわりを白くぼかして白い背景に溶けこませる」。顕微鏡の写真は「白い背景の上に、丸い顕微鏡の視野として」）
- 「文字・ラベル・矢印は一切入れない」
- 「横長 4:3」
- 「〜がはっきり見える構図」
- 「まわりに余白を残す」（重ねる文字を置く場所）

いくつかの生物や物を 1 枚に並べるときは「パネルの間は白い余白で区切る（線や枠は入れない）」とし、並べ方（左から・上段と下段 など）を指定した。region やラベルの位置を決めやすくするため。

### 先生の確認（いちばん大事）

生成した画像は、理科として正しくないことがよくある（あしの数、花弁やおしべの数、細胞の形、地層の重なり、月の光る側 など）。**各画像の「確認」に書いた点を先生が見てから使う**（設計書 10「理科としての正しさは先生が確認する」）。まちがっていたら作り直すか、その図は簡略図のままにする。

## 4. アプリ側の実装メモ（実装指示書を書くときの材料）

この計画の範囲外だが、画像を組みこむときに必要になること。

1. **画像の部品を足す**: `js/figures.js` に `{ type: 'image', src, x?, y?, width?, height?, alt }` のような部品を足す（既定は場面いっぱいの 0, 0, 320, 240）。`items` のいちばん先に置き、ほかの部品を上に重ねる。`src` は `assets/images/` の下だけを許す（外部の URL は使わない）。`docs/figures-guide.md` に追記する。
2. **文字を読みやすくする**: 写真の上の文字は読みにくいので、`text` に白いふち取り（`stroke` を白で太く、`paint-order: stroke`）か、白い半透明の下じきを付ける項目（例 `halo: true`）を足す。引き出し線（今の `leader()` と同じ点線）は、写真の上では白ふちの付いた濃い線にする。
3. **region**: 今の region（ア・イ…の丸）を画像の上に置き、引き出し線で指す部分につなぐ。問題文の「（ア: 図の左上の…）」のような位置の説明は、画像に合わせて見直す。
4. **画像が読めないとき**: 画像が読みこめないと図が空になるので、`alt` の文を図の下に出すか、今の簡略図を残しておいて差しかえる形にする（`figure` に `fallback` を持たせる など）。
5. **オフライン**: `sw.js` のキャッシュに画像を足し、版（SW の版）を上げる。113 枚 × 200 KB ≒ 23 MB になるので、全部を最初に読みこむのではなく、単元を開いたときに読みこむ形がよい。
6. **テスト**: `tests/content-all.test.js` に「`image` の `src` のファイルが実在する」「region の id がそろっている」確認を足す。
7. **差しかえの単位**: 1 単元ずつ（A の 5 単元から）。drag・ray-draw の問題には手を付けない。

## 9. 決めたこと（判断の記録）

- 生物の解説カードは「写真寄り」にした。ただし、模式図でないと伝わらないもの（細胞の模式図・心臓の 4 部屋・維管束の拡大・分裂の順序・相同器官の骨の色分け・柔毛の中の管）は簡略図のまま残した。
- 問題は「写真で見分ける力」が要るもの（5 つのなかまの動物、節足動物 3 種、葉脈と根の 4 択、結晶の形、イカの解剖、消化器官、マツのりん片）だけを画像にした。
- 並び順がちがう 2 問（例 volcano-2-p2 と r1、strata-4-p4 と r4）は、画像だと 2 枚要るうえ写真の差がまぎらわしいので、簡略図のままにした。
- drag・ray-draw の問題は 1 問も画像にしない（判定と samples が座標に結びつくため）。
- 1 枚のカードに 2 枚の画像が要る場合は、カードを足す案（volcano-2-c4-2、weather-3-c4 の断面、light の 2 枚）として書き、作るかどうかは先生の判断にまかせた。
- 風景・空・夜空の画像は「白い背景」と両立しないので、「まわりを白くぼかして白い背景に溶けこませる」形にした。顕微鏡の写真は「白い背景の上の丸い視野」にした。
- 気象衛星の雲画像・化石・動物などは生成した画像で、本物の写真ではない。先生が確認したうえで「イメージ」として使う。
