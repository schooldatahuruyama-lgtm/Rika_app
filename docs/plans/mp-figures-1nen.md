## 実装の前に決めること（この精査で見つけた制約）

1. **動く図の使い回しは、今のテストでは通らない。** `tests/content-all.test.js` の「1 kind ＝ 1 カード（全単元で重ならない）」と「登録した kind はちょうど 1 枚のカードが使う」の 2 つのテストが、同じ kind を 2 枚目のカードに付けることを拒む（光の 23 種も前者の対象）。使い回しの 15 枚を入れるには、次のどちらかが要る。
   - 案 A（おすすめ）: テストに「使い回しを許すカード → kind」の表（例 `ANIM_SHARED = { 'sound-mp2-c1': 'so-light-vs-sound', ... }`）を足し、その表のカードだけ 2 枚目を許す。カード側は `anim: '<kind>'` を書くだけになる。
   - 案 B: 同じ関数を別名で登録する（例 `['so-light-vs-sound-mp', soLightVsSound, { restT: 0.99 }]` を DEFS に 1 行）。動きの式は書かないが、kind の数は増える。
2. **静止図の文字の整合**（光以外）: 使い回しのカードも「静止図の text が `frame(kind, restT)` に同じ文字・同じ座標である」テストを受ける。下の使い回し表の「静止図」欄に、通るかどうかを書いた（同じ／部分集合なら通る、文字がちがうものは静止図の文字を合わせる）。
3. **光の使い回し**は文字の整合を見ない（`ANIM_LEGACY_UNITS`）が、動いている間はもとのカードの絵になる（ミニプリントの静止図とラベルが少しちがう）。気になるカードは、静止図をもとのカードの図に替えるか、新しい kind にする。
4. **basics の接頭辞**がない。`ANIM_PREFIX` と `docs/anim-guide.md` の表に `basics: 'ba-'` を足す（ファイルは `anim-bio.js`。顕微鏡・観察の器具なので生物の分野に置く。ろうそくの燃焼 `ba-candle-air` も同じファイルに置き、単元で 1 か所にまとめる）。
5. **光の新しい kind**（`li-lens-cover`）は、`tests/anim.test.js`（光 23 種）を変えないため `anim.js` の `BUILD` には足さず、`anim-physics.js` の `register` で足す。光は接頭辞の検査の対象外だが、名前は `li-` で始める（`ANIM_PREFIX` に `light: 'li-'` を足す必要はない）。
6. **写真の部品**: `content/basics.js` には `photo()`・`pointer()`・`tag()` がないので、`content/plants.js` と同じものを足す（保存先 `assets/images/basics/`。`.jpg`）。
7. **写真に替える問題の文**: 位置や色の説明（「黄色の粒」「上から見た」など）を写真に合わせて直す（下の表の「region の置き方」に書いた）。並びが変わる問題は `answer` も合わせる。
