## 1. 何のために作るか

中学生が、1回3〜5分の短い学習（解説 → 予想 → 問題 → フィードバック）を積み重ねて、中学理科を自分のペースで理解できるようにする。正解率だけでなく、挑戦・復習・継続を経験値として評価し、「間違えても復習で伸びた」ことを本人に見せる。

試作1は中1「光の世界」1単元に限定し、先生が架空の生徒データで検証する。学校での実運用（ログイン、オンライン保存、実在生徒の登録）は試作1の範囲外。

参考にした考え方（NewsPicks の Workschool 回、2026-10-31）:
「学習意欲を本人任せにせず、つい学んでしまう環境を設計する」。超短時間学習、ゲーミフィケーション、チーム学習、学習コミュニティ、習慣化の5要素のうち、試作1は「一人でも楽しく学べる」部分だけを作る。チーム学習・コミュニティ（班の協力クエスト、応援、学びの共有、希望者ランキング）は第2段階で、ホームに「準備中」のカードを置くだけにする（2026-11-03 ユーザー決定）。

## 2. ゴール・やらないこと・失敗の条件

### ゴール（試作1で確かめること）

要件定義書「試作品の検証項目」1〜6 をそのまま採用する。

1. 「光の世界」の学習マップを選んで進められる。
2. 各ステージで「解説から」「問題から」のどちらからでも始められる。
3. 選択式・穴埋め・図を使った問題・画面操作型問題がタブレットのタッチで無理なく操作できる。
4. 誤答に応じて、解説 → 類題 → 基礎への学び直し → 元のステージへ復帰、が動く。
5. 正解以外の取り組み（挑戦・復習・継続・学び直し）が経験値に反映される。
6. 一度読み込んだ教材を通信を切っても使え、学習記録が端末内に残る。

### やらないこと（試作1）

- ログイン、オンライン保存、端末間の引き継ぎ、同期
- 班の協力クエスト、応援、学びの共有、ランキング（ホームに「準備中」カードのみ）
- AI による問題生成、先生用の確認画面、教材の編集画面
- 課題配信、PDF・Word への書き出し
- 「光の世界」以外の単元（ただし教材データの形は他単元を追加できる形にする）
- 実在生徒の登録（架空の生徒プロフィールのみ）

### 失敗の条件（できていても失敗とみなす）

- 経験値やレベルが高いことと、科学的に理解できていることの区別がつかない画面。理解度の目安は経験値とは別に表示する。
- 間違えた生徒を責める表現、失敗を強調する演出（赤い大きな ×、減点の目立つ表示）。
- 1回の学習が細切れすぎて、光の進み方を考える時間がない（解説カードだけで終わり、作図や考察がない）。
- タブレットで指では操作できない問題（小さなドラッグ対象、ホバー前提の操作）。
- 教科書の本文や図版の転載。教材の文章と図はすべてオリジナルで書く。
- 端末のデータが消えることを画面で知らせていない。

## 3. 制約

- 学校タブレット（Chrome または Edge、画面幅 768px 前後、タッチ操作）と、家庭のスマホ（幅 375px）・PC で使える1つの Web アプリ。縦向きを基本に、横向きでも崩れない。
- 初回はオンラインで読み込み、その後は通信なしで解説・問題・判定・経験値付与・記録が続く。
- 記録は端末内のみ。ブラウザのデータ削除や端末の変更で記録が消えることを、設定画面とプロフィール作成時に明示する。
- 架空の生徒だけを扱う。実名を入れさせない注意書きを出す。
- 外部サービスへの送信なし。外部ライブラリなし（前回の時間割アプリと同じ方針。インストール不要で動く）。
- 教材の著作権: 文章・図は自作。教科書名・出版社名は書かない。

## 4. 利用者から見た動き（決めたこと）

### 4.1 画面一覧

| 画面 | 役割 |
|---|---|
| プロフィール選択 | 初回に架空の生徒を1人作る（ニックネーム、アバター）。複数作って切り替えられる（先生が複数の生徒を演じるため）。実名を入れない注意と、端末内保存の注意を出す |
| ホーム | 「今日のクエスト」「レベルと経験値」「連続学習」「学習マップへ」「記録を見る」「班の協力チャレンジ（準備中）」のカード |
| 学習マップ | 「光の世界」の4領域（光の直進 → 反射 → 屈折 → 凸レンズ）の道にステージが並ぶ。各ステージに状態（未着手・途中・クリア）と星（0〜3）。領域は好きな順に選べる。領域内のステージは順に解放 |
| ステージ入口 | ステージ名、約何分、扱う内容、「解説から学ぶ」「問題から挑戦」の2つの大きなボタン |
| 解説ビュー | 解説カードを1枚ずつめくる（2〜4枚）。各カードは短い文と図（SVG）。最後に「予想してみよう」1問（選択式、正誤は経験値に影響せず、答えた後に短い解説） |
| 問題ビュー | 問題を1問ずつ出す。答えると即時フィードバック（正解 / おしい）。誤答時は解説の抜粋 → 類題。学び直しの提案はここで出る（4.3） |
| 結果 | 「できたこと」「復習で伸びたこと」「獲得した経験値の内訳」「次のおすすめ」。レベルアップ時はマスコットが祝う |
| 記録 | 進捗（領域ごとのクリア数）、理解度の目安（概念ごとに「まだ / もう少し / できた」）、取り組み履歴（日付、ステージ、結果）、経験値とレベル、連続学習日数 |
| 設定 | プロフィールの切り替え・作成・削除、記録の JSON バックアップと復元、「端末内保存のため消える可能性がある」注意、教材の読み込み状態（オフラインで使える教材の一覧）、すべて削除 |

### 4.2 1回の学習（クエスト）の流れ

```
ステージ入口
  ├─ 解説から学ぶ: 解説カード(2〜4枚) → 予想(1問) → 問題(4〜5問) → 結果
  └─ 問題から挑戦: 問題(4〜5問) → 結果
                      └─ 途中で「解説を見る」ボタンでいつでも解説カードへ戻れる
```

1回の目安は3〜5分。問題数は教材データで決める（暫定: 1ステージ 4〜5問）。

### 4.3 誤答時の学び直し（暫定ルール。設定ファイルで変更できる）

各問題には「概念」（例: 反射の法則）が1つ付く。各概念には「基礎になる概念」が0個または1個付く（例: 鏡に映る像 → 反射の法則）。

1. 誤答: 「おしい」と表示し、その問題の解説（短い）を見せる。次に同じ概念の類題を1問出す。
2. 類題も誤答（同じ概念で2回続けて誤答）: その概念に基礎概念があれば「〇〇に戻って確かめよう」と提案する。「戻る」「あとで」のどちらも選べる（強制しない）。
   - 戻る: 基礎概念の確認問題を2問出す。2問とも正解なら元のステージの続きに戻る。1問でも誤答なら基礎概念の解説カードを見せてから、もう一度確認問題（1問）。それでも誤答なら「今日はここまで。明日また挑戦しよう」と結果画面へ（経験値は挑戦分が入る）。
   - あとで: 元のステージの続き。結果画面に「〇〇を確かめるのがおすすめ」と出す。
3. 基礎概念がない場合: 類題の後は解説カードを見せて続きに進む。

類題は教材データの「類題プール」から出す。プールが尽きたら、解説を見せて続きに進む。

### 4.4 理解度の目安（暫定）

概念ごとに 0〜1 の値を持つ。更新: 1回目で正解 +0.25、類題や学び直しの後で正解 +0.15、誤答 −0.20（0〜1 に収める）。表示は 3段階: 0.4 未満「まだ」、0.8 未満「もう少し」、0.8 以上「できた」。経験値とは別物として扱い、記録画面でも別のカードに置く。

### 4.5 経験値・レベル・連続学習（暫定。設定ファイルにまとめる）

| 行動 | 経験値 |
|---|---|
| 問題に答える（正誤を問わず、1問につき1回まで） | +10 |
| 正解 | +10 |
| 1回目で正解 | さらに +5 |
| 誤答後の類題で正解（復習で伸びた） | +15 |
| 学び直しに戻って確認問題を終える | +20 |
| 解説カードを最後まで読む | +10 |
| ステージを最後まで終える | +50 |
| 今日はじめて学習する（連続学習の日数分、上限 +50） | +10 × 連続日数 |

数え方（決めたこと）:

- 「1問につき1回まで」「1回目で正解」は、そのステージへの今回の挑戦（入口から結果画面まで）の中で数える。再挑戦すれば数え直す。
- 経験値のかせぎ過ぎを防ぐため、クリア済みのステージへの再挑戦で得られる経験値は半分にする（暫定）。復習クエスト（4.6）は 1 概念につき 1 日 1 回だけ全額、2 回目からは半分。
- 誤答後の類題と学び直しの確認問題は、ステージの問題（4〜5問）の外側に加えて出す。類題への正解は「復習で伸びた」の経験値になり、星の計算には入れない。
- 理解度の「1回目で正解」も今回の挑戦の中での1回目を指す。

レベルは累積経験値のしきい値表で決める（暫定: Lv2=100, Lv3=250, Lv4=450, Lv5=700, 以後 +300 ずつ）。レベルアップ時はマスコットが祝う短い演出（1〜2秒、スキップ可）。

連続学習日数: その日に1問でも答えたら「学習した日」。前日も学習していれば +1、空いたら 1 に戻る。ホームに曜日7つの印で今週の学習日を見せる（Workschool のストリーク表示を参考）。

### 4.6 今日のクエスト（おすすめ）

ホームの「今日のクエスト」は次の順で1つ決める。

1. 理解度が「まだ」で、最後に取り組んでから1日以上経った概念があれば、その概念の復習クエスト（類題プールから3問）。
2. なければ、途中のステージ。
3. なければ、未着手の最初のステージ（領域の順: 直進 → 反射 → 屈折 → 凸レンズ）。
4. 全部クリア済みなら、理解度が一番低い概念の復習クエスト。

### 4.7 ステージのクリアと星

- ステージの問題を最後まで終えたら「クリア」。正解率に関係なく次のステージが解放される（途中で「今日はここまで」になった場合は「途中」のまま）。
- 星: ステージの問題（類題・確認問題を除く）のうち、今回の挑戦で1回目に正解した割合で 3段階（暫定: 50% 未満 ★、80% 未満 ★★、80% 以上 ★★★）。再挑戦で星は上書き（上がるときだけ）。

## 5. 教材（光の世界）

### 5.1 領域とステージ（試作1の内容）

4領域 × 2ステージ = 8ステージ。各ステージの文章・図は自作する。

| 領域 | ステージ | 概念 | 基礎になる概念 |
|---|---|---|---|
| 光の直進 | 1. 光はまっすぐ進む（光源、光の道すじ、影） | 光の直進 | なし |
| 光の直進 | 2. ものが見えるしくみ（光源と物体、目に届く光） | 光の直進 | なし |
| 光の反射 | 1. 反射の法則（入射角＝反射角） | 反射の法則 | 光の直進 |
| 光の反射 | 2. 鏡に映る像（像の位置、見える範囲） | 鏡の像 | 反射の法則 |
| 光の屈折 | 1. 屈折の向き（空気⇄水・ガラス、境界で折れ曲がる） | 屈折の向き | 光の直進 |
| 光の屈折 | 2. 水中のものの見え方と全反射（浮いて見える、折れて見える、光が出てこない） | 屈折の見え方 / 全反射（問題ごとにどちらかを付ける） | どちらも 屈折の向き |
| 凸レンズ | 1. 焦点と光の集まり方（平行光、焦点距離） | 焦点 | 屈折の向き |
| 凸レンズ | 2. 実像と虚像（物体の位置と像の位置・大きさ） | レンズの像 | 焦点 |

### 5.2 問題の形式（試作1で実装する代表形式）

| 形式 | 動き | 判定 |
|---|---|---|
| 選択式 | 2〜4つの大きなボタン | 正解の選択肢 |
| 穴埋め | 文中の空欄に、語群から選ぶ、または数値を入力（角度など） | 語群は一致。数値は許容誤差つき（例: ±2°） |
| 図を使った選択 | SVG の図の中の領域（例: 鏡で反射した光が進む先の候補 A〜D）をタップ | 正解の領域 |
| 光線を引く | 図の中の点（光源）から指でドラッグして光線を引く。反射・屈折の場合は境界で折れた先の方向をドラッグで決める | 反射: 角度の許容誤差（暫定 ±5°）。屈折: 向きで判定（下記）。凸レンズ: 決まった光線が通る点で判定（下記） |
| 光学要素を動かす | 物体や鏡・レンズを指でドラッグして位置を変える。例: 「像がスクリーンに映る位置に物体を置こう」 | 位置の許容範囲 |

操作型の2形式は、ドラッグ対象を指で押さえられる大きさ（44px 以上）にし、ドラッグ中は現在の角度・位置を数値でも表示する（屈折の問題では角度の数値は出さず、「法線に近づく / 離れる」の向きを示す）。マウスでも操作できる（Pointer Events を使う）。

「光線を引く」の判定（決めたこと。中1 の扱いに合わせ、屈折の法則の計算はしない）:

- 反射: 正解の反射角は入射角と同じ。引いた光線の角度が許容誤差（暫定 ±5°）に入れば正解。
- 屈折: 正解は「向き」。引いた光線が (a) 境界の反対側に出ていて、(b) 法線をはさんで入射光と反対側にあり、(c) 空気→水・ガラスなら入射光の延長より法線に近い側、水・ガラス→空気なら法線から遠い側、の3つを満たせば正解。角度の細かい値は問わない。
- 凸レンズ: 扱う光線は3本の決まった光線（軸に平行 → 焦点を通る、中心を通る → 直進、焦点を通る → 軸に平行）だけ。引いた光線が通るべき点（焦点、レンズの中心、または軸と平行）からのずれが許容範囲（暫定: 図の中で 12px 以内、平行は ±5°）なら正解。

各ステージは少なくとも1問は図を使った問題か操作型問題を含む。選択式だけのステージを作らない。

### 5.3 教材データの形（決めたこと）

教材は JavaScript のデータファイル（`content/` 配下、1単元1ファイル）として同梱する。将来の他単元は同じ形のファイルを追加する。

```
単元 { id, title, areas: [領域] }
領域 { id, title, order, stages: [ステージ] }
ステージ { id, title, minutes, concepts: [概念id], lessons: [解説カード], warmup: 問題, problems: [問題], retryPool: [問題] }
解説カード { id, text, figure }           // figure は SVG を返す描画の指定（作る人に任せる）
問題 { id, type, concept, prompt, figure, (形式ごとの項目), explanation, hint }
概念 { id, title, basic: 概念id | null, checkPool: [問題] }   // checkPool は学び直しの確認問題
```

- `retryPool` は概念ごとに 2 問以上。`checkPool` は 3 問以上。
- 問題の `type` は `choice` / `fill` / `figure-choice` / `ray-draw` / `drag` の5種類。
- 図は SVG を JavaScript で組み立てる（画像ファイルにしない。差し替えやすく、オフラインでも軽い）。

## 6. 記録と保存（決めたこと）

- 保存先は `localStorage`。キーは `rika-quest:v1`。中身は 1 つの JSON（プロフィール一覧、プロフィールごとの記録）。
- 記録の内容: 解答履歴（日時、ステージ、問題、概念、正誤、何回目か、学び直しかどうか）、ステージ状態（未着手/途中/クリア、星、途中の位置）、概念ごとの理解度、累積経験値、レベル、連続学習日数と最終学習日、解説カードを読んだ記録。
- 設定画面から JSON で書き出し・読み込みできる（前回の時間割アプリと同じ）。
- スキーマに `version` を持ち、将来の変更時は読み込み時に変換する。
- 壊れた JSON を読み込んだら、消さずに別キーに退避し、画面で知らせる。

## 7. オフライン（決めたこと）

- Service Worker で、アプリ本体（HTML、CSS、JS）と教材データ（`content/`）を初回に全部キャッシュする（キャッシュ優先、更新は次回のオンライン時）。
- 設定画面に「オフラインで使える教材」の一覧と、キャッシュの状態（済み / 未）を表示する。
- Service Worker は `http(s)://` または `localhost` でしか動かない。`index.html` をダブルクリックで開いた場合（`file://`）はアプリは動くがオフライン対応は効かない。画面にその旨を小さく表示する。
- ホーム画面に追加できるよう `manifest.webmanifest` を置く。

**作る人への注意:** 教材を JavaScript のデータファイルにしたのは、`file://` でも `fetch` なしで読めるようにするため。

## 8. 見た目（決めたこと）

Workschool のアプリ画面を参考にする。

- 配色: 鮮やかな青（例: `#1A5CFF` 付近）を背景とアクセントに、白い角丸カード（角丸 16px、薄い影）。正解は緑、おしいは黄色〜オレンジ（赤は使わない）。
- マスコット: 小さなオレンジ色の生き物（SVG）。ホームと結果画面に出る。レベルアップ時に祝う。名前と見た目は作る人に任せる（ユーザーが後で変えられるよう、1か所にまとめる）。
- 文字: 本文 18px 以上、ボタンは高さ 56px 以上、タッチ対象は 44px 以上。
- 1画面1つのこと。ホームは縦にカードが並ぶ。学習マップは縦スクロールの道。
- 「おしい」の画面は、正解を責めずに「ここを見直そう」と次の一歩を示す。
- ダークモードは作らない。

## 9. 技術（決めたこと）

- HTML + CSS + JavaScript のみ。ビルドなし、外部ライブラリなし、npm の依存なし（前回と同じ）。
- JavaScript は `<script>` で読み込む普通のスクリプト（ES Modules は `file://` で動かないため使わない）。
- ロジック（判定、学び直しの分岐、経験値、理解度、今日のクエスト、保存の変換）は画面から切り離し、Node.js の標準テスト（`node --test`）で検証する。暫定の数値はすべて `config` にまとめる。
- 画面の動作確認は Chrome/Edge で行う。タブレット相当の幅（768px）とスマホ幅（375px）を確認する。
- 試作1の完了条件（2026-11-03 ユーザー決定）: PC の Chrome/Edge で幅 768px と 375px の表示・操作を確認し、`localhost` の簡易サーバー（`python -m http.server`）で Service Worker によるオフライン動作を確認するまで。本物のタブレットでの確認と、GitHub Pages などへの配置は試作1の後に決める。

## 10. 開発の進め方（決めたこと）

前回の時間割アプリと同じ仕組みを、このフォルダに作る。許可も前回と同じ（2026-11-03 ユーザー決定）: ユーザーへの確認なしで進めてよい（`git init`、CLAUDE.md などの作成、ファイルの上書き、コミット）。未定の点は要件定義書とこの設計書に沿って Claude Code が判断し、報告に書く。自作教材の理科的な正しさは、完成後にユーザー（理科教員）が確認する。

| 役割 | 担当 |
|---|---|
| 設計・判断・指示書 | Claude Code（Fable のこのセッション） |
| コードを書く | Claude Code のサブエージェント（Opus）。指示書（`.ai-tasks/`）に沿って書く |
| レビュー | Codex（`tools/codex-review.ps1`、読み取り専用）。使えないときは実装に関わっていない別の Claude エージェント |
| 最終確認・コミット | Claude Code |

- `CLAUDE.md`、`AGENTS.md`、`tools/codex-review.ps1`、`tools/codex-implement.ps1`、`.ai-tasks/`、`.ai-review/` の運用は前回のものをこのフォルダ用に直して使う。

- 作業の単位は「1ステージの流れが動く」など、ユーザーが触って確かめられる大きさにする。
