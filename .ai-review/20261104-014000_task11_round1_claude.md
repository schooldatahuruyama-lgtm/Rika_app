## 良い点
- XSS 対策が徹底している。利用者由来の文字（ニックネーム、読み込んだ JSON 内の値、教材の title）は `el()` の `text`（textContent）か `createTextNode` 経由のみ（`js/ui-screens.js:33-58`）。`innerHTML` は `svgBox()` の 1 箇所（`:63`）だけで、渡すのは `mascot.svg(96)`。`grep` でも `innerHTML` 等はそれだけ。`confirm-text` / `message` / header も textContent。アバターは固定リスト（`avatarOf`）に引き当てるので、読み込んだ JSON の `avatar` 値が class や HTML に入ることもない。
- 記録の扱いが契約どおり。`setRecord` は新しい record を `store.records[id]` に入れて save する薄い関数で、record の関数が純粋（新オブジェクトを返す）という前提と合っている。`createProfile` / `deleteProfile` だけ store を直接変える点も `record.js` の約束どおり。
- `ctx.store` / `ctx.record` を getter にしたため、`replaceStore` の後でも古い store を掴まない（画面は `go` で再描画）。
- 失敗した読み込みは `importJson` が error を返した時点で store に触れずに終わる。成功時だけ確認ダイアログ→置きかえ。
- アクセシビリティの基本が押さえられている。操作は `button`、入力は `label[for]`、アバター選択は `aria-pressed`、マップのノードに状態つき `aria-label`、ロック中は `disabled`、XP バーは `role=progressbar`、確認ダイアログの初期フォーカスは安全側の「やめる」、`:focus-visible` のアウトラインあり。
- 赤を使わず、「削除」系は濃い枠で区別。ボタン 56px 以上、本文 18px 以上、タッチ対象も確保。
- 描画関数が関数を返すと次の `go` の前に呼ぶ後片付けフックを用意しており、Task 12 のポインター操作に使える。
