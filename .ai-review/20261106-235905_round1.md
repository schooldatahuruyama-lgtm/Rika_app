## 概要

指定された未コミット変更を、指示書・設計書14章と照合しました。REST の基本形、マルチパス更新、textContent による表示は概ね整合しています。

## Claude Code の対応
- #1 High（古い受信データで採点）: **対応する**。答え合わせで採点する前に REST の GET で answers/<qid> と players をサーバーから取り直す（修正指示書 .ai-tasks/20261107-010000_ライブクイズ_修正1.md）。
- #2 High（答え合わせ中に未接続だと記録が欠ける）: **対応する**。受信した部屋データの answers から、自分の確定済みの回答で未反映のものをまとめて反映する（phase に関係なく、その問題が reveal 済み・ended なら）。
- #3 High（送信失敗の回答が記録される）: **対応する**。記録はサーバーで確認できた回答（watch の answers[qid][pid]）だけに限る。answering は表示だけ。
- #4 High／#5 Medium（プロフィールの取り違え）: **対応する**。参加時のプロフィール id と描画世代を持ち、完了時と記録時に照合。記録済みキーに参加者 id を含める。
- #6 Medium（切断の通知）: **対応する**。最初の切断で「再接続しています」、10 回失敗で「接続できません」を分けて通知。
