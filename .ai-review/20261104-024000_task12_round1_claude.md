# Claude レビュー結果（Task 12 / round 1）

## 仕様適合
- ❌ 問題あり:
  - **fill の同じ空らん id の重複（lens-1-p5）に対応していない。** `js/ui-problems.js:210` の `slots[b.id] = slot` は、2 回目の `[b1]` で 1 回目の枠を上書きする。語群のボタン（`js/ui-problems.js:228`）は `slots[b.id]`（＝最後の枠）だけを書きかえるので、lens-1-p5 では「焦点」を選んでも文中の 1 つ目の「①」は空のまま残る。解答の値（`{ b1: '焦点', b2: … }`）は正しく作られるので判定はできるが、画面の表示がうそになる。数値の空らんが重複した場合も `inputs[b.id]`（`js/ui-problems.js:200`）が最後の input だけを持つので、`disableAll` が 1 つ目の input を止めない。要求（「同じ選択を共有する形が望ましい」）を満たしていない。報告の確認手順にも lens-1-p5 は入っていない。
- ⚠️ 差分だけでは確認できない / 判断が要るもの:
  - **ray-draw の段階 1 を省ける作り**（`js/ui-problems.js:452`）。指示書は「1 回目のドラッグ: source から … 2 回目: hit から」の 2 段階だが、当たった点の近くを押すと段階 1 を済んだことにする。教材の問い（「当たった点から指で引こう」。content/light.js の ray-draw の大半）とは合うが、指示書とは違う。報告は懸念 1 で開示している。どちらにするかは利用者が決めること。今のままだと、問いの文は「当たった点から」、部品の案内（`instruction()` の「① 光源から○○まで、指でなぞって光を引こう」）は「光源から」と、生徒には食い違う 2 つの指示が並ぶ。
  - タッチ端末での実際の指の操作（実機・DevTools のタッチエミュレーション）は未確認（報告の懸念 6）。指示書 Step 3 は DevTools のタッチエミュレーションでの確認を求めている。コードは Pointer Events＋`touch-action: none`（CSS と `svg.style.touchAction` の両方）＋`setPointerCapture` なので、動く見込みは高い。
  - 報告は `npm test` 102 件成功と書いているが、出力そのものは貼っていない（警告やノイズがあったかは分からない）。この差分で自動テストは足していない（画面だけの変更で、計画もブラウザでの確認としている）。

それ以外の要求は、差分と契約（session.js・record.js・judge.js）を照らして満たしていることを確かめた:
- セッションの流れ: `answer`/`next`/`choose` の events はすべて `commitSession`（`js/app.js:247`）を通って `record.applyEvents(rec, events, { now, multiplier: newSession.xpMultiplier, stageId: newSession.stageId }, config)` に入る。`choose` も同じ道を通る（stageClear も入る）。`kind === 'stage'` のときだけ `setResume`。`current()` が ended なら `closeRecord`（`js/app.js:263`）で `finishStage({ stageId, stars, cleared: ended === 'completed' })` / `markReviewDone(conceptId, localDate(now))`。finishStage は resume を null にするので、終わった session が resume に残らない。
- XP の二重加算なし: `session.answer` は `pending` を立てた session を返し、`applyEvents` と `setResume(pending の session)` を同じ `setRecord` でまとめて保存する。再読み込み後は `current()` が `feedback` を返し、`renderProblem` はフィードバックだけを出して `answer` を呼ばない。再確認の誤答で `ended: 'stopped'` になった解答も、pending が先に効くのでフィードバック → `next` → ended → `closeRecord` の順になる。
- 解答の形は judge.js どおり: choice → optionId、fill → `{ [blankId]: 値 }`（数値は `Number`）、figure-choice → regionId、ray-draw → `{ out: { x, y } }`、drag → `{ x, y }`。drag の基準点（object は `x,y`、screen は `x` と `(y1+y2)/2`）は、教材の `target` と同じ座標の取り方。axis 'x' の問題では y は判定に使われない。
- 座標変換は `getScreenCTM().inverse()`、吸着は `config.tolerance.snapPx`。境界の「法線に近づく / 離れる」は `angleToNormalDeg`（向きを問わない線の角）で比べるので、水→空気（光が上へ進む）でも符号が逆にならない。judge の `bendOk` と同じ比べ方。
- invalid のときは部品の状態を残して「もう一度操作してね」、`makeSubmitter` が有効な解答を 1 回に限る（二重送信も `busy`/`done` で止める）。
- 「解説を見る」: `lessonStageForProblem` は stage の warmup/main/retry なら `session.stageId`、check（再確認の `recheck: true` も phase は 'check'）と review なら `reg.concept(problem.concept).lessonStageId`。フィードバック画面では `pending.phase` を使うので、解答後も同じ参照先。dialog を開くだけで events を出さない。画面を移るとき `closeLessonDialog` で閉じる。
- XSS: innerHTML は `figures.sceneSvg` と `mascot.celebrateMarkup`（文言は `escapeText` 済み）だけ。教材・ニックネームの文字はすべて `textContent`/`createTextNode`。`querySelector` に入れる id は `cssEscape` を通す。
- 色と言葉: 正解は緑（`--ok`）「正解！」、誤答はオレンジ（`--warn`）「おしい」＋「ここを見直そう」＋explanation＋ヒント。赤は使っていない。

## 良い点
- app.js の進行がよく閉じている。`commitSession` 1 か所に「applyEvents → setResume（stage だけ）→ ended なら closeRecord → setRecord（1 回の保存）」を集め、`answer`/`next`/`choose` が同じ道を通る。保存が 1 回なので、XP と再開位置が食い違う時間がない。
- 教材が変わって保存した続きの step が見つからない場合（`viewIsBroken`）に、resume を消して入口へ戻す扱いがある。
- `makeSubmitter` で「有効な解答につき 1 回」「invalid なら再送信」を 5 形式で共通にしている。
- ray-draw の細部（8px 未満のドラッグを無視して前の線に戻す、`pointercancel` で元に戻す、引き直し、図に法線がないときだけ案内の点線）。境界で角度の数値を出さない設計書 5.2 の決まりを守っている。
- figure-choice・drag はキーボードでも操作できる（`tabindex`、Enter/Space、矢印キー）。
- 結果画面の XP 内訳を xpLog（今回の分）から集計しており、record に別の集計を持たせていない。レベルアップの重ねは 1 回だけ、タップ・キー・時間で消え、画面を移るときに片付ける。
