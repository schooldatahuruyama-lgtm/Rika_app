## 節 2: 図の部品 `image` round 1

### 概要

`DRAW.image`、`text`・`label` の `bg`、`centerOf`、文字の層へ移す正規表現、テスト、ガイドを確認した。`src` の検査（`http:`・`javascript:`・`..`・`//`・引用符・`data:`・大文字の拡張子はどれも描かない）と属性のエスケープ（`attrs` → `escapeText`）は十分。`bg` を付けない既存の部品の出力は変わらない（`styledText` は `bg` がなければ `text()` の結果をそのまま返す。正規表現の rect 部分は省略できる形）。ドラッグ対象の文字と下地は item の中に残る。content-all の新しい検査は、`image` のない教材ではループが空になるので誤って失敗しない。指摘は Medium 1 件、Low 2 件。

### 指摘事項

| # | 重要度 | ファイル:行 | 内容 | 修正案 |
|---|---|---|---|---|
| 1 | Medium | tests/content-all.test.js:108 | ファイルの実在を `fs.existsSync(path.join(ROOT, src))` で確かめているが、開発機の Windows は大文字と小文字を区別しない。たとえば `src: 'assets/images/human/Lung.png'` で実ファイルが `lung.png` でも、テストは通る。公開先の GitHub Pages は大文字と小文字を区別するので、その画像は 404 になる。`sw.js` の `PRECACHE` に同じ綴りで入っていると `cache.addAll` が失敗し、Service Worker のインストール全体（オフライン教材すべて）が失敗する（推測。`sw.js:81` の `addAll` の動きから） | パスを `/` で分け、各段で `fs.readdirSync(dir).includes(name)` を使って、綴りが大文字・小文字まで一致することを確かめる。あわせて `docs/figures-guide.md` に「ファイル名は小文字をすすめる」と書く |
| 2 | Low | tests/content-all.test.js:18 | 指示書にない変更: `const BOOK_NAMES = /…/` が `const BOOK_NAMES =/…/` になった（`=` の後の空白が消えた）。動きは同じ | 空白を戻す |
| 3 | Low | docs/figures-guide.md:65 | 拡張子は小文字だけが通る（`.PNG`・`.JPG` は何も描かれない）が、ガイドには書かれていない。教材では content-all の検査で気づけるが、画像を書き出したときの拡張子が大文字だと戸惑いやすい | 表の `image` の行に「拡張子は小文字（`.PNG` は不可）」と書き足す |

確認して問題がなかった点（参考）:
- `preserveAspectRatio="xMidYMid meet"` が常に付き、`href`（`xlink:href` なし）で出る。`opacity` は数でないとき・空・null のとき書かず、範囲外は 0〜1 にそろう（`clamp01`）。
- `centerOf` の `image` は `pos(it.width, ctx.width)` を使う。呼び出し側は `boundary` と同じく `ctx` を渡しているので、落ちない。
- 下地の rect は `class` が先頭の属性になる（`tag` は Object のキーの順）。正規表現 `(?:<rect class="text-bg"[^>]*\/>)?<text[\s\S]*?<\/text>` と合う。rect に `scene-label` のクラスは付かないので、文字のふち取りの CSS の対象にならない。
- `image` は SVG の中なので、`js/ruby.js` のふりがなの対象にならない。
- content-all の新しい検査が見る図（レッスンの `figure` と全問題の `figure`）は、既存の ITEM_TYPES の検査と同じ範囲。教材には `figure:` 以外の図のキーはない。
