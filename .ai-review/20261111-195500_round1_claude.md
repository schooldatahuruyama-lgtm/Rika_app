# レビュー結果（round 1、Claude 代行）: ライブクイズのデータベースの URL の組みこみと、QR コードでの参加

Codex は週の利用上限（2026-11-11 21:05 まで）のため、実装に関わっていない Claude エージェントが読み取り専用でレビューした。

## 概要

- 対象: 未コミットの変更（`js/qr.js` と `tests/qr.test.js` は新規。ほかに `js/app.js`、`js/config.js`、`js/ui-live-host.js`、`js/ui-live.js`、`index.html`、`sw.js`、`css/style.css`、`tests/config.test.js`、ドキュメント類）。
- `npm test`: tests 788 / pass 788 / fail 0。
- QR の符号化（`js/qr.js`）に誤りは見つからなかった。
  - 型番 1〜10 の 4 レベルすべてで、誤り訂正符号語の数とブロックの数が規格の表と一致。
  - 総符号語数（26, 44, 70, 100, 134, 172, 196, 242, 292, 346）、M のデータ符号語数（16, 28, 44, 64, 86, 108, 124, 154, 182, 216）、位置合わせパターンの座標、型番情報（7c94 / 85bc / 9a99 / a4d3）、形式情報（M・マスク 0 が `101010000010010`）は規格どおり（node で計算して確認）。
  - ブロックの分け方、インターリーブ、符号語を置く順、8 種のマスクの式、形式情報を書く 2 か所、暗モジュールは参照実装の手順と同じ。
  - テストの復号は実装とは別に書かれており、往復の検査として有効。
  - 外部の QR 読み取りライブラリでの実地確認はレビュー側ではしていない（Claude Code が jsQR で別に確認した）。
- 安全性（XSS・オープンリダイレクト）: 問題なし。`parseJoin` が返すのは `^[A-HJ-NP-Z2-9]{6}$` を通った 6 文字だけ。`innerHTML` に入るのは `qr.svg` が作った数値と固定の文字列だけ。
- URL の優先順位は指示書どおり（端末に保存した URL があればそれ、なければ組みこみ）。
- Service Worker: 画面を開く要求にはクエリに関係なく `index.html` を返すので、`?live=` 付きでもオフラインで開ける。
- ふりがな・効果音への影響なし。
- カメラの解放: 「読むのをやめる」・画面を離れたとき・`getUserMedia` の途中でやめたとき・許可が出なかったときは正しく止まる（例外は指摘 1）。

## Claude Code の対応

| # | 分類 | 対応・理由 |
|---|---|---|
| 1 | 対応する | `join` の入口でカメラを止め、検出のときに参加済みなら何もしない守りを足す（修正指示書 `.ai-tasks/20261111-200000_ライブクイズ_QR_修正1.md`） |
| 2 | 対応する | 読んだコードを伝える一文を参加中の画面に出す |
| 3 | 対応する | 保存した URL と組みこみの URL を、どちらも `normalizeUrl` を通してから比べる |
| 4 | 対応する | `https:` でない、または localhost・127.0.0.1 のときに QR の下へ注意を出す |
| 5 | 対応する | 画面が裏に回ったらカメラを止める（費用が小さく、電池とプライバシーの面で安全側） |
| 6 | 対応する | 規格の数え方に合わせる（2 行の直し。往復のテストで確かめる） |
| 7 | 対応する | Claude Code がコミット前に VERSION を `2026-11-11-29` に上げる |

Claude Code 側の確認（2026-11-11）: jsQR（別実装の読み取りライブラリ）で 7 種の文字列（size 21〜49）がすべて復号できた。内蔵ブラウザで、組みこみの URL のまま部屋を作る → ロビーの QR が `…/?live=<コード>` に復号できる → その URL を別タブで開くと部屋コードが入った参加画面になり、URL から `?live=` が消える → 参加 → 先生側に名前が出る → 出題中の画面に「参加コード」が出る → 部屋を消すと生徒側に「先生が部屋を閉じました」、を実際の Firebase で確かめた（テスト用の部屋は削除済み）。
