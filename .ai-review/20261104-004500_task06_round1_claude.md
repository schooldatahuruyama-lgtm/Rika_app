# Claude レビュー結果（Task 6 / round 1）

## 仕様適合
- ✅ 適合: 指示書の公開 API 7 関数（`js/session.js:315`）、分岐（設計書 4.3）、events の規則、星、JSON 往復のすべてが差分で実装・テストされている。抜け・余分・取り違えは見つからなかった。手で追った分岐:
  - main 誤答 → `missStreak=1`、そのステージの retryPool から未使用の同概念 1 問を `index+1` に挿入（`js/session.js:209-211, 232-238`）。プールが尽きたら挿入なしで、feedback の explanation を見せて続行（テスト「類題プールが尽きたら挿入せず続行」）。
  - retry 誤答 → `missStreak+1`。`missToOffer`（2）以上で basic があれば offer、なければそのステージの lessons を `emitRead:false` で挿入（`js/session.js:212-224`）。
  - accept → `learnbackRounds[basic]+1`、`learnback={...,round,results:[],recheck:false,usedIds:[]}`、確認問題 `checkCount` 問を offer の位置に挿入（`js/session.js:278-284`）。確認問題は `usedProblemIds` に入れず、回ごとの `usedIds` で回の中の重複を防ぐ（`js/session.js:156-169`）。round 2 では未加点の k3 を先に出す。
  - 2 問そろってから判定（`js/session.js:246-252`）。全問正解 → `learnback=null` と `learnback` event。1 問でも誤答 → basic の `lessonStageId` の lessons（`emitRead:true`）＋再確認 1 問（`recheck:true`）。再確認がそろえば結果に関係なく `learnback` event 1 回、誤答なら `ended='stopped'`（`js/session.js:261-266`）。stopped の後の `next` は stageClear を出さない（`js/session.js:134`）。
  - 経験値 events は `awardedProblemIds` で問題ごと 1 回、mastery は毎回（main 正解 firstTry / それ以外の正解 later / 誤答 wrong）（`js/session.js:194-203`）。warmup は history だけを返し、results・missStreak・分岐に触れない（`js/session.js:191`）。
  - lessonRead はブロックの最後のカードを `next` で抜けるときだけ、`emitRead` のブロックに限り lessonStageId 付き（`js/session.js:144-147`）。類題後の再掲（emitRead false）は出さない。自分のステージのときだけ `session.lessonRead=true`。
  - stageClear は queue を使い切る `next` で（`js/session.js:117-126`）。コントローラ承認済みの例外どおり、offer が最後の step の `choose('later')` でも出る（`js/session.js:289`）。復習（kind 'review'）では出ない。
  - 星: `config.stars` の最初の「上限 > 割合」（`js/session.js:302`）。50% ちょうど → ★★、80% → ★★★、main 0 問 → 0。分母は `results.main` のみ。
  - pending 中・ended 後・問題以外の step・judge invalid の `answer` は同じ参照の session と空 events を返す（`js/session.js:175-180`）。二重送信は pending で、再出題の加点は awardedProblemIds で防いでいる。
  - session は id 参照の queue と素のデータだけで、JSON 往復後も `current` が同じ（テストで lesson / warmup / feedback / offer / check / basic の lesson の 6 地点と、読み戻し後の完走を確認）。
  - コントローラの判断（step を id 参照で持つ、復習では分岐しない、later が最後なら completed+stageClear）はすべてそのとおりに実装されている。
- ⚠️ 差分だけでは確認できない:
  - ブラウザでの読み込み順: `js/session.js:11-13` は読み込み時に `RikaQuest.judge / xp / record` を取るため、`index.html` で judge.js・xp.js・mastery.js・record.js を session.js より前に置く必要がある（Task 12）。
  - `ended='stopped'` は再確認の `answer` の時点で立ち、フィードバックは pending として先に出る（`js/session.js:96-99, 266`）。Task 12 が `answer` の直後に `session.ended` を見て結果画面へ移ると、最後のフィードバックが飛ばされる。`current()` の view で画面を決めること。
  - `choose` の events（later が最後のときの stageClear）を Task 12 が `applyEvents` に渡すこと。

## 良い点
- 分岐の挿入先を `const at = s.index + 1` の 1 か所にそろえ（`js/session.js:208`）、main / retry / check の分岐が短い `if` の並びで読める。
- 確認問題の選び方が丁寧: 回の中で未使用 → その中でも未加点を先に → 足りなければ再使用（`js/session.js:156-169`）。round 2 でも加点のある問題が出やすく、指示書の「別の回では再使用してよい」と両立している。
- 数値（missToOffer / checkCount / recheckCount / review.problemCount / repeatMultiplier / stars）はすべて config から読み、ファイルに直書きがない。
- `lessonBlock`（`js/session.js:86-92`）で「同じ lessonStageId・同じ emitRead の連続」をブロックとみなし、index/total と lessonRead の判定を 1 つの考え方で出している。
- テストは fixture の実際の流れを `drive` / `play` で動かし、event の種類と順序まで `deepEqual` で確かめている。round 2 の再使用問題が `['history','mastery']` だけになること、stopped 後に答えられないこと、元の session が変わらないことなど、壊れやすいところを押さえている。
- 拒否時に同じ参照を返すので、UI が参照比較で「変化なし」を判定できる。
