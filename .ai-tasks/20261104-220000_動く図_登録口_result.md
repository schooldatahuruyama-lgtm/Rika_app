## 指示書・計画と違う点、判断したこと

1. **光（light）は接頭辞と静止図の文字の整合を検査しない**（`ANIM_LEGACY_UNITS = ['light']`）。光の kind には接頭辞がなく、光の 23 枚のカードでは静止図の文字 13 個が動く図と位置・文字がちがう（例: straight-1-c3 の静止図「近づけると影は大きい」と動く図「光源に近い → 影は大きい」）。指示書の「光のカードは今までどおり通ること」に合わせた。kind が `KINDS` にある・重ならない・静止図がある・`image` がない、は光にもかける（すべて通る）。
2. 静止図との整合は、計画の文どおり「`text`・`x`・`y` が同じ」で見る。部品の種類は `text` と `label` のどちらでもよい（`label` を `text` に替えても通る）。
3. `ANIM_TEXT_EXCEPTIONS` の形は `{ kind: ['静止図の文字', ...] }`（文字で除く）。表に書いた kind が `KINDS` にないと失敗する。
4. 計画 3-5 の 3 の「光以外の単元で anim を持つカードの数（単元ごと）」の検査は、今は 0 本なので入れていない（指示書の枠の一覧にもない）。動く図を足す回で、その単元の数を足すとよい。
5. 道具の細かい決まり（計画の式は変えず、はしの扱いだけ決めた）:
   - `ease` は範囲の外の k を 0〜1 に収めてから計算する。
   - `osc` の `phase` は省くと 0。
   - `along` は長さ 0 の辺を飛ばす。折れ線の長さが 0 のときは最初の点・向き (1, 0)。k は 0〜1 に収める。
   - `partial` は長さ 0 の折れ線も `[]`。k = 1 は元の点の写し（別の配列）。
   - `growLine` は style の `color`・`width` を指定したときだけ item に入れる（指定がなければ `figures.js` の既定 ink・幅 3）。
   - `mix` は大文字・小文字どちらも読み、`'#RRGGBB'`（大文字。`TOKEN_HEX` と同じ）を返す。`#rgb` やトークン名は例外（トークンは `TOKEN_HEX` で色コードにしてから渡す）。
   - `register` の `opts` は省略・`null` 可。数でない `restT`・`period`（文字列 '0.5' など）は例外。
6. `periodOf` は知らない kind にも `PERIOD_MS`（4000）を返す（`restT` が知らない kind に 0 を返すのと同じ扱い）。

## 懸念

- `KINDS` は登録で増える配列（凍結していない）。外から `push` されると `frame` は知らない kind として例外を出すので、画面側で落ちる可能性はある（今の画面は `includes` で見るだけなので問題ない）。
- `mix` の戻り値は大文字の色コード。`figures.js` の `paint` は大文字・小文字どちらも通すので描画には影響しない。
