## 判断した点（指示書と違う・指示書にない点）

- `questionFromProblem` の戻り値に `stageId` も入れた（履歴の stageId に使う）。
- `customQuestion(input, n)`: 2 つ目の引数で id の番号を渡せる（省略時はページ内の通し番号）。選択肢は 4 つまで、空の文は飛ばして a〜d を振り直す。answer は元の並びの番号で、その文が空なら null。
- `newRoom`: 各問題に `order` を付ける。同じ id の問題は先のものだけ残す（`meta.count` は残った数）。`code` は受け取るが部屋データには入れない（パスに使う）。
- `scoreFor(question, answer, …)`: answer は `{ choice, at }`（文字列でも可）。開始前の時刻は残り時間＝制限秒として上限 1000。時刻が数でなければ速さの点なしで 500。
- `applyScores`: 二重加算を防ぐため、足した問題 id を `lastQ`、その問題の点を `lastPoints` に残す（生徒の端末が自分の点を表示できる）。参加者にいない pid の答えは無視。
- `recordEvents`: null は配列に入れない（record.applyEvents が null で落ちるため）。教材の問題は `history（phase 'live', attempt 1, stageId は問題の stageId）`・`answer`・`correct`・`mastery（later / wrong）`。自作は `answer`・`correct` だけ（履歴も入れない。そのため連続学習の日次加点も付かない）。
- `safeRoom`: Firebase は null を保存せず、配列を object で返すこともあるので、どちらでも読む。名前は 12 字に切る。answers は 問題 id → pid → `{ choice, at }`。
- `isStale`: createdAt がない部屋は古いとみなす。
- `nextState`: reveal は show のときだけ。ended のあとの next は変えない。問題 0 件の start は ended。
- `live-db`: 401 も 403 と同じ案内。ほかは `通信できませんでした（<status>: <Firebase の error>）`。ヘッダーは付けない（Firebase の REST は不要）。
- `watch`: EventSource の `error` で自分で閉じ、3 秒後につなぎ直す（データが届いたら回数を 0 に戻す。続けて 10 回を超えたら onError）。cancel・auth_revoked は閉じて onError、つなぎ直さない。テスト用に `setTimeoutImpl`・`clearTimeoutImpl`・`random` も差しかえられる。
- `serverTime`: 送る前後の端末時刻の真ん中との差を返し、書いた `_time/<id>` はあとで消す（失敗は無視）。
- `normalizeUrl`: 「含む」ではなくホスト名が `.firebaseio.com` / `.firebasedatabase.app` で終わるかで判定（`https://example.com/firebaseio.com` を通さないため）。パスは落として `https://<host>` を返す。

## 気になる点

- 規則では players の `score`・`lastQ` を誰でも書けるので、生徒が自分の得点を書きかえられる（設計書 14 章の「割り切り」の範囲）。
- answers のキーは問題 id にした（`$q`）。画面（指示書 B）でもこれに合わせること。
- 教材の問題 id に Firebase のキーに使えない文字（`. # $ [ ] /`）がないことは content/ で確認した。
