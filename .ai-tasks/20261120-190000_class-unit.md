# 実装指示書: 先生がクラスごとに決めた「今の単元」を受け取る（段階 3・理科クエスト側）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。先に `.ai-tasks/20261119-170000_jugyolog-sync.md`（段階 2b の指示書）と、`js/link.js`・`js/sync.js`・`js/app.js` のアカウントのモードの所を読んでから始めてください。

## 目的

授業ログとつなぐ作業の段階 3。先生は、授業ログの画面でクラスごとに「今の単元」を決める（授業ログ側は別の指示書で作る）。理科クエストは、授業ログのアカウントでつながっているときに、それを読んで生徒の単元にする。

先生の決定（2026-11-19）:

1. 先生がクラスごとに「今の単元」を決める。決めていないクラスは、生徒が選ぶ。
2. 生徒は、先生が決めた単元のほかにも進めてよい。
3. 今日のクエストは、今までどおりアプリが自動で決める（`js/recommend.js` は変えない）。

Claude Code が決めた動き（2026-11-20。先生に伝えてある）:

- 先生が単元を変えると、生徒が次に開いたときに、その単元に **1 回だけ**切りかわる。そのあと生徒がほかの単元を選ぶのは自由。
- 先生が決めた単元には印を付け、ほかの単元にいるときは、ボタン 1 つで戻れる。
- クラスが 2 つ以上ある生徒は、いちばん新しい年度のクラスの単元を使う。
- 教材にない id は「決めていない」と同じ。読めなかったときは、学習を止めず、前に受け取ったまま続ける。

## データベースの形（授業ログ側の規則で決まっている。変えられない）

| 場所 | 中身 | 決まり |
|---|---|---|
| `accounts/<uid>` | 生徒の ID の文字列（例 `s26-001`）。先生のアカウントには無い | 本人が読める |
| `memberOf/<生徒の ID>` | `{ <classId>: true, … }` | 本人が読める |
| `classes/<classId>` | `{ year: 数, name: 文字列, … }` | そのクラスの生徒が読める |
| `rika/classUnit/<classId>` | 単元の id の文字列（`/^[a-z0-9-]{1,40}$/`）。決めていないときは無い（`null`） | そのクラスの生徒が読める。生徒は書けない |

読むだけ。このアプリからは、どれも書かない。

## 変えるファイルと内容

### 1. `js/class-unit.js`（新しく作る。`js/sync.js` と同じ IIFE・`module.exports` の形）

`RikaQuest.classUnit = { clean, pickClass, createClassUnit }`

- `clean(value)` → `/^[a-z0-9-]{1,40}$/` に合う文字列ならそのまま、それ以外は `null`。
- `pickClass(list)` → `[{ id, year, name }]` から 1 つ選ぶ。`year` の大きい順、同じなら `name` の文字コード順（`<` で比べる）、それも同じなら `id` の順で、最初の 1 つ。空なら `null`。`year` が数でない行は、いちばん後ろに回す。
- `createClassUnit({ uid, link, fetch, config })` → `{ load() }`。`config` は `config.link`。
  - `load()` は投げない。返す形: `{ status: 'ok', unitId: 文字列 | null, classId: 文字列 | null }` か `{ status: 'offline' | 'denied' | 'broken' }`。同時に 2 回呼ばれたら 1 回にまとめる。
  - 手順:
    1. `uid` の形を確かめ（`/[/.#$\[\]]/` を含まない・空でない）、`link.getToken()` で通行証を取る。`link.savedUid() !== uid` か、通行証が無ければ `{ status: 'offline' }`。
    2. `accounts/<uid>` を読む。文字列でない（先生・未登録）→ `{ status: 'ok', unitId: null, classId: null }`。生徒の ID に `/[/.#$\[\]]/` があれば `broken`。
    3. `memberOf/<生徒の ID>` を読む。値が `true` のキーだけを取り、キーは `/^[A-Za-z0-9]+$/` に合うものだけ。0 個 → `ok`・`null`。11 個以上あれば、最初の 10 個だけ使う。
    4. それぞれ `classes/<classId>` を読み、`{ id, year, name }` にする（`year` が数でない・`name` が文字列でないものも、行としては残す）。`pickClass` で 1 つ選ぶ。
    5. `rika/classUnit/<選んだ classId>` を読み、`clean` を通す。
  - 通信の決まりは `js/sync.js` の `request` と同じにする: `config.dbUrl` + パス + `.json?auth=<通行証>`、`redirect: 'error'`、`config.timeoutMs` で打ち切り、401/403 → `denied`、500 以上・例外・時間切れ → `offline`、そのほかの 2xx 以外・JSON でない → `broken`。通行証は URL の `auth=` にだけ入れ、記録（console）・保存場所に出さない。**GET だけ**を使う。
  - どれか 1 つでも `ok` でなければ、その状態を返して終える（途中の結果は使わない）。

### 3. `js/app.js`

- `applyClassUnit()`（新しく）: 今のプロフィールと `state.classUnitSeen` があるときだけ動く。
  - `unitId` が `null`、または `state.reg.unit(unitId)` が無い（教材にない）→ `profile.classUnitApplied` があれば消して `save()`。単元は変えない。
  - `unitId` があり、`profile.classUnitApplied !== unitId` → `profile.unitId = unitId`・`profile.classUnitApplied = unitId` にして `save()`。保存に失敗したら、両方とも元に戻す（次の機会にもう一度ためす）。成功して、画面が `['home','map','record','settings','units']` のどれかなら描き直し、メッセージ「先生が決めた単元「<単元の名前>」にしました。」を、今ある知らせ方（単元を変えたときのメッセージと同じ出し方）で出す。

## 端の場合

- 不正な入力: `accounts/<uid>` が数・オブジェクト → 生徒でないものとして `ok`・`null`。`memberOf` が文字列・配列・`true` でない値 → その分は使わない。`classes/<id>` が `null`・形がちがう → `year` なしの行として後ろに回す。`rika/classUnit` が数・空・41 文字以上・大文字入り → `null`（決めていない）。形は合うが教材にない id → 単元を変えず、`classUnitApplied` を消す。JSON でない返事 → `broken`。
- 重複と境界: 同じ単元をもう一度受け取る → 何もしない。先生が「決めない」に戻す → 生徒の単元はそのまま、印が消える。先生が A → 決めない → A と変えた → もう一度 A に切りかわる。プロフィールがまだ無い → 作った直後に当てる。2 台の端末 → `classUnitApplied` はプロフィールと一緒に同期されるので、2 台目でもう一度切りかわらない。クラスが 0 個・11 個以上（10 個まで）。同じ年度に 2 つ → 名前の順で最初。
- 違反や失敗の見せ方: 読めない（通信なし・拒否・こわれた返事）→ 学習を止めない。帯は変えない。前に受け取った `classUnitApplied` の印は出したままにする。単元の切りかえの保存に失敗 → 元に戻し、メッセージは出さず、次の読みこみでもう一度ためす。「この単元にする」の失敗 →「単元を変えられませんでした。」。
