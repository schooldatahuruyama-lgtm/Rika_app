# 実装指示書: 汎用の図の部品（全単元の教材を描けるようにする）

作成: Claude Code（Fable）2026-11-04。実装: Claude Code のサブエージェント（Opus）。レビュー: Codex。

## 目的

要件定義書「追加予定機能 1. 全単元への展開」のための土台。いまの `js/figures.js` の部品（鏡・レンズ・光線・電球など 14 種）は「光の世界」専用で、化学（ビーカー・試験管・炎）、生物（細胞・からだの図）、地学（地層・天気図）、電流（回路図）の図が描けない。
教材の書き手（別のエージェント）が、座標と色だけで何でも描ける**汎用の部品**と、理科でよく使う**記号の部品**を足す。既存の光の部品と教材（`content/light.js`）の見た目は変えない。
あわせて、`content/` に単元ファイルが増えても自動で検査される**共通テスト**を足す。

## 色の指定

- `COLOR` に足す: `red: '#D9534F'`（血液・リトマス紙などの理科の色としてだけ使う。不正解の強調には使わない）、`yellow: '#FFD34D'`、`pink: '#F2A6C2'`、`purple: '#8E6BD6'`、`brown: '#A0623A'`、`sky: '#CFE4FF'`、`white: '#FFFFFF'`、`lightgreen: '#C9EBD3'`、`sand: '#E8D8B0'`、`rock: '#B8B2A7'`。
- 新部品の `fill`・`stroke`（・`color`）は、`COLOR` のトークン名（`'blue'` など）か `#rrggbb`／`#rgb` の文字列を受け付ける。それ以外（未指定・知らない名前）は部品ごとの既定にする。関数 `paint(value, fallback)` を 1 つ作って共用する。`'none'` も受け付ける（塗らない）。
- 矢印: `ARROW_DEFS` に `scene-arrow-<token>`（ink / blue / green / gray / orange / red）の marker を足す。既存の `scene-arrow`（橙）はそのまま残す。

## 新しい部品（`DRAW` に追加）

座標は既存と同じく x 右向き・y 下向き、場面は 320×240 が基本。`label` の文字は既存部品と同じく `text()` で描く（文字の層にまとめられる）。

| type | 項目 | 描き方 |
|---|---|---|
| `rect` | `x, y, width, height, fill?, stroke?, rx?, label?, labelPos?` | 四角。`fill` 既定 `white`、`stroke` 既定 `ink`、太さ 2。`label` は中央（`labelPos: 'above'` なら上端の 8px 上、`'below'` なら下端の 20px 下） |
| `circle` | `x, y, r, fill?, stroke?, label?, labelPos?` | 丸。既定は `rect` と同じ。`label` は中央（`labelPos` は同上） |
| `ellipse` | `x, y, rx, ry, fill?, stroke?, label?, labelPos?` | 楕円。同上 |
| `polygon` | `points: [[x,y],...], fill?, stroke?, label?` | 閉じた多角形。`label` は重心（点の平均） |
| `line` | `points: [[x,y],...], color?, width?, dashed?, arrow?` | 折れ線（点 2 つなら直線）。`color` 既定 `ink`、`width` 既定 3、`linecap/linejoin: round`。`arrow: true` で終点に同じ色の矢じり（`scene-arrow-<token>`。`#hex` のときは `ink` の矢じり）。`dashed` で `8 6` |
| `text` | `x, y, text, size?, anchor?, color?, bold?` | 文字だけ（`label` の拡張版）。`size` 既定 16・下限 12、`anchor` は `start`/`middle`/`end`（既定 `start`）、`bold` で `font-weight: bold` |
| `beaker` | `x, y, width?, height?, level?, liquid?, label?` | ビーカー（上が開いた U 字の容器。`x,y` は底の中央）。`width` 既定 70、`height` 既定 80。`level`（0〜1、既定 0.6）の高さまで `liquid`（色、既定 `water`）で塗り、液面は少し波打った線。`label` は容器の下 20px |
| `tube` | `x, y, height?, level?, liquid?, label?, tilt?` | 試験管（幅 24、底が丸い）。`x,y` は底の中央。`tilt`（度、既定 0、時計回り）で傾ける（`transform=rotate`）。`level`・`liquid` は beaker と同じ |
| `flame` | `x, y, label?` | 炎（アルコールランプやガスバーナーの火）: 外炎を `orange`、内炎を `yellow` の涙型。`x,y` は炎の底の中央、高さ 36 |
| `symbol` | `x, y, kind, rotate?, label?` | 回路図の記号。`kind`: `battery`（電池: 長い線＋短い線、長いほうが＋。`rotate: 90` で縦向き）、`bulb`（豆電球: 丸と×）、`resistor`（抵抗: 長方形 36×14）、`switch`（スイッチ: 開いた斜め線）、`ammeter`（丸に A）、`voltmeter`（丸に V）。どれも `x,y` を中心に幅 40 の中に収める。導線は `line` で描く。`label` は記号の下 24px |
| `arrow` | `x1, y1, x2, y2, color?, width?, label?` | `line` の 2 点版（`arrow: true` 固定）。力や運動の矢印に使う。`label` は中点の 10px 上 |

既存の `label` に任意項目 `size`・`anchor`・`color` を足す（指定がなければ今までどおり 16px・左寄せ・`ink`）。

`centerOf`（ドラッグの当たり判定の中心）:
- `rect` → 中心、`circle`/`ellipse`/`beaker`/`tube`/`flame`/`symbol`/`text` → `(x, y)`（beaker/tube は底の中央より `height/2` 上、flame は 18 上）
- `polygon` → 点の平均、`line`/`arrow` → 全点の平均（`arrow` は 2 点の中点）

`ITEM_TYPES`（`Object.keys(DRAW)`）に新部品が入ることで、既存テスト「14 種類すべて」は件数が変わる。そのテストは「`ITEM_TYPES` のすべてを描ける」に書き直し、各 type ごとに最小の item を 1 つずつ用意する表を持つ。

## tests/content-all.test.js

`fs.readdirSync('content')` で `*.js` のうち `curriculum.js` 以外を全部読み、各ファイルの `module.exports.unit` について次を検査する（`tests/content-light.test.js` にある汎用の検査を移さず、同じ内容をここにも書いてよい。light のテストは残す）:

1. `validateUnit(unit)` が `[]`。
2. `unit.id` がファイル名（拡張子なし）と同じ。`unit.title` が文字列。`unit.mascot` が `MASCOTS` のキー。
3. 全ステージ: `problems` に図・操作型が 1 問以上、各概念の retryPool ≥ 2・checkPool ≥ 3（validateUnit と重なるが残す）。
4. ray-draw / drag の `samples.correct` が正解、`samples.wrong` が不正解で invalid でない。
5. figure-choice の `answer` が図の `region` の id にある。drag の `draggable.itemId` の item が図にあり、`target` が図の中（0 ≤ x ≤ width、0 ≤ y ≤ height）。
6. 図（`figure`）の全 item の `type` が `figures.ITEM_TYPES` にある（lessons・problems・retryPool・checkPool の figure を全部見る。`figure: null` は可）。
7. 教科書名・出版社名を含まない（`東京書籍|啓林館|大日本図書|教育出版|学校図書|学図|東書|啓林`）。
8. 全問題に `prompt`・`explanation`・`hint` の文字列があり、レッスンカードは 2〜4 枚、各 `text` が 40〜160 字、`figure` がある。
9. `index.html` の `<script src="content/<id>.js">` と `sw.js` の `PRECACHE` に、そのファイルが入っている。

## tests/figures.test.js に足すテスト

- `rect`/`circle`/`ellipse`/`polygon` が描け、`fill`/`stroke` のトークン名が色コードになり、`#abc` もそのまま使われ、知らない名前は既定になる。`'none'` は `fill="none"`。
- `line` の `points` 3 点が `<polyline>` になり、`arrow: true` で `marker-end="url(#scene-arrow-blue)"`（`color: 'blue'`）、`#hex` のときは `scene-arrow-ink`。`dashed` で `stroke-dasharray`。
- `text` の `size: 8` は 12 に切り上げ、`anchor: 'end'`、`bold`。`label` の `size`・`anchor`・`color` が効き、指定なしは今までどおり。
- `beaker` の `level: 0.5` で液体の `rect`（または path）の高さが `height * 0.5` 相当。`tube` の `tilt: 30` で `rotate(30` が入る。`flame`、`symbol` の 6 種がすべて描ける（知らない `kind` は丸だけ）。`arrow` に `marker-end`。
- `centerOf` は公開していないので、`draggableId` を付けたときの当たり判定（`hit-area` の cx/cy）で確かめる: `rect` は中心、`polygon` は点の平均、`beaker` は底から `height/2` 上。
- 既存の光の部品の出力が変わっていないこと: `content/light.js` の最初のレッスンカードの `sceneSvg` を変更前の文字列と比べる…のは難しいので、代わりに「`ray`・`mirror`・`lens` を含む場面の `sceneSvg` に、新しいマーカー以外の差がない」ことを、既存テストが通ることと `scene-arrow"`（橙）が残ることで確かめる。

## 守ること

- 既存のコードの書き方（`tag`/`line`/`text`/`num`/`attrs`、日本語コメント）に合わせる。
- `content/light.js` の見た目を変えない（既存部品のコードは触らない。`label` の既定値も変えない）。
- 文字はすべて `escapeText` を通す。`fill`/`stroke` に渡された文字列は `paint()` を通してからしか属性に書かない（`#rrggbb`/`#rgb` の正規表現で検査。それ以外の文字列は属性に出さない）。
- `git add`・`git commit` はしない。ネットワークからパッケージを追加しない。
- 同時に別のエージェントが `js/ui-screens.js`・`js/app.js`・`index.html`・`sw.js`・`css/style.css`・`js/units.js`・`content/curriculum.js` と `tests/units.test.js`・`tests/curriculum.test.js` を編集している。これらのファイルは触らない。`npm test` でそれらのテストが一時的に失敗しても、自分の変更が原因でなければ直さず報告に書く（自分のテストは `node --test tests/figures.test.js tests/content-all.test.js tests/content-light.test.js` で確かめる）。
