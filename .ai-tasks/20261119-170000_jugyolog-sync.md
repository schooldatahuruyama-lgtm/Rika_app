# 実装指示書: 記録を授業ログのアカウントに保存する（段階 2b）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。大きい変更なので、**先に `js/app.js`・`js/ui-screens.js`・`js/link.js`・`js/storage.js`・`js/record.js` を読んでから**始めてください。

## 目的

段階 2a（`.ai-tasks/20261119-150000_jugyolog-link-band.md`）で、授業ログのログインを読んで帯を出す所まで作った。段階 2b では、**授業ログにログインしている生徒の記録を、生徒ごとに Firebase（授業ログと同じデータベース）へ保存し、どの端末でも続きができる**ようにする。

先生の決定（2026-11-19）:

1. ログインして開いたとき: アカウントの記録を読みこんで、続きから始まる。
2. 2 台の端末で同じ生徒が学習したとき: どちらの分も残して、合わせる。片方を捨てない。
3. 通信がないとき: 学習は続けられる。記録は端末にためて、黄色の帯で件数を知らせ、つながったら自動で送る。
4. 共用のタブレットで別の生徒がログインしたとき: 前の生徒の記録は見せない。ログイン中は、その生徒の記録だけが出る（プロフィールの切りかえは出さない）。
5. 初めてつないだとき: 端末に前の記録があれば、中身を見せて「わたしの記録です／ちがいます」を選ぶ。無ければ、ニックネームとアバターを決める。
6. ログインなしでも、今までどおり使える（端末の中だけ）。

## 全体の考え方（大事）

**ログイン中は、別の「入れ物」（store）を使う。**

- 端末モード（今までどおり）: localStorage の `rika-quest:v1`（`config.storageKey`）。ログインしていないときに使う。
- アカウントモード: localStorage の `rika-quest:acct:<uid>`。形は今の store と同じ `{ version: 1, currentProfileId, profiles: [1 人だけ], records: { <id>: 記録 } }`。プロフィールは 1 人だけ。
- 画面のコード（`ui-screens.js` など）は、今までどおり `state.store`（`ctx.store`）を見る。アカウントモードでは `state.store` がアカウントの入れ物になるので、ほかの生徒や端末のプロフィールは、自然に見えなくなる。
- `save()` は、今のモードのキーに保存する（`RQ.storage.save` に渡す `config` の `storageKey` を差しかえる。`js/storage.js` は変えなくてよい）。
- 同期の情報（送っていない分など）は、別のキー `rika-quest:sync:<uid>` に置く。

## データベースの形（授業ログ側の規則で決まっている。変えられない）

データベース: `https://jyugyolog-default-rtdb.firebaseio.com`（REST。`<パス>.json?auth=<ID トークン>`）。

| 場所 | 中身 | 決まり |
|---|---|---|
| `rika/state/<uid>` | `{ v: 1, updatedAt: <ミリ秒>, json: <文字列> }` | `json` は 2〜500000 文字。ほかの項目は置けない。本人が読み書きできる |
| `rika/log/<uid>/<id>` | 文字列（JSON） | 2〜200000 文字。`id` は `^[A-Za-z0-9_-]{8,40}$`。**1 回書いたら、書きかえも削除もできない**（2 回目の書きこみは「権限がありません」（401／403）になる） |

- `state.json` の中身（この指示書で決める）: `JSON.stringify({ profile: <プロフィール（id をふくむ、そのまま）>, record: <記録から history と xpLog を除いたもの> })`。
- `log` のかたまりの中身: `JSON.stringify({ h: [<history の項目>…], x: [<xpLog の項目>…] })`。
- 本名・メールアドレス・uid 以外の ID は、どこにも置かない（今ある決まりのまま。ニックネームは「実名は入れない」）。

## 変えるファイルと内容

### 1. `js/config.js`

- `link` に足す: `dbUrl: 'https://jyugyolog-default-rtdb.firebaseio.com'`、`acctKeyPrefix: 'rika-quest:acct:'`、`syncKeyPrefix: 'rika-quest:sync:'`、`pushDelayMs: 3000`、`pullMinMs: 60000`、`stateMaxChars: 500000`、`chunkMaxChars: 150000`。

### 2. `js/link.js`

- `getToken()` を足す → Promise。使える ID トークン（期限まで 5 分以上あるもの）を返す。足りなければ、取り直してから返す（今ある通信の 1 本化を使う）。`ok` にならなければ `null`。トークンは外に保存しない。
- `savedUid()` を足す → 保存されているログインの uid（確かめの前でも返す）。無ければ `null`。
- 今ある動き（`jugyolog:auth` を書かない・消さない など）は変えない。

### 3. `js/sync.js`（新しく作る。ほかの `js/*.js` と同じ形。DOM は使わない。`fetch`・保存場所・時刻・乱数は引数）

次の 3 つの部分を作る。関数の分け方は任せるが、下の名前は外に出す。

**(a) 形を変える**

- `packState(profile, record)` → `json` の文字列。`unpackState(json)` → `{ profile, record }` または `null`（JSON でない・オブジェクトでない・`profile.id` が文字列でない・`record` がオブジェクトでない）。
- `packChunk(h, x)`・`unpackChunk(text)` → `{ h: [], x: [] }` または `null`（配列でない項目は空の配列にしてよい。項目がオブジェクトでないものは捨てる）。

**(b) 合わせる** `mergeRecord(local, remote, deps)` → 新しい記録（元を変えない）。`deps = { levelFor(xp) }`。`local`・`remote` は、history と xpLog を**すでに合わせたあと**の配列を `local` 側に持っている前提（`remote` には history・xpLog が無い）。

| 項目 | 合わせ方 |
|---|---|
| `history`・`xpLog` | `local` のものをそのまま使う（かたまりの取りこみは (c) がする） |
| `xp` | `xpLog` の `amount` の合計。ただし `xpLog` が空のときは `max(local.xp, remote.xp)` |
| `level` | `deps.levelFor(xp)` |
| `stages` | ステージごと: `status` は cleared > inprogress > none の強い方。`stars`・`attempts` は大きい方。`resume` は、合わせたあとの `status` が `cleared` なら `null`、そうでなければ `local` に `resume` があれば `local`、無ければ `remote` |
| `mastery` | 概念ごと: `lastAt` が新しい方（同じ・無いときは `value` の大きい方） |
| `lessonsRead` | どちらかが `true` なら `true` |
| `reviewDone` | 日付の新しい方 |
| `badges` | 両方を合わせる（同じ id は `local` を残す） |
| `liveResults` | `code` が同じものは 1 つ（`local` を残す） |
| `streak` | `lastDate` の新しい方。同じなら `count` の大きい方 |
| 知らない項目 | `local` にあれば `local`、無ければ `remote` |

- `mergeRecord(a, a)` は `a` と同じ中身になること。`remote` が `null` なら `local` のまま。

**(c) 送る・受ける** `createSync({ uid, link, fetch, storage, config, now, random, levelFor })` → 次を持つもの。`config` は `config.link`。

- 同期の情報 `rika-quest:sync:<uid>` の形: `{ v: 1, seenRev: <最後に見た／書いた state の updatedAt。無ければ null>, chunks: [<取りこみ済み・送信済みのかたまりの id>], len: { h, x }, pending: { h: [], x: [] }, sending: null または { id, h, x }, dirty: 真偽 }`。読めない・形がちがうときは、初期値で始める（`len` は 0 にせず、**今の記録の長さ**にする。前の分を二重に送らないため）。
- `capture(record)`: 記録の `history`・`xpLog` のうち、`len` より後ろに増えた分を `pending` に足し、`len` を進め、`dirty` を `true` にして保存する。**`save()` が成功するたびに呼ばれる**。配列が `len` より短くなっていたら（記録の入れかえ）、`len` を今の長さに合わせるだけ。
- `pendingCount()`: `pending.h` と `sending.h` の件数の合計。`isDirty()`: `dirty` か、送っていない分があるか。
- `pull(store)` → Promise `{ status, store, changed }`。`status` は `'ok' | 'none'（リモートにまだ無い）| 'offline' | 'denied' | 'broken'`。
  1. `link.getToken()`。`null` → `offline`。
  2. `GET rika/state/<uid>`。通信の失敗・5xx・時間切れ → `offline`。401／403 → `denied`。`null` → `none`（`store` はそのまま）。
  3. 形を確かめる（`v === 1`・`updatedAt` が数・`json` が `unpackState` で読める）。だめ → `broken`（`store` はそのまま。**このあと push もしない**）。
  4. `updatedAt === seenRev` → 変わっていないので、そのまま `ok`（`changed: false`）。
  5. ちがう → 先に `capture`（呼び出し側の記録で）。`GET rika/log/<uid>.json?shallow=true` で id の一覧を取り、`chunks` に無いものを 1 つずつ `GET` して `unpackChunk`。読めたものの `h`・`x` を記録に足し、`at` の順に並べ直す（同じ `at` は元の順）。`len` を新しい長さにし、`chunks` に id を足す。読めないかたまりは飛ばす（`chunks` に足さない。次にまた試す）。
  6. `mergeRecord(local, remote.record)` で合わせる。プロフィールは、`dirty` なら `local`、そうでなければ `remote`（ただし `id` は `local` のものを残す。ローカルに記録が無いときは `remote` をそのまま使う）。
  7. `seenRev = updatedAt` にして保存。`changed: true`。
- `push(store)` → Promise `'ok' | 'offline' | 'denied' | 'broken' | 'too-big'`。
  1. 前の `pull` が `broken` のまま → `broken`（上書きしない）。
  2. `sending` が無く `pending` が空でなければ、`pending` を `sending` に移す（`id` は `now().toString(36)` と乱数の英数字で 16 文字以上。`^[A-Za-z0-9_-]{8,40}$` に合うこと）。1 つのかたまりが `chunkMaxChars` をこえるなら、こえない所で切り、残りは `pending` に戻す。
  3. `sending` があれば `PUT rika/log/<uid>/<id>`（本文は JSON の文字列を、さらに JSON にしたもの＝文字列の値）。成功 → `chunks` に足して `sending` を消す。401／403 → `GET` で同じ id を読み、**中身が同じなら成功として扱う**（前の返事が届かなかっただけ）。ちがう・無い → `denied`。通信の失敗 → `offline`（`sending` は残す。次に同じ id で送る）。
  4. まだ `pending` が残っていれば 2〜3 をくり返す（1 回の `push` で 20 かたまりまで）。
  5. `dirty` なら `PUT rika/state/<uid>` に `{ v: 1, updatedAt: now(), json }`。`json` が `stateMaxChars` をこえる → `too-big`（送らない）。成功 → `seenRev = updatedAt`、`dirty = false`。
  6. 同時に呼ばれたら 1 本にまとめる。`pull` と `push` は同時に動かさない（順番にする）。
- 通信は `timeoutMs` で打ち切る。トークンは URL の `auth=` にだけ入れ（Firebase の REST の決まり）、`console`・例外の文・localStorage には出さない。`dbUrl` のほかへ送らない。`redirect: 'error'`。
- 保存場所への書きこみが失敗（容量など）しても、例外で止まらない（`dirty` はメモリに持つ）。

### 4. `js/app.js`

- モードの決め方（`start()` と、`link` の `onChange`）:
  - `link.savedUid()` が無い、または `status` が `none`・`expired` → **端末モード**（今までどおり）。
  - `savedUid()` があり、`rika-quest:acct:<uid>` が端末にある → すぐに**アカウントモード**でその入れ物を使い、裏で `pull` → `push`。
  - `savedUid()` があり、端末に入れ物が無い → 画面に「授業ログの記録を読みこんでいます…」を出して待つ（`link.check()` と `pull`）。
    - `pull` が `ok` → リモートの中身で入れ物を作って、ホームへ。
    - `pull` が `none` → **初めてつないだとき**の流れ（下）。
    - `offline`・`denied`・`broken`、または `status` が `unknown` → 端末モードで始め、帯で知らせる（下の表）。**このとき、初めてつないだときの窓は出さない**（次につながったときに出す）。
- 途中でログインが変わったとき（`storage` イベントや確かめ直しで、uid が変わった・無くなった・新しく入った）: 学習の途中なら今の保存を済ませてから、`root.location.reload()` する（モードの切りかえを 1 つの道にするため）。同じ uid のままなら何もしない。
- 初めてつないだときの流れ（リモートに無く、端末にもアカウントの入れ物が無い）:
  - 端末の入れ物（`rika-quest:v1`）にプロフィールが 1 人以上ある → 新しい画面「この端末に、前の記録があります」を出す。プロフィールごとに、ニックネーム・アバター・レベル・クリアしたステージの数・最後に学習した日（無ければ「まだ」）と、ボタン「わたしの記録です」。いちばん下にボタン「ちがいます（新しく始める）」と、文「『ちがいます』を選んでも、前の記録は端末に残ります。消えません。」
    - 「わたしの記録です」→ そのプロフィールと記録を、アカウントの入れ物に**移す**（端末の入れ物からは消して保存する。先にアカウント側の保存が成功してから消す）。同期の情報は、`len` を 0・`pending` に全部の `history`・`xpLog` を入れた形で作る（前の分も送るため）。→ ホームへ。裏で `push`。
    - 「ちがいます」→ プロフィールを作る画面へ。作ったプロフィールは、アカウントの入れ物に入る。
  - 端末にプロフィールが無い → プロフィールを作る画面へ（アカウントの入れ物に入る）。
- 送るとき: `save()` が成功するたびに、アカウントモードなら `sync.capture(今の記録)` を呼び、`pushDelayMs` 後に `push`（その間に次の保存があれば、待ち時間を取り直す）。`online`・`visibilitychange`（visible）で、`pull`（前の `pull` から `pullMinMs` たっていれば）→ `push`。`pagehide` では、待ち時間を待たずに `push` を始める（終わりを待たない）。
- `pull` で `changed` のとき: `state.store` を入れかえて保存し、**いまホーム・学習マップ・記録・設定・単元をえらぶ の画面なら、その画面を作り直す**。学習の途中（解説・問題・提案・結果）やライブクイズ・先生用の画面では、作り直さない（次に画面を移ったときに出る）。
- ほかのアカウントの入れ物の片付け: アカウントモードに入ったとき、localStorage の `rika-quest:acct:<別の uid>` のうち、その `rika-quest:sync:<別の uid>` が「送っていない分が無い」（`pending`・`sending` が空で `dirty` でない）ものを、入れ物と同期の情報の両方とも消す。送っていない分があるものは残す。
- アカウントモードでの `clearAll`（「すべて削除」）: 呼ばれても、端末の入れ物（`rika-quest:v1`）・アカウントの入れ物・授業ログのログインは消さない（下の設定画面で、ボタン自体を出さない）。
- `makeCtx()` に `account`（アカウントモードなら `{ uid }`、端末モードなら `null`）を足す。

## 端の場合

- 不正な入力: リモートの `state` が形ちがい・`json` が読めない → `broken`。帯で知らせ、**上書きしない**。端末の記録はそのまま使える。かたまりが読めない → 飛ばす（ほかは取りこむ）。同期の情報・アカウントの入れ物が壊れている → 入れ物は今ある `RQ.storage.load` の扱い（退避して新しく始める）に合わせ、同期の情報は初期値。`uid` に `/` `.` `#` `$` `[` `]` がふくまれる → アカウントモードにしない（端末モード）。
- 重複と境界: 同じかたまりを 2 回送らない（`sending` の id を残す）。2 回目の PUT が拒まれ、中身が同じなら成功。2 台が同時に `state` を書いたら、あとの書きこみが残るが、次の `pull` でまた合わせる。`history` が 0 件のときは、かたまりを送らない。`state` がちょうど `stateMaxChars` は送る。
- 違反や失敗の見せ方: 上の帯の表のとおり。送れない・読めない・拒まれた・大きすぎるは、すべて黄色の帯の文で出す。だまって捨てない。どの失敗でも、学習は止めない。
