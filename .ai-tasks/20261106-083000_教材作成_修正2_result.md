## 画面の確認（headless Edge、自分の http サーバー 127.0.0.1:8873。スクリプトはスクラッチパッドの author_check3/check.js）

- API の generate を止めておける偽物にして生成を始めると、一覧の「下書きファイルを読みこむ」が disabled（title あり）。一覧の行の「開く」で開き直しても進行表示は残り、生成は続く。
- 生成中に同じ id の下書きを updatedAt ちがいで保存（取り込みと同じ置きかえ）してから結果を返すと、ステージ 2 は null のまま、置きかえた題名も残り、ステージの行に「下書きが置きかわったので、生成結果は入れませんでした。」。生成が終わると読みこむボタンは戻る。
- 置きかえなしの生成は「作りました。」で入る。
- loadDrafts を差しかえて壊れた要素（null の問題、文字列のカード、options が文字列の warmup）を描かせても例外なし。壊れた行が 3 つ出る。コンソールのエラーなし。

## 判断した点

- 知らない type の問題: 以前は normalizeStage がそのまま入れていたが、新しい isDraft では通らず、`saveDrafts` の filter で下書きごと保存から落ちる（消える）。それを避けるため、整える段階で捨てて errors に書くようにした。
- warmup は normalizeStage が作れないとき null になるので、null（と undefined）は形の検査で許す。figure-choice は figure の中身までは見ない（編集画面は isObject で防いでいる）。
- 生成中でも「下書きの一覧」へ戻る・別の下書きを開くことは止めていない（指示どおり）。

## 気になる点

- 同じファイルを書き出して生成中にそのまま取り込むと updatedAt が同じで結果は入るが、中身も同じなので害はない。
- 編集画面の防御は保険で、壊れた下書きは loadDrafts で捨てられるため通常は出ない（壊れた要素が 2 つある下書きで 1 つ消しても saveDrafts で落ちるが、そこまで届かない）。
