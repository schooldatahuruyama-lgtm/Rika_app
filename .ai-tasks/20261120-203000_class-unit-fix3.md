# 実装指示書（修正 3）: クラスの単元 — 「決めない」を受け取ったときも時刻を残す

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。前の指示書は `.ai-tasks/20261120-200000_class-unit-fix2.md`、レビューは `.ai-review/20261120-185512_round1.md`。

## 目的

レビュー（サイクル 2・round 1）の指摘（High）に対応する。修正 2 では、先生の「決めない」を受け取ると、印（`classUnitApplied`）と一緒に時刻（`classUnitAppliedAt`）も消した。そのため「決めないを受け取りずみ」と「まだ何も受け取っていない」の見分けが付かず、古い印 X（時刻あり）を持つ別の端末の記録が先に送られていると、X の方が新しいと見なされ、生徒の選んだ単元が X に戻る。

## 考え方

`classUnitAppliedAt` を「先生の決めたこと（単元、または『決めない』）を、最後に受け取った時刻」とする。印（`classUnitApplied`）が無くて時刻だけある = 「『決めない』を受け取りずみ」。両方とも無い = 「まだ何も受け取っていない」。

## 変える内容

### 1. `js/app.js`

- `applyClassUnit()`:
  - 先生が「決めない」・教材にない id のとき: 印（`classUnitApplied`）があれば消し、`classUnitAppliedAt` を今の時刻に**する**（消さない）。印がもともと無いときは、今までどおり何もしない（時刻も変えない。まだ何も受け取っていない生徒に、毎回保存を起こさないため）。
  - 単元を当てるとき: 今までどおり、印と時刻を入れる。
  - 保存に失敗したら、印・時刻・単元を元に戻す（今までどおり）。
- `normalizeStore`: `classUnitAppliedAt` は、0 以上の有限の数でなければ消す。**印が無くて時刻だけある形は、消さずに残す**（修正 2 で入れた「印が無いのに時刻だけあるときは消す」をやめる）。
- `ctx.classUnitId`・`setUnit`・画面は変えない。

### 2. `js/sync.js`（プロフィールを合わせる所。端末のプロフィールを残す場合だけ）

修正 2 の決まりのうち、「印が無い側は、時刻があっても 0 として扱う」をやめる。

- 両方の印が同じ（両方とも無い場合もふくむ）→ 端末側のまま。`classUnitAppliedAt` は、両方にあれば大きい方、片方だけにあればその値。
- 印がちがう（片方だけに印がある場合もふくむ）→ それぞれの時刻（数でない・無いときは 0。**印が無くても、時刻があればその値**）を比べる。
  - アカウント側の時刻の方が**大きい** → 合わせた結果の `classUnitApplied`（アカウント側に無ければ消す）・`classUnitAppliedAt`・`unitId`（アカウント側に無ければ、端末側のまま）を、アカウント側の値にする。
  - それ以外（端末側が大きい・同じ）→ 端末側のまま。
- アカウント側の印・時刻が、文字列・0 以上の有限の数でないとき → 無いものとして扱う。
- ほかは変えない。

## 端の場合

- 不正な入力: 時刻が文字列・負・`NaN`・`Infinity` → 無いもの（0）。
- 重複と境界:
  - （今回の場面）端末 A: 印なし・時刻 300（「決めない」を受け取りずみ）・単元 Z・送っていない変更あり。アカウント側: 印 X・時刻 100・単元 X → A は印なし・時刻 300・単元 Z のまま。そのあとの単元の読みこみ（先生は「決めない」）でも変わらない。
  - 逆: 端末 A: 印 X・時刻 100・送っていない変更あり。アカウント側: 印なし・時刻 300・単元 Z → A は印なし・時刻 300・単元 Z になる。
  - （round 1 の場面）端末 B: 印なし・時刻なし・送っていない記録あり。アカウント側: 印 X・時刻 100・単元 Z → B は印 X・単元 Z。
  - （round 2 の場面）端末 A: 印 Y・時刻 200・単元 Z。アカウント側: 印 X・時刻 100 → A のまま。
  - まだ何も受け取っていない生徒が、先生の「決めない」を読む → 何も保存しない。
- 違反や失敗の見せ方: 変えない。

## テスト

- `tests/link.test.js`（アプリ全体）:
  - 今回の場面: 端末は「決めない」を受け取りずみ・Z を選択・未送信、アカウント側は古い X のまま記録だけ新しい → 同期と単元の読みこみのあと、単元は Z のまま、印なし。
  - 単元を受け取りずみの生徒が「決めない」を受け取る → 印が消え、時刻が残る（新しくなる）。開き直しても（`normalizeStore` を通っても）時刻が残る。
  - 何も受け取っていない生徒が「決めない」を読む → 保存が起きない。
  - round 1・round 2 の場面のテストが通ること。
