## 1. `js/richtext.js`

IIFE 形式（他の `js/*.js` と同じ。Node では `module.exports`、ブラウザでは `root.RikaQuest.richtext`）。依存なし。

記法: 文の中の `**語句**` が用語。入れ子なし。`**` の数が奇数なら、最後の `**` 以降は普通の文として扱う（例外を出さない）。

```
parse(text) → [{ text: string, term: boolean }]   // 文を順に分けた部分。空文字の部分は入れない
plain(text) → string                               // `**` を取り除いた文（字数の計算や検査に使う）
terms(text) → [string]                             // 用語を出てきた順に、重複なしで
```

例: `parse('光を出すものを**光源**という。')` → `[{text:'光を出すものを',term:false},{text:'光源',term:true},{text:'という。',term:false}]`。
`terms('**光源**から出た光。**光源**は…')` → `['光源']`。`plain('a**b**c')` → `'abc'`。`parse('a**b')` → `[{text:'a**b',term:false}]`。

## 2. `js/ui-screens.js`

- 新しい補助 `richParagraph(className, text)`: `el('p', { class: className })` の中に、`parse` の結果を順に足す。`term: true` の部分は `el('strong', { class: 'term', text })`、それ以外はテキストノード。**innerHTML は使わない**（既存どおり `el` と `textContent`）。
- `lessonCardBody(card)`: `el('p', { class: 'lesson-text', text: card.text })` を `richParagraph('lesson-text', card.text)` に替える。その下に、`terms(card.text)` が 1 つ以上あれば `el('div', { class: 'term-list' }, [ el('span', { class: 'term-list-label', text: '大切な言葉' }), ...用語ごとに el('span', { class: 'term-chip', text }) ])` を足す。用語がなければ出さない。解説画面と「解説を見る」モーダルの両方がこの関数を使っているので、両方に効く。
- 解答後の説明文（`fb.explanation` を `feedback-text` で描いている箇所）も `richParagraph('feedback-text', fb.explanation)` にする。ヒントはそのまま。
- `RQ.richtext` は `root.RikaQuest.richtext` から取る（他モジュールと同じ取り方に合わせる）。

## 4. `content/light.js`

### 4a. 解説文の用語

24 枚すべての `text` に `**語句**` を入れる。各カードに 1 つ以上。**文そのものは変えない**（`plain(text)` が今の文と同じになること。字数の検査 60〜120 字は `plain` で数える）。目立たせる用語は、そのカードで初めて定義・説明している語に限る（毎回すべてを太字にすると目立たなくなる。同じ語が後のカードにまた出るときは、その語がそのカードの主役なら付け、ついでに出るだけなら付けない）。

ステージごとの用語（この中から選ぶ。これ以外を用語にしない）:

| ステージ | 用語 |
|---|---|
| straight-1 | 光源、光の道すじ、影 |
| straight-2 | 光源 |
| reflect-1 | 反射、入射光、反射光、法線、入射角、反射角、反射の法則 |
| reflect-2 | 像 |
| refract-1 | 屈折、境界面、法線 |
| refract-2 | 全反射、入射角、反射角 |
| lens-1 | 凸レンズ、光軸、焦点、焦点距離 |
| lens-2 | 実像、虚像 |

例: `'電球や太陽のように、自分で光を出すものを**光源**といいます。光源から出た光は、あらゆる向きへ進みます。光の進む道を**光の道すじ**といい、…'`。

### 4b. 用語問題

各ステージに 2 問足す（合計 16 問）。どちらも `term: true` を問題オブジェクトに付ける（content-registry は知らない項目を無視するので検査には影響しない。テストがこの印を使う）。

- **main に 1 問**: `problems` の **index 1**（最初の問題の次）に挿入する。形式は `fill`（既存の `word` 空らん。選択肢をタップして入れる）。空らんの答えは、そのステージの解説で `**` を付けた用語そのもの。選択肢は 3 つで、まぎらわしい用語（同じステージや近いステージの用語）をまぜる。空らんは 1〜2 個。
- **retryPool に 1 問**: 同じ概念（`concept`）で、聞き方を変えた用語問題（`fill` か `choice`。`choice` なら「次の説明に合う言葉はどれ？」のように、説明文から用語を選ぶ）。
- `id` は既存の付け方（`<stage>-p<n>`、`<stage>-r<n>`）に続ける。main に挿入する問題の id は、既存の番号とぶつからないよう `<stage>-t1`（term）、retryPool は `<stage>-t2` とする。
- `prompt`、`explanation`、`hint` は必須（既存のテスト）。`explanation` の中では、聞いた用語に `**` を付けてよい（解答後の説明文も richtext で描く）。
- refract-2 の用語問題の `concept` は `'total-reflect'`（全反射）。他のステージは、そのステージの `concepts` の最初のもの。
- `figure` は不要（`fill(...)` ヘルパーが `figure: null` を付ける）。
- 理科として正しい内容にする。教科書名・出版社名を書かない（既存テスト）。

例（reflect-1 の main）:
```js
fill({
  id: 'reflect-1-t1', concept: 'reflect-law', term: true,
  prompt: '大切な言葉を入れよう。',
  text: '鏡に当たる光を[b1]、はね返った光を[b2]という。',
  blanks: [
    word('b1', ['入射光', '反射光', '法線'], '入射光'),
    word('b2', ['入射光', '反射光', '法線'], '反射光'),
  ],
  explanation: '鏡に当たる光が**入射光**、はね返った光が**反射光**です。言葉を区別できると、角度の話が分かりやすくなります。',
  hint: '「入射」は入ってくる、「反射」ははね返るという意味だよ。',
}),
```
