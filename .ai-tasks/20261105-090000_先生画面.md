## 目的

要件定義書「追加予定機能 4. 先生用の確認画面：生徒の学習進捗、理解度、苦手分野を一覧表示する。先生からの課題配信は当面不要」。
サーバーはない（設計書 7・9）ので、**この端末に保存されている生徒（プロフィール）の記録**を一覧し、さらに**ほかの端末で書き出した記録ファイル（設定の「記録を書き出す」の JSON）を読みこんで合わせて見る**形にする。読みこんだ記録はこの端末の学習記録には入れず、先生画面の中だけで使う（端末の記録を上書きしない）。

## js/teacher.js の仕様（純粋関数。`record`・`mastery`・`xp` を require）

```js
// 1 人分のまとめ
summarizeStudent(profile, rec, reg, config, now) → {
  id, nickname, avatar,
  unitId（profile.unitId か null）, level, xp, streak（rec.streak.count）,
  lastAt（history の最後の at。なければ null）, daysSince（lastAt から now までの日数。null なら null）,
  stages: { cleared, total }（登録済み全単元のステージ数）,
  mastery: { できた: n, もう少し: n, まだ: n, 未学習: n }（登録済み全概念を config.mastery.labels のラベルで数える。mastery に記録のない概念は 未学習）,
  weak: [{ conceptId, title, unitId, unitTitle, value, wrong, total }, ...]  // 「まだ」「もう少し」の概念を、誤答数（history の correct=false の数）が多い順に最大 5 つ
}
// 複数の生徒のまとめ（この端末の store と、読みこんだ store の配列）
summarizeAll(stores, reg, config, now) → { students: [summarizeStudent...（nickname 順）], weakConcepts: [{ conceptId, title, unitId, unitTitle, students: n（まだ の人数）, wrongRate（誤答数 ÷ 解答数、解答 0 なら null） }...] }
//   同じ profile.id が複数の store にあるときは、history の最後の at が新しいほうを使う（古いほうは捨てる）
toCsv(summary) → 文字列（UTF-8、先頭に BOM。列: ニックネーム, 単元, レベル, 経験値, 連続日数, 最終学習日, クリア/全ステージ, できた, もう少し, まだ, 未学習, 苦手（概念名を「・」区切り））
```
- 日付は `xp.localDate` を使う。`now` は Date。
- `reg.units()` で全単元を回し、`reg.stagesInOrder(unit.id)` でステージ、`unit.concepts` で概念。
- 例外を出さない（形の崩れた record は `app.normalizeStore` 相当の守りを `teacher.js` にも軽く入れる: `rec.history`・`rec.mastery` が無ければ空扱い）。

## js/ui-teacher.js（画面）

`renderTeacher(section, ctx)`:
1. `topBar('先生用の確認画面', '設定', () => ctx.go('settings'))`。
2. 注意書き（`caution`）: 「この端末に保存された記録を表示します。ほかの端末の記録は『記録ファイルを読みこむ』で合わせて見られます（この端末の記録には入れません）。」
3. 「記録ファイルを読みこむ」ボタン（`<input type="file" accept=".json" multiple>` を隠して使う。`RQ.storage.importJson` で各ファイルを読み、失敗したファイルは名前つきで `ctx.message`。読みこんだ store は `ctx.state.teacherImports`（配列）に保持。画面を描き直す）。「読みこんだ記録を消す」ボタン。
4. **生徒の一覧**（`table.teacher-table`。`summarizeAll([ctx.store, ...imports], ...)`）: ニックネーム（アバター小）／単元／Lv／連続／最終学習（「今日」「きのう」「n 日前」「なし」）／クリア（n / N）／理解度（できた・もう少し・まだ を 3 色の小さな数で）／苦手（概念名 2 つまで）。行をタップすると下に**その生徒の詳細**。
5. **生徒の詳細**: 単元ごとの進捗（`helpers.progressList`）、理解度（`helpers.masteryCard` を単元ごと）、苦手の概念（weak の一覧: 概念名・単元・誤答 n / 解答 m）、最近の取り組み 20 件（日付・ステージ・正誤）。
6. **クラスのまとめ**: 「まだ」の人数が多い概念 10 件（概念名・単元・人数・誤答率）。
7. 「CSV で書き出す」ボタン（`helpers.downloadText('rika-quest-teacher-<日付>.csv', toCsv(summary))`）。
8. 画面の文字は textContent（innerHTML はマスコット・図だけ）。ふりがな（ruby）は先生画面では付けなくてよい（`section` に `data-no-ruby`）。

設定画面: カード「先生用」に「先生用の確認画面を開く」ボタンと一文「生徒の進捗・理解度・苦手を一覧します（先生が使う画面です）」。

## テスト（tests/teacher.test.js）

`tests/fixtures/unit.js` の単元と `record.js` で記録を作って:
- `summarizeStudent`: history なし → lastAt null・stages cleared 0・mastery 未学習 = 概念数。`applyEvents` で誤答 2 回・正解 1 回の概念が weak の先頭、`wrong` 2・`total` 3。`finishStage` でクリア 1。
- `summarizeAll`: 同じ profile.id が 2 つの store にあるとき新しいほうを使う。nickname 順。`weakConcepts` の人数と誤答率。
- `toCsv`: 先頭が BOM、行数 = 生徒数 + 1、カンマや改行を含むニックネームが引用される。
- 形の崩れた record（`history` が無い）で例外を出さない。
