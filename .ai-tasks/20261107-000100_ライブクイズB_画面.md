## 先生の画面 `live-host`（`renderLiveHost(section, ctx)`。`data-no-ruby`。`ui-teacher.js` と同じ `renderSeq`/`isCurrent` の守り。画面を離れたら watch を止める）

1. **準備** card: 「データベースの URL」入力（`ctx.live.dbUrl()`、`normalizeUrl` で検査、保存・消す）。未設定なら「docs/live/setup.md の手順で Firebase を準備してください」と案内し、先へ進めない。
2. **問題を選ぶ** card: 単元の select（`RQ.units.list`）→ ステージの一覧（チェックボックス。ステージを選ぶとその `problems`・`retryPool` の choice 問題が `questionFromProblem` で入る。各問題もチェックで外せる）。「自分で書く」: 問題文・選択肢 4 つ・正解の select → 「足す」。選んだ問題の一覧（並べかえは不要。消すだけ）。「1 問の秒数」（10/20/30/60、既定 20）。「題名」（任意）。
3. **開始**: `newRoomCode` → `newRoom` → `db.put('rooms/<code>', room)` → **ロビー** card: 部屋コードを大きく（`class="live-code"`、`data-no-ruby`）、「生徒はホームの『ライブクイズに参加』でこのコードを入れます」、参加者の名前の一覧（`watch('rooms/<code>')` で更新。人数）、「問題を出す」（1 人以上で有効）。
4. **出題**: `nextState(state, questions, 'start', now)` を `patch('rooms/<code>/state', …)`（`startedAt` は `db.serverTime()` の offset を足した端末時刻でよい）。画面: 問題番号 n / N、問題文（大きく）、選択肢 4 つ（ア〜エ＋文。色分け: `live-opt-a`〜`d`）、残り時間（`state.startedAt` と `seconds` から 1 秒ごとに描く。0 で自動的に「答え合わせ」へ）、答えた人数 / 参加者数、button「答え合わせ」。
5. **答え合わせ**: `nextState(... 'reveal')` → `applyScores` で players を更新して `patch('rooms/<code>/players', …)`（score だけ）→ 画面: 選択肢ごとの人数の横棒（`tally`。正解を緑で、ほかは灰色）、正解の文、上位 5 人（`leaderboard`）、button「次の問題」（最後なら「結果を見る」）。
6. **最終結果**: 順位の一覧（全員）、「CSV で書き出す」（`H.downloadText`。列: 順位, ニックネーム, 得点）、「終了して部屋を消す」（`remove('rooms/<code>')` → 準備に戻る）。
7. 通信エラーは card の中に赤字で残す（`live-error`）。`watch` の onError は「接続が切れました。再接続しています」。

## 生徒の画面 `live`（`renderLive(section, ctx)`。プロフィールが要る。`data-no-ruby` は部屋コードとニックネームだけ）

1. **参加** card: 部屋コード入力（6 文字。英大文字に正規化）、「参加する」。URL は先生の端末と同じものが要るので、`ctx.live.dbUrl()` が無ければ「先生のデータベースの URL」入力を出す（先生が黒板に書く想定。1 度入れたら保存）。参加 = `db.get('rooms/<code>/meta')` で存在と `isStale` を確かめ → `put('rooms/<code>/players/<pid>', { name: nickname, joinedAt: {".sv":"timestamp"}, score: 0 })`（pid は `newPlayerId`。端末に `sessionStorage` で保持し、画面を描き直しても同じ pid）→ `watch('rooms/<code>')`。
2. **待機**: 「先生が問題を出すのを待とう」、参加者の人数。
3. **問題**（`state.phase === 'show'`）: 問題文、選択肢ボタン 4 つ（大きく、色は先生と同じ）、残り時間。押したら `put('rooms/<code>/answers/<index>/<pid>', { choice, at: {".sv":"timestamp"} })` → ボタンを disabled に「答えた！」。時間切れで disabled。
4. **答え合わせ**（`'reveal'`）: 自分の答えが正解か（○/×と正解の文）、この問題の得点（`scoreFor`。先生の計算と同じ式）、いまの合計と順位（`leaderboard` の自分の行）。**教材の問題なら** `ctx.live.record(recordEvents(...))` を 1 問につき 1 回だけ（reveal を初めて見たとき）。効果音（`RQ.sfx.play`）は正解・不正解で鳴らす。
5. **終了**（`'ended'`）: 最終順位（上位 5 人と自分）、「ホームへ」。
6. 接続が切れたら「接続が切れました」と再接続（live-db が行う）。画面を離れたら watch を止める。部屋が消えたら（data が null）「先生が部屋を閉じました」。

## CSS

`.live-code`（48px、字間広め）、`.live-question`（22px）、`.live-options`（2 列。375px では 1 列）、`.live-opt-a/b/c/d`（4 色: blue/green/orange/purple の薄い背景＋太い左線）、`.live-timer`（大きな数字。残り 5 秒で赤）、`.live-bar`（横棒。幅は % で）、`.live-rank`（順位の表）、`.live-error`。

## テスト・確認

ロジックは A で済み。ここでは `tests/offline.test.js`（PRECACHE と index.html）と `npm test` 全件成功。画面は headless Edge で、**偽の live-db**（`RikaQuest.liveDb.createDb` を差しかえ、メモリ上の部屋を 2 つの画面で共有する）を使って、先生: 準備 → 問題を選ぶ → 開始 → 出題 → 答え合わせ → 結果、生徒: 参加 → 答える → 答え合わせ → 結果、を通す（内蔵ブラウザは使わない）。
