## 判断した点

1. **バッジの判定の位置**: 指示書は `commitSession` の `setRecord` 直前だが、そこでは `closeRecord`（`lastResult` を作る）が先に動くため、クリアで取れたバッジが結果画面に出ない。そこで `closeRecord` の中でも finishStage / markReviewDone の後に判定してから `newBadges` を集めた（`commitSession` 側の判定も残す。2 回目は何もしない）。`finishSession` の経路も同じ。
2. `newBadges` は `Object.keys(...).filter(...)` の代わりに `badges.unseen(rec)`（DEFS の順、DEFS にない id は除く）にした。
3. `markBadgesSeen` は、まだ見せていないものが無ければ保存せず true を返す（結果画面を描き直しても無駄に保存しない）。
4. `stats(rec, reg, config)`: 「できた」の境は config から読むため 3 番目の引数を足した（省略時は読み込んだ config）。
5. `stats.level` は数値でない記録では 0。`totalStars`・`perfectStages` は登録済みのステージだけ数える。
6. 設計書の節番号: 既存の「4.6 今日のクエスト」が 4.5 の文中（「復習クエスト（4.6）」）や `docs/reports/sdd-ledger.md` から参照されているので、番号を変えないよう **4.5.1** にした。
7. `teacher.safeRecord` に `badges` を足した（`latestEntries` が safeRecord の形を渡すため、そこで落とすと数えられない）。数は DEFS にある id だけ。
8. 記録画面の取った日が読めない（形の崩れた at）ときは「取った」と出す。
9. `award` / `markSeen` は `"__proto__"` のキーを写さない（読み込んだファイル対策）。
