## 2. 動く図（anim）の使い回し

ドリルのカード（ステージ id が `-dr<数字>` で終わるステージの `lessons`）は、いま全部静止図だけ。既存の動く図のうち、**カードの内容と合うものだけ**を使い回す（ミニプリントのカードと同じやり方。`content/light.js` の `light-mp1-c1` の `anim: 'rays-spread'` の書き方を見る）。

- 動く図の種類（kind）は `js/anim.js`（光の 23 種）と `js/anim-physics.js`・`js/anim-chem.js`・`js/anim-bio.js`・`js/anim-earth.js` の `DEFS`。各関数の上のコメントに「何が動くか・もとのカード id」が書いてある。書き方の決まりは `docs/anim-guide.md`。
- **使える kind は、その単元の接頭辞のものだけ**（`tests/content-all.test.js` の `ANIM_PREFIX`: sound `so-`、force `fo-`、electricity `el-`、motion `mo-`、substance `su-`、state-change `st-`、solution `sl-`、chemical-change `ch-`、ion `io-`、plants `pl-`、animals `an-`、body `bo-`、heredity `he-`、nature `na-`、volcano `vo-`、strata `sr-`、weather `we-`、space `sp-`、basics `ba-`。light は光の 23 種と `li-` のどれでも）。
- 付け方: カードに `anim: '<kind>',   // 動く図の使い回し（js/anim-*.js）。figure は静止図として残す` を足す。`figure` はそのまま残す（動きを止める設定の生徒には静止図が出る）。
- **付けてよい条件（全部を満たすときだけ）**:
  1. 動く図が、カードの文（`text`）の言っている現象そのものを見せている（「近い話題」ではだめ）。
  2. 動く図の中の文字・数値・名前が、カードの文や静止図と食い違わない（例: カードが「30 Ω」なのに動く図が「20 Ω」ならだめ）。
  3. 動く図に替わることで、静止図にあった大事な情報（表・式・比べる 2 つの絵）が失われない。静止図が表・式・まとめの箱のカードには付けない。
  4. 静止図に `image`（写真）の部品があるカードには付けない（テストが落ちる）。
- 迷ったら付けない。合うものがないカードは静止図のままでよい（無理に全部へ付けない）。
- 新しい kind は作らない。`js/anim*.js` は変えない。

### 確かめ方（付けたカード全部）

`anim.frame(kind, t)` は `{ width, height, items }` を返すので、`js/figures.js` の `sceneSvg` で SVG にできる。付けた各カードについて t = 0.1・0.4・0.7 の 3 コマを画像（か SVG）にして見て、カードの文と合っているかを確かめる。画像化には headless Edge を使ってよい（`--user-data-dir` は実行ごとに別のフォルダにし、終わったら必ずプロセスを止める）。見て合わないと思ったら外す。

## 3. 領域の組みかえ（学習マップを分野でまとめる）

`.ai-tasks/20261121-160000_学習マップ_分野でまとめる.md` の **「B. 教材の領域の組みかえ」の表**のとおりに、担当の単元の `areas` を作り直す（プログラム側の A は実装済み: ステージの `free: true` が使える）。

- プリント（`-mp<n>`）とドリル（`-dr<n>`）の**すべてのステージ定義に `free: true` を足し**、`areaId` を入れ先の領域の id に直す。
- 領域「ミニプリント」（`…-miniprint`）と「ドリル」（`…-drill`）は `areas` から無くす（`free: true` の領域は残らない）。領域の `order` は 1 から振り直す。既存の基本の領域の id・title は変えない。
- 領域の中の並びは、基本のステージ（既存の順）→ プリント（番号順）→ ドリル（番号順）。
- ステージの `title`・`id`、問題・カード・概念（`lessonStageId` など）は変えない。
- 表に「あるだけ」「〜」と書いた範囲は、実際にあるステージで読みかえる。表にないステージが出てきたら、内容で近いほうの領域に入れて報告に書く。
- `docs/reports/content/<単元>.md` の冒頭の領域の説明に 1 行足す: 「2026-11-21: 領域を分野でまとめ、プリント・ドリルは free のステージ（いつでも挑戦できる）として各分野に入れた」。ドリルの節の表に、動く図を付けたカードは「（動く図: <kind>）」を足す。

## 端の場合

- `free` は真偽値 `true` だけ（文字列にしない）。基本のステージには `free` を付けない。
- 1 つのステージが 2 つの領域に入らない。どの領域にも入らないステージを残さない（組みかえの前後でステージの総数が同じことを node で確かめる）。
- 同じ kind を、同じステージの 2 枚のカードに付けない。
- 動く図の止まった絵（`restT`）がカードの文と食い違うものは付けない。
- `light` は `tests/content-light.test.js` がある: 「ミニプリント・ドリルのカードは anim を数えない」ので anim を付けてよいが、ステージ数 14・概念 8 は変えない。失敗したら内容を報告に書き、テストは直さない。

## 守ること

- 編集してよいのは担当の `content/<単元>.js`・`docs/reports/content/<単元>.md`・自分の報告ファイルだけ。`js/*`・`tests/*`・`index.html`・`sw.js`・`content/readings.js` は触らない。
- `npm test` を実行し、担当の単元に関する失敗がないこと（ruby の網羅率だけ許容）。
- git 操作なし。サブエージェントなし。パッケージ追加なし。ちびむすドリルのサイトにアクセスしない。
