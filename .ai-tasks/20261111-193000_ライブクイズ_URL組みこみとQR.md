# 実装指示書: ライブクイズ — データベースの URL の組みこみと QR コードでの参加

作成: Claude Code（Fable）2026-11-11。実装: Opus。レビュー: Codex（上限中は Claude）。設計: 設計書 14 章への追加。
ユーザー指示: 「（URL を）組みこんでほしいのと、QR コードみたいなのを出して、それをアプリから読み込めば入れるようにもしてほしい」。

## 決めたこと

1. **URL の組みこみ**: `js/config.js` に `live: { dbUrl: 'https://rika-quest-default-rtdb.firebaseio.com' }` を置く。`ctx.live.dbUrl()` は「端末に保存した URL（`rika-quest:live-db`）があればそれ、無ければ config の値」。生徒の参加画面は、URL が決まっていれば URL の入力欄を出さない（部屋コードだけ）。先生の準備の画面は「いまのデータベース: …（アプリに組みこみ）」と出し、別の URL に変える入力は「くわしい設定」として残す（消すと組みこみの値に戻る）。URL は公開リポジトリに載るが、規則で `rooms/` 以外は守られている（ユーザー承認済み）。
2. **QR コード（表示）**: 先生のロビー画面に、参加用の URL の QR コードを大きく出す。参加用の URL = `<今のページの origin + pathname>?live=<部屋コード>`（例 `https://schooldatahuruyama-lgtm.github.io/Rika_app/?live=A7K3PX`）。QR の下に部屋コードも今までどおり出す。出題中・答え合わせ中の画面にも、右上に小さく「参加コード A7K3PX」を出す（途中参加用。QR はロビーだけ）。
3. **QR コード（読み取り）は 2 通り**:
   - **端末のカメラアプリで読む**（どの端末でも動く）: QR の URL を開くとアプリが起動し、`?live=CODE` を読んで参加画面に部屋コードが入った状態で開く（プロフィールがあれば「参加する」を押すだけ。無ければプロフィールを作ったあと参加画面へ）。読んだあと URL から `?live=` を消す（`history.replaceState`。再読み込みで入り直さない）。
   - **アプリの中で読む**: 参加画面に「QR コードを読む」ボタン。`BarcodeDetector`（`formats: ['qr_code']`）と `navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } })` が使える端末だけボタンを出す。カメラの映像を出し、0.3 秒ごとに検出、`?live=CODE`（または 6 文字のコードそのもの）が読めたらカメラを止めて部屋コードに入れ、そのまま参加する。使えない端末では「この端末ではアプリの中で読めません。カメラアプリで QR コードを読むか、部屋コードを入れてください」と出す。画面を離れたらカメラを止める。カメラの許可が出なければその旨を出す。
4. QR の生成は外部ライブラリを使わず `js/qr.js` に書く（依存を足さない方針）。

## tests/qr.test.js（QR の正しさを自動で確かめる）

- **既知の値**: 型番 1・レベル Q・英数字モードの "HELLO WORLD" の例（データ符号語 `32 91 11 120 209 114 220 77 67 64 236 17 236 17 236 17`、誤り訂正符号語 `196 35 39 119 235 215 231 226 93 23`）でリード・ソロモンの計算を検査する（内部の `rsEncode(data, ecLen)` を export してよい）。形式情報: レベル M・マスク 0 のビット列が `101010000010010`。
- **構造**: `encode('https://example.com/?live=A7K3PX')` の size が `17 + 4 × 型番`、3 すみの位置検出パターン（7×7 の決まった形）とタイミングパターン、暗モジュール（(4×型番 + 9, 8)）がある。型番 2 以上は位置合わせパターンがある。
- **自前の復号で往復**: テストの中に小さな復号（マスクを外す → 符号語を読み出す → インターリーブを戻す → バイトモードを読む。誤り訂正の復号は不要＝誤りのない行列を読むだけ）を書き、`encode` した行列から元の文字列が戻ることを、長さ 10・30・62・100・150 バイトの文字列（型番 1〜10 にまたがる）と日本語をふくむ文字列で確かめる。
- 入らない長さ（型番 10 を超える）は null。
- `parseJoin`: URL・コードそのもの・小文字（大文字に直す）・関係ない文字列（null）・`I` `O` `0` `1` をふくむもの（null）。
