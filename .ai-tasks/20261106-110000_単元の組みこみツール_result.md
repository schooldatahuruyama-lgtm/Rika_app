## 判断した点

- `idConflicts` はステージ・概念・問題に加えて、領域とカードの id も比べる（`tests/content-all.test.js` の全単元の重複検査が領域・カードも見るため。比べないと組みこんだ後に npm test が落ちる）。同じ id の単元（`--force` の上書き）とは比べない。
- JS の検査は `validateUnit` ＋ `author.checkProblem`（全問題）＋ 単元 id の形（英小文字・数字・ハイフン、curriculum・readings は不可）。下書き JSON は `assembleUnit` の errors をそのまま使う。書く直前に、書く中身をもう一度評価して検査が通り、id・mascot・source が合うことを確かめる。
- `parseHeader` は分野の無い既存の形「（中学1年 理科）」も読み、field: null を返す（学年だけ使える）。
- `--mascot` で先生を変えたとき、JS は `"mascot": "X"`（手書きの `mascot: 'X'`）の最初の 1 つを書きかえる。JSON は `toContentJs` に渡す unit を変える。
- `patchSw` は既に入っているときは VERSION も上げない（指示書の「2 回目は changed: false」に合わせた）。
- 単元一覧の表の行は、既存の行の桁（`title:`・`grade:` の位置、全角は幅 2）にそろえる。
- 確認用一覧の fill は、空らんを【正解】に置きかえた文（数の単位は画面と同じく【】の後ろ）と語群。figure-choice は枠の文が読めれば「ア 文」、読めなければ region の label。ray-draw・drag（AI では作らない形）は「操作の問題」と書く。末尾に「概念のつながり」も付けた。

## 修正: Codex レビュー round1（.ai-review/20261106-115652_round1.md）の 2 件

High（--force で VERSION が上がらない）: `patchSw` を `patchSwPrecache(text, id)`（重複なら足さない）と `setSwVersion(text, version)` に分けた。`patchSw(text, id, version)` は両方を行い、version を渡せば PRECACHE に既にあっても VERSION を必ず変える（戻り値に `added` を足した）。`run` は content/<id>.js を書くので常に VERSION を上げる。--dry-run の表示は「PRECACHE には既に … があるので足さず、VERSION を A → B にする」。テスト: 既に PRECACHE にある sound で VERSION が上がり、重複しない検査を足し、run の --force の入れ直しでも VERSION が上がることを確かめるようにした。
