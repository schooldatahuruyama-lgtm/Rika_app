## 画面 `author`（`renderAuthor(section, ctx)`。`data-no-ruby`。`ui-teacher.js` の `renderSeq`/`isCurrent` と同じ守り）

### 1. 一覧（下書きがあるとき）
- `topBar('教材を作る', '先生画面', () => ctx.go('teacher'))`。
- card「下書き」: 各下書きの行（題名、単元 id、状態 下書き/確認済み、ステージ n/N 生成済み、「ためし中」の印、更新日）＋ button「開く」。button「新しく作る」、「下書きファイルを読みこむ」（`<input type=file accept=.json>` → `importDraftJson`）。
- card「API キー」: 伏せ字（先頭 7 文字＋ …）か「未設定」。input（type=password）＋「保存」、「消す」。注意文「キーはこの端末のブラウザにだけ保存されます。プリントの中身はキーで Anthropic に送られます。」。モデルの select（`claude-opus-5-5`（既定）・`claude-sonnet-5-5`）は下書きごと（`draft.model`）。

### 2. 新しく作る（フォーム）
- 単元 id（英小文字・数字・ハイフン。既存の教材 id と重なれば注意）、題名、学年（1/2/3）、分野（物理/化学/生物/地学）、担当の先生（A〜F。curriculum と同じ説明）、教科書名、学習範囲（textarea）、先生の注意（textarea）、ステージ数（2〜6、既定 4）、プリント（`<input type=file multiple accept=".txt,.md,.pdf,image/png,image/jpeg,image/webp">` → `RQ.authorApi.readFileAsAttachment`。一覧に名前と大きさ。PDF・画像は 1 本 10 MB まで）。
- 「作成を始める」→ `newDraft` → 保存 → 3 へ。

### 3. 生成
- 「計画を作る」（API）: `buildPlanPrompt` → `generate({ schema: SCHEMAS.plan, onProgress })` → `parseJson` → `normalizePlan` → errors が空なら `draft.plan` に入れて保存、ステージの一覧を表示。進行中は「生成中… n 文字」とキャンセルボタン（AbortController）。失敗はエラー文を card に出す（`ctx.message` ではなく、その場に残す）。
- ステージごとの行: 「このステージを作る」（API）／「作り直す」。すべて未生成なら「すべて作る」（順に 1 つずつ。途中で失敗したら止めて、できた分は保存）。
- **貼り付けの道**（API キーが無くても使える）: 各段階に「指示文をコピー」（`promptText` を textarea に出し、`navigator.clipboard.writeText` を試みて成否を message）と「結果を貼る」（textarea ＋「読みこむ」→ `parseJson` → normalize）。
- 生成が終わるたび `touch` → `saveDrafts`。

### 4. 編集（計画とステージ）
- 計画: 題名、領域の名前、ステージの名前・分、概念の名前（id は変えない）。
- ステージ: カードの文（textarea）、問題の一覧（形式・概念・問題文・選択肢（choice/figure-choice の枠）・正解（select）・解説・ヒント・term）。「問題を消す」「選択問題を足す」。figure-choice の図は枠の文だけ編集（`boxesScene` で組み直す）。items 版は「図は編集できません」。
- 編集のたびに `assembleUnit` で検査し、errors を card「教材の決まりとの照合」に出す（空なら「問題ありません」）。

### 5. ためす・書き出す・公開
- 「この端末でためす」トグル（`ctx.author.setPreview(id, on)`。errors があれば入れられない）。入れると「単元をえらぶ」に出る（grade 0「その他」）。
- 「確認済みにする」（status: 'checked'。チェック欄「内容を確かめました」が必要）／「下書きに戻す」。
- 「content/<id>.js を書き出す」（`toContentJs` → `H.downloadText`。status が checked でなければ disabled。ファイル名 `<id>.js`）、「下書き（JSON）を書き出す」（`exportDraftJson` → `rika-quest-draft-<id>.json`）、「下書きを消す」（`ctx.confirm`。ためし中なら unregister も）。
- 公開の手順を一文で: 「書き出した content/<id>.js を Claude Code（開発者）に渡すと、公開版に入ります。」

### 共通
- 文字は textContent。innerHTML は使わない。長い処理中はボタンを disabled。画面を離れたら（`isCurrent()` が false）生成の結果を捨てない（下書きは保存する）が描かない。
- 375px で崩れない（フォームは縦並び、問題の一覧は card の中に縦に）。

## CSS

`.author-form`（縦の stack）、`.author-draft-list`、`.author-stage-row`、`.author-problem`（枠線の薄い箱、見出しに形式と id）、`.author-progress`（生成中の表示）、`.author-errors`（赤みの薄い背景の一覧）、`.author-ok`（緑の薄い背景）。textarea は幅 100%、最小 3 行。

## テスト

ロジックは A のテストで足りる。この指示書では `tests/offline.test.js`（PRECACHE と index.html の一致）と `npm test` 全件成功を確かめる。画面は headless Edge で: 先生画面 → 教材を作る → 新しく作る → （API キーなしで）「指示文をコピー」が textarea に出る → 偽の結果（A のテストの fixture の JSON）を貼って読みこむ → 編集 → ためす → 単元一覧に出る → 書き出しのボタンが状態で変わる。
