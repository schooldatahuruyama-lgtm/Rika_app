# 実装指示書: 書き出した教材を公開版に組みこむ道具（tools/add-unit.js）

作成: Claude Code（Fable）2026-11-06。実装: Opus。レビュー: Codex。設計: 設計書 13 章「公開（要件 6）」。

## 目的

先生が「教材を作る」で書き出した `content/<id>.js`（または下書き JSON）を、1 コマンドでリポジトリに組みこむ。手作業（index.html・sw.js・単元一覧の表・先生の確認用一覧の作成・検査の調整）をなくし、間違いを減らす。

## 作成・変更するファイル

| ファイル | 変更 |
|---|---|
| `tools/add-unit.js` | 新規。Node スクリプト（依存なし）。`require` されたときは関数を export し、直接実行されたときだけ main を動かす（`require.main === module`） |
| `js/author.js` | `toContentJs` が書く unit に `source: 'author'` を入れる（`assembleUnit` の unit に付けてもよい。validateUnit は知らない項目を無視する） |
| `tests/content-all.test.js` | `unit.source === 'author'` の単元では「カードに図がある」の検査を飛ばす（文の字数・問題の項目などは今までどおり）。anim の検査は author の単元にはカードの anim が無いので自然に通る |
| `tests/add-unit.test.js` | 新規（下記） |
| `README.md` | 「単元を足す手順」を道具を使う手順に書きかえる（手作業の手順も「道具を使わない場合」として残す） |
| `docs/reports/content/`（実行時） | 道具が `<id>.md` を作る（先生の確認用一覧） |

## tools/add-unit.js の仕様

```
node tools/add-unit.js <file> [--grade 1|2|3] [--field 物理|化学|生物|地学] [--mascot A-F] [--force] [--dry-run] [--no-test]
```
- `<file>` は `content/<id>.js` の形の JS（「教材を作る」の書き出し）か、下書き JSON（`exportDraftJson` の形。`js/author.js` の `importDraftJson` → `assembleUnit` で unit にする。errors があれば止める）。
- 学年・分野: 引数 > JS の先頭コメント `// 「…」教材データ（中学N年 理科・分野）` から読む > 下書き JSON の `input.grade`/`input.field`。どれにも無ければエラー。mascot は `unit.mascot`（引数で上書き可）。
- 手順（`--dry-run` は書かずに「何をするか」を出す）:
  1. unit を読む（JS は `vm` で評価し `module.exports.unit` か `RikaQuest.content.register` に渡されたものを受け取る）。`js/content-registry.js` の `validateUnit` と、`js/author.js` の問題ごとの検査（assembleUnit と同じ関数を使えるなら使う。無ければ validateUnit だけ）で errors があれば止めて一覧を出す。
  2. `content/<id>.js` が既にあれば `--force` が無い限り止める。ほかの単元のステージ・概念・問題の id と重なれば止める（登録済みの全 `content/*.js` を読んで比べる）。
  3. `content/<id>.js` を書く（JS ならそのまま写す。`source: 'author'` が無ければ `const unit = {` の直後に足す。JSON なら `toContentJs` で作る）。
  4. `index.html` の `<script src="content/…">` の最後の行の直後に `<script src="content/<id>.js"></script>` を足す（同じ字下げ）。既にあれば足さない。
  5. `sw.js` の `PRECACHE` で `'content/…'` の最後の直後に `'content/<id>.js',` を足す（同じ字下げ）。`VERSION` を今日の日付で上げる（`YYYY-MM-DD-N`: 同じ日付なら N+1、違う日付なら 1。既存の形 `'2026-11-06-24'` と同じ）。
  6. `content/curriculum.js` の `UNITS` に同じ id の行が無ければ、その学年のブロックの最後（次の学年のコメント `// 2 年` の前、3 年なら配列の最後の行の前）に `{ id: '<id>', title: '<unit.title>', grade: N, field: '<field>', mascot: '<M>' },` を足す（既存の行と同じ書き方・字下げ。title の `'` はエスケープ）。
  7. `docs/reports/content/<id>.md` を作る（既にあれば `--force` のときだけ上書き）。形は既存の `docs/reports/content/sound.md` に合わせる: 見出し、単元の概要（学年・分野・領域・ステージ数・概念数・問題数）、ステージごとに「カード: c1 …／c2 …」（各カードの文の先頭 40 字）と問題の表 `| id | 形式 | 概念 | 内容【正解】 |`（choice は prompt と正解の文、fill は text と正解の語・数、figure-choice は prompt と正解の枠の文か region の label）、概念の確認問題の表、末尾に「AI 教材作成で作成。理科としての正しさは先生が確認する」。
  8. `--no-test` が無ければ `npm test` を実行し、結果の末尾（tests/pass/fail の行）を出す。失敗したら「書いたファイルはそのまま。直すか、git checkout で戻す」と案内。
- 出力は日本語。失敗は非 0 の終了コード。ファイルは UTF-8・LF で書く（既存ファイルの改行コードを保つ）。

### export する関数（テスト用）
`parseHeader(text) → { grade, field } | null`、`patchIndexHtml(text, id) → { text, changed }`、`patchSw(text, id, version) → { text, changed }`、`nextVersion(current, today) → string`、`patchCurriculum(text, row) → { text, changed }`、`reportMd(unit, meta) → string`、`loadUnitFile(path) → { unit, errors }`、`idConflicts(unit, otherUnits) → string[]`。

## テスト（tests/add-unit.test.js）

- `parseHeader`: 書き出しの先頭 2 行から 1・物理 を読む。無ければ null。
- `patchIndexHtml` / `patchSw`: 実際の `index.html`・`sw.js` の文字列に `zz-test` を足すと、content の最後の直後に 1 行入り、2 回目は changed: false。`nextVersion('2026-11-06-24', '2026-11-06')` → `'2026-11-06-25'`、`('2026-11-06-24', '2026-11-07')` → `'2026-11-07-1'`。
- `patchCurriculum`: 実際の `content/curriculum.js` に grade 2 の行を足すと `// 3 年` の直前に入る。grade 3 は配列の最後。既にある id は changed: false。足した後の文字列を `vm` で評価して `units()` に行があり、順が学年順のまま。
- `reportMd`: `tests/author.test.js` の fixture から組んだ unit で、表の行数が問題数と同じ、正解が【】で入る。
- `loadUnitFile`: `toContentJs` で作った JS を一時ファイルに書いて読める。壊れた JS は errors。
- `idConflicts`: 既存の `content/sound.js` と同じステージ id を持つ unit で指摘が出る。
- `npm test` 全件成功。実際に `tools/add-unit.js --dry-run` を、`toContentJs` で作った一時ファイルに対して実行して、例外なく「何をするか」が出る（テストの中で `child_process.execFileSync` で）。
