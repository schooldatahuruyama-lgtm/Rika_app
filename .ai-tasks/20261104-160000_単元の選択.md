# 実装指示書: 単元をえらぶ（全単元への展開の第一歩）

作成: Claude Code（Fable）2026-11-04。実装: Claude Code のサブエージェント（Opus）。レビュー: Codex。

## 目的

要件定義書 `docs/requirements.md` の「追加予定機能 1. 全単元への展開：中学1〜3年の理科を体系化し、『単元を自由に選ぶ』『おすすめ問題で学ぶ』を両立する」の第一歩。
今はアプリ全体が `UNIT_ID = 'light'` に固定されている（`js/ui-screens.js`）。これを「生徒ごとに選んだ単元」に変え、中学 1〜3 年の単元一覧（教材がまだない単元は「準備中」）を見せる画面を足す。
設計書 `docs/superpowers/specs/2026-11-03-rika-quest-design.md` 5.3「将来の他単元は同じ形のファイルを追加する」に沿い、教材のファイル（`content/<単元>.js`）を 1 つ足して `index.html`・`sw.js` に加えるだけで、その単元が選べるようになる形にする。
単元ごとの先生（マスコット）はすでに `js/mascot.js` の `forUnit(unit)`（`unit.mascot` が A〜F）で切り替わる。単元一覧の各単元にも先生を出す。

**新しい理科の教材（解説・問題）は書かない。** 今回はしくみだけ。

## js/units.js の仕様

```js
// 単元の一覧（教材の登録状況つき）と、いま選んでいる単元
// list(reg, curriculum) → [{ id, title, grade, field, ready, unit, teacher }, ...]
//   curriculum.units() の順。ready は reg.unit(id) が登録されているか。unit は登録された教材（なければ null）。
//   teacher は RikaQuest.mascot.forUnit(ready ? 登録された教材 : 表の項目)（登録済みなら教材の mascot を優先）。
//   curriculum にないが reg に登録されている単元は末尾に足す（grade: 0, field: '', title は教材の title）。
// currentId(reg, curriculum, profile) → 文字列 | null
//   profile.unitId が文字列で reg.unit(profile.unitId) があればそれ。
//   なければ list(...) の ready な最初の id。1 つもなければ null。
```

- 依存: `mascot.js`（Node では `require('./mascot.js')`、ブラウザでは `root.RikaQuest.mascot`。`recommend.js` の書き方に合わせる）。
- `curriculum` が `null`/`undefined` でも例外を出さず、登録済みの単元だけを並べる（`units()` のない値は空の表として扱う）。
- 公開: `{ list, currentId }`。ブラウザでは `RikaQuest.units`。

## js/app.js の変更

- `normalizeStore`: 各 profile について `if (p.unitId !== undefined && typeof p.unitId !== 'string') delete p.unitId;`（知らない単元 id はそのまま残す。表示時に `units.currentId` が既定へ戻す）。
- `makeCtx()` に足す:
  - `curriculum: RQ.curriculum`（`RQ.curriculum` がなければ `null`）
  - `get unitId() { return RQ.units.currentId(state.reg, RQ.curriculum || null, currentProfile()); }`
  - `setUnit(id)`: `state.reg.unit(id)` がなければ `false` を返す。あれば現在の profile の `unitId = id` にして `save()` の結果を返す。profile がなければ `false`。
- ファイル冒頭のコメント（ctx の説明）にも 3 つを足す。

## js/ui-screens.js の変更

- `const UNIT_ID = 'light';` を削除。`helpers` の `UNIT_ID` も外す（ほかで使っていないことは grep 済み）。
- 冒頭コメントの ctx の説明に `curriculum, unitId, setUnit` を足す。
- **ホーム** `renderHome`:
  - `const unit = ctx.reg.unit(ctx.unitId);`（`ctx.unitId` が null なら unit は null。先生は `RQ.mascot.forUnit(unit)` のまま＝まる先生）。
  - hero の直後に「いまの単元」カードを足す:
    ```
    card([
      cardTitle('いまの単元'),
      el('p', { class: 'unit-current', text: unit ? unit.title : '単元がえらばれていません' }),
      （curriculum に項目があれば）el('p', { class: 'muted', text: '1年・物理' のように GRADE_LABELS[grade] + '・' + field }),
      button('単元をえらぶ', () => ctx.go('units'), 'btn-block'),
    ])
    ```
  - `questCard`: `UNIT_ID` → `ctx.unitId`。「全部クリア！」のときの文を「学習マップから好きなステージにもう一度挑戦するか、ほかの単元をえらぼう。」にし、`button('単元をえらぶ', () => ctx.go('units'), 'btn-block')` を足す。
- **単元をえらぶ画面** `renderUnits(section, ctx)`（`screens.units`）:
  - `topBar('単元をえらぶ', 'ホーム', () => ctx.go('home'))`。
  - `const items = RQ.units.list(ctx.reg, ctx.curriculum); const current = ctx.unitId;`
  - 学年ごと（`grade` の値ごと、1→2→3→0 の順。項目のない学年は出さない）に `card` を 1 つ: `cardTitle(GRADE_LABELS[grade])` と `el('ul', { class: 'unit-list' })`。
  - 各単元は `li` の中の `button.unit-card`（`type: 'button'`）:
    - `ready` でなければ `disabled: true`、class に `is-soon` を足す。
    - 中身: `svgBox(RQ.mascot.svg(44, item.teacher), 'unit-teacher')`、`el('span', { class: 'unit-body' }, [ el('span', { class: 'unit-title', text: title }), el('span', { class: 'unit-meta muted', text: meta }) ])`。
    - `meta`: `field`（空なら省く）と、ready なら `'クリア n / N ステージ'`（N は `ctx.reg.stagesInOrder(id).length`、n はそのうち `RQ.record.stageState(rec, s.id).status === 'cleared'` の数）、ready でなければ `'準備中'`。区切りは `'　'`（全角空白）。
    - `id === current` なら `el('span', { class: 'tag tag-ok unit-now', text: 'いまの単元' })` を末尾に足し、`aria-current: 'true'`。
    - `aria-label`: `title + '（' + meta + (current なら '、いまの単元' : '') + '）'`。
    - `onclick`（ready のときだけ）: `ctx.setUnit(id)` → `ctx.go('home')` → `ctx.message('単元を「' + title + '」にしました。', 'ok')`。`setUnit` が `false` なら `ctx.message('単元を変えられませんでした。', 'warn')` だけ。
  - 末尾に `button('ホームへ', () => ctx.go('home'), 'btn-block')`。
- **学習マップ** `renderMap`: `ctx.reg.unit(ctx.unitId)`。unit がないときの文を「単元がえらばれていません。」にし、`button('単元をえらぶ', () => ctx.go('units'), 'btn-primary btn-block')` を出す。
- **ステージ入口** `renderStage`: `areaOfStage(ctx.reg.unitOfStage(stage.id), stage.id)`。
- **記録** `renderRecord`: `RQ.units.list(ctx.reg, ctx.curriculum).filter(x => x.ready)` を使い、
  - `progressCard(ctx, rec, readyItems)`: 1 枚のカード。単元ごとに `el('h3', { class: 'progress-unit', text: title })` を置いてから、その単元の領域の行（今の作り）。ready が 0 なら「教材が読み込まれていません。」の `p`。
  - `masteryCard(ctx, rec, unit, title)`: ready な単元ごとに 1 枚、見出しは `'理解度の目安（' + title + '）'`。
- **ホームの hero の文**（`'今日も' + unit.title + 'を探検しよう'`）はそのまま。

## テスト

- `tests/curriculum.test.js`:
  1. `units()` の各項目に `id`（文字列、重複なし）・`title`・`grade`（1〜3）・`field`（物理/化学/生物/地学）・`mascot`（`mascot.MASCOTS` のキー）がある。
  2. `unit('light')` があり、その `mascot` が `require('../content/light.js').unit.mascot` と同じ。`unit('nope')` は `null`。
  3. `units()` は呼ぶたびに新しい配列（元を変えられない）。
- `tests/units.test.js`（`tests/fixtures/unit.js` の単元 `u` と、小さな偽の curriculum を使う）:
  1. `list`: curriculum に `[{ id: 'u', ... mascot: 'B' }, { id: 'x', ..., mascot: 'C' }]`、reg に `u` だけ登録 → 2 件、`u` は `ready: true` で `unit` が登録した教材、`x` は `ready: false, unit: null`。`teacher.name` は `u` が教材の mascot（教材に mascot がなければ まる先生）、`x` が ぷにカプセル。
  2. `list`: reg にあって curriculum にない単元 `u` → 末尾に `grade: 0, field: '', title: 教材の title, ready: true`。
  3. `list(reg, null)` と `list(reg, {})` は例外を出さず、登録済みだけを返す。
  4. `currentId`: `profile.unitId` が登録済み → それ。未登録の id／数値／`undefined`／profile が `null` → ready な最初の id。登録が 0 件なら `null`。
- 既存テストはすべて成功のまま（`npm test`）。

完了の条件: `npm test` がすべて成功。ブラウザで、ホームに「いまの単元: 光の世界」が出て、「単元をえらぶ」で 1〜3 年の一覧（光の世界だけ押せる、ほかは準備中、各単元に先生の絵）が出る。
