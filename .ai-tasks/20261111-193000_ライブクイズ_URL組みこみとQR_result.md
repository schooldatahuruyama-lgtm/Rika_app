## ブラウザでの確認（headless Edge・CDP、偽の live-db。スクラッチパッド `qrB/`）

- 別の実装（jsQR 1.4.0、jsdelivr から確認ページだけで読み込み）で `qr.encode` の 7 種（参加 URL、日本語、型番 8 相当まで）がすべて正しく読めた。
- 先生: 組みこみの URL の表示、URL を入れずに問題を選べる、ロビーに QR（420px 幅で 280px）、QR の path が参加用 URL の encode と一致、出題・答え合わせに参加コード、出題中は QR なし。
- 生徒（プロフィールなし）: `/?live=CODE` で開く → プロフィール画面、URL から `?live=` が消える → 作成後に参加画面、コードが入っている、URL 欄なし → 参加 → 読み込み直すとホーム。
- アプリの中で読む（BarcodeDetector・getUserMedia は偽物）: 映像が出る → 3 回目の検出で参加、カメラ停止。`facingMode: 'environment'`、`formats: ['qr_code']`。許可なし（NotAllowedError）の案内。画面を離れるとカメラ停止。この Edge（Windows）は BarcodeDetector が無いので案内文が出ることも確認。

## 指示書と違う点・判断した点

- `encode` は L/Q/H も受け付ける（表を持つだけ。既定 M）。戻り値に `version`・`mask`・`ec` も入れた。
- プロフィール作成のあと参加画面へ行く仕組みは、`ui-screens.js` を変えずに `app.go` で `home` → `live` に回す形にした（`pendingLive` は参加画面が読むと消える）。
- 生徒の参加画面にも「くわしい設定: データベースの URL を変える」を残した（先生が別のデータベースを使うとき用）。空にして参加すると組みこみに戻る。
- `setDbUrl` に組みこみと同じ URL を渡したときは保存を消す（「組みこみ」の表示を正しく保つため）。
