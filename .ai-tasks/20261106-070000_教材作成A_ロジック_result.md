## 判断した点

- **ステージ・概念の id は単元の id で始める**（`field` → `magnet-field`）。登録先の検索（stage/concept）は全単元をまたぐので、既存単元（light の `straight` など）とぶつからないようにした。指示文でもそう頼み、コードでも付ける（付いていれば何もしない）。モデルの id → 整えた id の対応表で参照（areaId・concepts・basic・lessonStageId）をつなぐ。
- **lessonStageId** が無い/知らない id なら、その概念を扱う最初のステージにする。初めて学ぶステージの concepts に入っていなければ足す（そのステージで類題・確認問題を作らせるため）。**basic** が知らない id なら errors に出して null にする。ステージのない領域は外す。minutes は 3〜6 に収める。
- **checkPool** は、各ステージで「そのステージが lessonStageId の概念」の分だけ受け取る（ほかのステージの分は捨てる）。`<conceptId>-k<n>` の id がステージ間でぶつからないため。
- **assembleUnit** のステージの id・題名・時間・概念は計画（plan）から取る（計画を直したときに合わせるため）。
- 問題の concept が計画に無い id で、ステージの概念が 1 つならその概念にする。
- **figure-choice（items 版）**: region が 2 つ以上あれば region を選択肢にする（id が無い・重複なら `r<n>`、label が無ければ ア…、r は 22 以上）。region が 2 つ未満なら boxes から枠を組み、items は使わない。boxes も 2 つ未満なら choice に落とす（このとき選択肢 1 つの choice は assembleUnit の検査で「選択肢が 1 つです」と出る）。
- **arrow**: スキーマの項目一覧に x1〜y2 が無いので、`points: [[x1,y1],[x2,y2]]` で受けて x1〜y2 に直す（チャット経由で x1〜y2 が来ればそれを使う）。text の size は 13 以上に、色はトークン名・#hex・none だけ残す。
- **boxesScene**: 枠 2〜3 は横 1 列、4 は 2×2。文字は 14px。1 行の文字数は「12 文字まで、かつ枠の幅に収まる数」（2×2 と 2 枠は 9 文字、3 枠は 6 文字）。12 文字×13px は 2 枠横並びの幅（約 148px）に収まらないため。region は枠の左上（中心 x+26, y+26）。
- **assembleUnit の追加検査**（validateUnit に無いもの）: 問題文・解説・ヒントが空でない、choice の正解が選択肢にある・選択肢 2 つ以上、fill の word の正解が選択肢にある・文に `[b1]` がある・正解を入れると `judge` で正解になる、figure-choice の正解の region がある、カードの文が 40〜160 字、教科書名・出版社名が入っていない（tests/content-all.test.js と同じ決まり）。
- normalizeStage の errors: カード数、warmup が choice か、問題数、用語問題（term）の有無、図の問題が作れない、概念ごとの類題 2・確認問題 3。
- 下書きの書き出しは `{ format: 'rika-quest-draft', version: 1, draft }`。読みこみは包みなしの draft も受け、`preview` は false に戻す（端末ごと）。
- 正解の番号は整数のほか、数字の文字列・'a'〜'd' も受ける（チャット経由のため）。
- `toContentJs(unit, input, now)` は日付を決めるために 3 つめの引数（省略可）を足した。先頭のコメントに教科書名は書かない。

## 気になる点

1. **AI スキーマ**: 構造化出力が `$defs`/`$ref`、anyOf（問題 3 種・空らん 2 種・items の null）、optional 項目（部品の 16 項目）をどこまで受けるか、実 API では確かめていない（テストは偽 fetch のみ）。optional や union の数に上限がある場合は 400 になり、そのときは `output_config` を含む 400 として **schema なしで 1 回やり直す**ので止まりはしないが、形の保証がなくなる。実キーで 1 度試すのがよい。部品の type は enum（7 種）にした。
2. **公開時の検査とのずれ**: `tests/content-all.test.js` は「レッスンカードに図がある」を求めるが、指示書どおりカードの figure は null。書き出した `content/<id>.js` をそのままリポジトリに入れるとこの検査で落ちる（図を足すか、AI 教材は例外にするかの判断が要る）。index.html・sw.js への追加も要る。
3. 2×2 の枠は 3 行（約 27 字）まで。それより長い枠の文ははみ出す（指示文では 20 字以内と頼んでいる）。
4. `anthropic-version: 2026-10-21` と beta 名・`fallbacks` は指示書のとおりで、実 API での確認はしていない。
