# 実装指示書: 先生が、授業ログのクラスの進み具合を見る（段階 4）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。先に `js/teacher.js`・`js/ui-teacher.js`・`js/teacher-gate.js`・`js/class-unit.js`・`js/sync.js`（`packState`・`unpackState`）・`js/app.js`（`go`・`start`・`makeCtx`）を読んでから始めてください。

## 目的

授業ログとつなぐ作業の段階 4。先生が、授業ログのクラスを選ぶと、そのクラスの生徒の進み具合（単元・最後に学習した日・クリアした数・苦手な所など）が一覧で出る。今の「記録ファイルを集める」をしなくてもよくなる。

Claude Code が決めた動き（2026-11-20。先生に伝えてある）:

1. 置き場所は、今ある「先生用の確認画面」（`teacher` の画面）。今ある一覧・くわしい表示・クラス全体の苦手・CSV を、そのまま使う。
2. 使えるのは、授業ログに**先生として**ログインしているときだけ。先生と確かめられたら、パスコードは聞かない。
3. 一覧には、出席番号・生徒の ID・ニックネームと、今ある列を出す。
4. まだ始めていない生徒・読めなかった生徒は、消さずに別に並べる。
5. 読むのは生徒ごとの「今の状態」（`rika/state/<uid>`）だけ。履歴（`rika/log`）は読まない。
6. 読みこんだ一覧は、端末に保存しない（メモリの中だけ）。

## データベースの形（授業ログ側の規則で決まっている。変えられない。**読むだけ**）

| 場所 | 中身 | 決まり |
|---|---|---|
| `teacherList/<uid>` | 先生なら `true` | 本人が読める |
| `classes` | `{ <classId>: { year: 数, name: 文字列, … } }` | 先生が丸ごと読める |
| `members/<classId>` | `{ <生徒の ID>: 出席番号（数） }` | 先生が読める |
| `accounts` | `{ <uid>: 生徒の ID の文字列 }`（先生の uid は入っていない） | 先生が丸ごと読める |
| `rika/state/<uid>` | `{ v: 1, updatedAt: 数, json: 文字列, base?: 数 }`。`json` は `sync.packState` の形 | 先生が読める |
| `rika/classUnit/<classId>` | 先生が決めた単元の id（無いこともある） | 先生が読める |

このアプリからは、どれも書かない。

## 変えるファイルと内容

### 1. `js/class-progress.js`（新しく作る。`js/class-unit.js` と同じ IIFE・`module.exports` の形）

`RikaQuest.classProgress = { sortClasses, memberRows, createClassProgress }`

- 通信は `js/class-unit.js` の `request` と同じ決まりにする（`config.dbUrl` + パス + `.json?auth=<通行証>`、GET だけ、`redirect: 'error'`、`config.timeoutMs`、401/403 → `denied`、500 以上・例外・時間切れ → `offline`、そのほか → `broken`）。通行証は URL の `auth=` にだけ入れ、記録・保存場所に出さない。
- `sortClasses(value)` → `classes` の値から `[{ id, year, name }]` を作る。`id` は `/^[A-Za-z0-9]+$/` に合うものだけ。`year` が有限の数でない・`name` が文字列でない行は捨てる。`year` が 2000 未満の行（授業ログの「規則の確認」用のクラス）は捨てる。`year` の大きい順、同じなら `name` の文字コード順、`id` の順。
- `memberRows(members, accounts)` → `[{ sid, number, uid }]`。`members` は `{ sid: 数 }`、`accounts` は `{ uid: sid }`。`sid` は `/^[A-Za-z0-9-]{1,40}$/` に合うものだけ。`number` が有限の数でなければ `null`。同じ `sid` を持つ uid が 2 つ以上あるときは、`uid` を `null` にして `dup: true` を付ける（どちらの記録か決められないため）。uid に `/[/.#$\[\]]/` があるものは使わない。`number` の小さい順（`null` は後ろ）、同じなら `sid` の順。
- `createClassProgress({ link, fetch, config, unpackState })` → `{ isTeacher(), listClasses(), load(classId) }`。どれも投げない。
  - 共通: `uid = link.savedUid()`、`link.getToken()` で通行証。どちらかが無ければ `{ status: 'offline' }`（ログインしていないときは `{ status: 'none' }`: `link.status() === 'none'` または `savedUid()` が無い）。
  - `isTeacher()` → `teacherList/<uid>` を読み、`{ status: 'ok', teacher: true | false }`。`denied` のときは `{ status: 'ok', teacher: false }`。結果（`ok`）は、同じ uid の間は覚えておいてよい。
  - `listClasses()` → 先生でなければ `{ status: 'not-teacher' }`。`classes` を読み、`{ status: 'ok', classes: sortClasses(value) }`。
  - `load(classId)` → `classId` が `/^[A-Za-z0-9]+$/` に合わなければ `{ status: 'broken' }`。先生でなければ `not-teacher`。`members/<classId>` と `accounts` と `rika/classUnit/<classId>` を読む（`classUnit` は読めなくても続け、`null` にする）。`memberRows` を作り、61 人以上なら最初の 60 人だけ使い `truncated: true`。`uid` のある行について `rika/state/<uid>` を読む（同時に 5 つまで）。
    - 返す形: `{ status: 'ok', classId, classUnit: 文字列 | null, truncated: 真偽, rows: [{ sid, number, uid, kind, profile?, record?, updatedAt? }] }`
    - `kind`: `'ok'`（状態が読めて、`v === 1`・`updatedAt` が有限の数・`unpackState(json)` が `null` でない）、`'empty'`（`rika/state/<uid>` が `null` = まだ始めていない）、`'no-account'`（`uid` が無い = まだログインしたことがない）、`'dup'`（上の `dup`）、`'broken'`（形がおかしい・`json` が 500000 文字より長い）、`'failed'`（その生徒の読みこみが `offline`・`denied`・`broken`）。
    - `members` か `accounts` が読めなければ、その状態（`offline`・`denied`・`broken`）を返す。
  - 同じ `classId` の `load` が重なったら 1 回にまとめる。

### 2. `js/teacher.js`

- `summarizeStudent`: 履歴から「最後に学習した時刻」（`lastAt`）が取れないとき（履歴が空）、状態に残っている日付を使う: `mastery` の各 `lastAt` と、`streak.lastDate`（その日の 0 時として扱う）のうち、いちばん新しいもの。どれも無ければ今までどおり `null`。履歴があるときの動きは変えない。
- `storeFromState(profile, record, key)`（新しく。export に足す）→ `{ version: 1, currentProfileId, profiles: [profile の写し], records: { [id]: record } }`。プロフィールの `id` は `'acct-' + key` に置きかえる（生徒どうしで重ならないように）。もとの `profile`・`record` は変えない。
- ほかは変えない。

### 3. `js/ui-teacher.js`

- **先生の確かめとパスコード**: `teacher` の画面を開いたとき、`ctx.state.account` があり `ctx.state.link` があれば、`classProgress.isTeacher()` を確かめる。`teacher: true` なら、パスコードの画面を出さずに `ctx.state.teacherUnlocked = true` にして先生の画面を出す。確かめている間は「確かめています…」を出す（`renderSeq`・`isCurrent` の今ある守り方に合わせ、古い返事で描き直さない）。`teacher: false`・`ok` 以外・アカウントのモードでないときは、今までどおりパスコードの画面。
- **`reloadIfStoreGone`**: アカウントのモード（`ctx.state.account` がある）では、端末モードのキー（`ctx.config.storageKey`）を見て再読みこみする今の確かめを行わない（端末のキーが無いと、開き直しをくり返すおそれがあるため）。端末モードの動きは変えない。
- **カード「授業ログのクラスから読みこむ」**（「記録を合わせて見る」のカードの上に置く）:
  - 出すのは、先生と確かめられたときだけ。それ以外では、このカードを出さない。
  - 中身: クラスを選ぶ欄（`select`。「2026 年度 1年1組」の形。年度の新しい順）、「読みこむ」ボタン、状態の文（`role="status"`）。クラスの一覧は、カードを出すときに `listClasses()` で読む。0 個なら「授業ログにクラスがありません。」。
  - 「読みこむ」: `load(classId)` を呼ぶ。読みこみ中は「読みこんでいます…」とし、ボタンを押せなくする。
  - 成功したら、`ctx.state.teacherClass = { classId, name, classUnit, truncated, rows, loadedAt }` に入れて描き直す。
  - 失敗の文: `offline` →「つながりません。電波を確かめて、もう一度ためしてください。」、`denied`・`not-teacher` →「先生のアカウントで、授業ログにログインしているときだけ読みこめます。」、`broken` →「クラスの記録を読みこめませんでした。」、`none` → カードを出さない。失敗しても、前に読みこんだ一覧は消さない。
  - 「クラスの一覧を消す」ボタン（読みこんだあとだけ出す）→ `ctx.state.teacherClass = null`。
- **一覧の出し方**: `ctx.state.teacherClass` があるときは、`stores` を、端末の記録・読みこんだファイルではなく、**クラスの `kind: 'ok'` の行から作ったもの**（`RQ.teacher.storeFromState(profile, record, uid)` → `ctx.app.normalizeStore`）にする。今ある `summarizeAll`・`latestEntries`・`fillUnitTitles`・`studentsCard`・`detailCard`・`classCard`・CSV は、そのまま使う。
  - 見出しに「（クラスの名前）の進み具合（n 人）」と、読みこんだ時刻を出す。先生が決めた単元（`classUnit`）があれば「先生が決めた単元: （単元の名前）」も出す（教材にない id は出さない）。
  - `studentsCard` の表に、クラスのときだけ、いちばん左に「番号」「ID」の列を足す（`'acct-' + uid` から行を引く）。並びは番号の小さい順（番号なしは後ろ）、同じなら ID の順。
  - 表の下に、次を出す（0 人のものは出さない）:
    - 「まだ始めていない生徒（n 人）: 3 番 s26-003、…」（`empty` と `no-account`。`no-account` には「（まだログインしていません）」を付ける）
    - 「読みこめなかった生徒（n 人）: …」（`failed`・`broken`・`dup`。`dup` には「（同じ ID のアカウントが 2 つあります）」を付ける）。この行は `error` の見た目にする。
    - `truncated` のとき「61 人目からは読みこんでいません。」（`error` の見た目）
  - くわしい表示（`detailCard`）で、履歴が無い生徒の「誤答 x / 解答 y」「最近の取り組み」の所には、「答えの履歴は、クラスの読みこみでは出ません。」と出す（0 件のように見せない）。`classCard` の誤答率は、今ある「—」のままでよい。
- クラスを読みこんでいないときの画面は、今までどおり（端末の記録と、読みこんだファイル）。
- `data-no-ruby` は今のまま。

### 4. `js/app.js`

- `makeCtx()` に足さなくてよいものは足さない。`classProgress` の入れ物は、`ui-teacher.js` の中で `RQ.classProgress.createClassProgress({ link: ctx.state.link, fetch: (...a) => fetch(...a), config: ctx.config.link, unpackState: RQ.sync.unpackState })` として作ってよい（`RQ.classProgress` が無い・`ctx.state.link` が無いときは、カードを出さず、パスコードの画面のまま。**部品が無くても止まらないこと**）。
- `state.teacherClass`（最初は `null`）を足す。アカウントが変わる・端末モードになる・再読みこみのときは `null` に戻す。先生の画面を離れても消さなくてよいが、`teacherUnlocked` が `false` に戻るときは一緒に `null` にする。
- **入口の印**: 開いたときのアドレスに `?teacher=1`（と、あれば `&class=<classId>`）が付いていたら、始まりの処理（`start`）が終わったあとに `go('teacher')` する。`class` の値は `/^[A-Za-z0-9]+$/` に合うときだけ `state.teacherClassWanted` に入れる。そのあと `history.replaceState` で、アドレスからこの 2 つを消す（ほかの部分は残す）。`ui-teacher.js` は、先生と確かめられてクラスの一覧が読めたとき、`teacherClassWanted` が一覧にあれば、それを選んで 1 回だけ自動で読みこみ、`teacherClassWanted` を `null` にする。一覧に無ければ何もしない。
  - 引きつぎの画面（`claim`）が出ているとき・読みこみ中は、今ある決まり（`go` が `claim` に回す）のままでよい。
  - 先生でない人が `?teacher=1` で開いた → パスコードの画面が出るだけ（今と同じ守り）。

## 端の場合

- 不正な入力: `classes`・`members`・`accounts` が `null`・文字列・配列 → 空として扱う（`members` が空なら「このクラスには、まだ生徒がいません。」）。`rika/state` の `v` が 1 でない・`updatedAt` が数でない・`json` が文字列でない・JSON でない・50 万文字より長い → その生徒は `broken`。ニックネームが文字列でない → 今ある `prepareImport` と同じく空にする。`?class=` に記号 → 無視。出席番号が数でない → 番号なしで後ろに並べる。
- 重複と境界: 生徒 0 人。60 人ちょうど（全員）・61 人（60 人と「読みこんでいません」）。同じ ID に uid が 2 つ → `dup`。同じクラスをもう一度読みこむ → 新しい結果に入れかわる。別のクラスを選ぶ → 入れかわる。読みこみ中に画面を離れる・アカウントが変わる → 結果を捨てる。先生自身のプロフィール（先生の端末の記録）は、クラスの一覧には入れない。
- 違反や失敗の見せ方: 全体の失敗 → カードの中の赤い文（前の一覧は残す）。生徒ごとの失敗 → 「読みこめなかった生徒」に名前を出す（だまって消さない）。先生でない → カードを出さない・パスコードの画面。
