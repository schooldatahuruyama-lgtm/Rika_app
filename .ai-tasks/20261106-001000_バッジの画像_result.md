## 動作確認（headless Edge、幅 375px、http://127.0.0.1:8876 の http.server）

- 記録画面: 画像 20 枚すべて読み込み（naturalWidth 160）、表示 44×44、alt は空、draggable="false"、SVG 0 個。取っていないものは filter grayscale(1)・opacity 0.45（親の span は opacity 1 なので二重にならない）。取ったものは filter none
- 結果画面「新しいバッジ！」: span 64px、画像 64px 表示
- ホームの最近 3 つ: 44px で画像表示
- ふりがな on でもメダル内に ruby なし
- 存在しない id（`nope`）で作ると、onerror で SVG に置きかわり、64px で表示、aria-label は残る
- コンソールのエラー・例外なし、横スクロールなし

## 判断した点

- 指示書の `draggable: false` は、`el()` が false の属性を付けないため、avatarBadge と同じく文字列 `'false'` にした
- 大きさ 64 に対応するため、`.badge-medal` の幅・高さを CSS 変数 `--badge-size`（js が style で渡す、既定 44px）にした
- 画像が白背景で、記録画面のタイル（#F4F7FD）や結果画面の黄色いカード（#FFFBEA）の上で白い四角が見えたため、`.badge-img` に `mix-blend-mode: multiply` を付けて白を下地になじませた（このアプリに暗いテーマはないので副作用はない）
- 取っていないときの opacity は画像だけ 0.45 にし、SVG（読み込み失敗時）は今までどおり 0.6 にした

## 気になる点

- `mix-blend-mode: multiply` は指示書にない追加。将来暗い背景の上にバッジを置くと絵が暗くなる
- PRECACHE が 20 枚ぶん増える（オフライン用の初回キャッシュが少し重くなる）
