## js/author.js の仕様（IIFE＋module.exports。`require('./content-registry.js')`、`./judge.js` を使う）

### 入力の形

```js
// 先生の入力
input = { unitId（英小文字・数字・ハイフン。例 'magnet'）, title, grade: 1|2|3, field: '物理'|'化学'|'生物'|'地学', mascot: 'A'〜'F',
          textbook（文字列。空可）, scope（学習範囲。空可）, notes（先生の注意。空可）, stageCount: 2〜6（既定 4） }
// 下書き
draft = { id: unitId, input, status: 'draft'|'checked', preview: false, model, plan: null|Plan, stages: [null|StageDraft...], createdAt, updatedAt（ISO） }
```

### モデルに作らせる形（AI スキーマ。`SCHEMAS.plan`・`SCHEMAS.stage` に JSON Schema として置く。すべての object に additionalProperties:false と required。minimum/maxLength などの数値・文字数の制約は書かない＝説明文で伝える）

```js
Plan = { unitTitle, areas: [{ id（英小文字）, title }...（1〜3）],
         stages: [{ id（英小文字・数字・ハイフン、単元内で一意）, areaId, title, minutes（3〜6）, concepts: [conceptId...（1〜2）], goal（1 文）}...（stageCount 個）],
         concepts: [{ id（英小文字・ハイフン）, title, basic（concept id か null。前提となる概念）, lessonStageId }...（stageCount〜stageCount×2 個）] }
Stage = { lessons: [{ text（**用語** 記法で用語を囲む。80〜160 字）}...（2〜4 枚）],
          warmup: ChoiceAI（予想する問題）,
          problems: [ProblemAI...（4〜6 問。うち 1 問は term:true の fill、1 問以上は figure-choice）],
          retryPool: [ProblemAI...（各概念 2 問以上）],
          checkPool: [{ concept: conceptId, problems: [ProblemAI...（3 問以上）] }...] }
ProblemAI = ChoiceAI | FillAI | FigureChoiceAI（type で区別。共通: concept, prompt, explanation, hint, term（boolean））
ChoiceAI = { type:'choice', options: [文...（3〜4）], answer: 0〜3（options の番号） }
FillAI = { type:'fill', text（[b1] [b2] の穴）, blanks: [{ id:'b1', kind:'word', options:[語...（3）], answer:語 } | { id, kind:'number', answer（数値）, tolerance（数値）, unit（文字列） }] }
FigureChoiceAI = { type:'figure-choice', boxes: [文...（2〜4。ア・イ・ウ・エの枠に入れる短い文）], answer: 0〜3, items: null | [汎用の図の部品...] }
```
- JSON Schema では union を anyOf で書く。`items` の部品は `{ type: string, ...}` の自由な object にしたいが additionalProperties:false が要るので、部品の項目は `type, id, x, y, width, height, r, rx, ry, points, text, label, fill, stroke, color, anchor, size` をすべて optional の項目として並べる（`points` は数値配列の配列）。
- `items` は docs/figures-guide.md の `rect`・`circle`・`ellipse`・`line`・`text`・`arrow`・`region` だけを許す（知らない type は捨てる）。`region` があればその id を選択肢にし、無ければ `boxes` から枠を組む。

### 関数

```js
buildPlanPrompt(input, materials) → { system, user }   // materials = [{ name, kind:'text', text }]（PDF・画像は API 側で content block にするので、ここでは名前だけを本文に書く）
buildStagePrompt(input, plan, stageIndex, materials) → { system, user }
//   system: 中学理科の教材作成の役割、対象学年、日本語、中学生が読める言葉、用語の **記法、問題の形式の決まり（上の AI スキーマの説明）、
//           正解率だけでなく考え方を問う、誤答にもていねいな解説、安全（実験の注意）、教科書の本文や図の転載をしない（要件「教科書の著作権」）、
//           出力は JSON だけ。 user: 単元名・学年・分野・教科書・範囲・注意、（stage のときは）計画の全体とこのステージの担当、プリントの本文。
parseJson(text) → object | null   // ```json フェンスや前後の文を取り除いて JSON.parse。失敗は null
normalizePlan(obj, input) → { plan, errors[] }   // 形を整え、id を英小文字に、ステージ数、概念の lessonStageId・basic の存在を確かめる。errors が空なら plan は使える
normalizeStage(obj, plan, stageIndex, input) → { stage, checkPool, errors[] }
//   stage は教材の形: { id, areaId, title, minutes, concepts, lessons:[{id, text, figure:null}], warmup, problems, retryPool }
//   checkPool は { [conceptId]: [problem...] }
//   id の付け方: カード `<stageId>-c<n>`、warmup `<stageId>-w1`、problems `<stageId>-p<n>`（term は `-t<n>`）、retryPool `<stageId>-r<n>`、checkPool `<conceptId>-k<n>`
//   choice: options → [{id:'a',text}...], answer → 'a'〜'd', figure:null。fill: figure:null、blanks はそのまま（kind・answer を確かめる）
//   figure-choice: figure = boxesScene(boxes) か items から組んだ scene。answer は region の id（'r1'…）。boxes が 2 未満なら choice に落とす
//   ステージの problems に figure-choice が無ければ、term でない最初の choice を figure-choice（boxes = options）に変える（教材の決まり）
boxesScene(labels) → scene   // 320×240。枠 2〜4 を横（3 つまで）か 2×2 に並べる。各枠: rect（白、角丸）＋ text（枠の文。13px 以上、長ければ 2 行に折る: 12 文字で区切る）＋ region（id 'r1'…、label 'ア'…、r 22、枠の左上）
assembleUnit(draft) → { unit, errors[] }   // plan と stages（全部そろっているか）から unit を組む: { id, title, mascot, concepts:[{id,title,basic,lessonStageId,checkPool}], areas:[{id,title,order,stages}] }。
//   errors = validateUnit(unit) ＋ 問題ごとの検査（choice の answer が options にある、fill の word の answer が options にある、figure-choice の answer の region がある）＋ 足りないステージ
toContentJs(unit, input) → 文字列   // content/<id>.js の中身。先頭のコメント（単元名、作成日、「AI 教材作成で作成。先生確認済み」）、IIFE、const unit = <JSON.stringify(unit, null, 2)>、末尾は既存の content/*.js と同じ register の 2 行
newDraft(input, now) / touch(draft, now)
loadDrafts(storageObj) → draft[]（キー 'rika-quest:drafts'。読めなければ []。形の崩れた要素は捨てる） / saveDrafts(storageObj, drafts) → boolean
exportDraftJson(draft) → 文字列 / importDraftJson(text) → { draft, error }
promptText({ system, user }) → コピー用の 1 本の文字列（「--- 指示 ---」「--- 入力 ---」の見出し付き）
```
- すべて例外を出さない。欠けた項目は errors に日本語で書く。
- 用語の記法: カードの text は `**` が閉じていること（validateUnit が見る）。閉じていなければ `**` を取り除く。

## js/author-api.js の仕様

```js
generate({ apiKey, model（既定 'claude-opus-5-5'）, system, user, attachments（[{ kind:'pdf', data(base64) } | { kind:'image', mediaType, data } ]）, schema（JSON Schema か null）, maxTokens（既定 32000）, onProgress(chars), signal, fetchImpl（既定 globalThis.fetch） })
  → Promise<{ text, stopReason, usage, model }>
```
- `POST https://api.anthropic.com/v1/messages`。ヘッダ: `content-type: application/json`、`x-api-key`、`anthropic-version: 2026-10-21`、`anthropic-dangerous-direct-browser-access: true`（ブラウザから直接呼ぶために必要）、`anthropic-beta: server-side-fallback-2026-07-01`。
- 本文: `{ model, max_tokens, stream: true, system, fallbacks: 'default', output_config: schema ? { format: { type: 'json_schema', schema } } : undefined, messages: [{ role:'user', content: [ ...attachments を document（{type:'document', source:{type:'base64', media_type:'application/pdf', data}}）/ image（{type:'image', source:{type:'base64', media_type, data}}）に, { type:'text', text: user } ] }] }`。`thinking` は書かない（既定の adaptive のまま）。
- SSE を読む（`content_block_delta` の `text_delta` をつなぐ。`message_delta` の `stop_reason`・`usage`）。`onProgress` に累計文字数。
- エラー: HTTP 401 → `Error('API キーが正しくありません')`、429 → 「混み合っています。少し待ってやり直してください」、400 で本文に `output_config` を含むとき → `schema` なしで 1 回だけやり直す、その他 → `Error('API エラー ' + status + ': ' + 本文の error.message)`。ネットワーク失敗 → 「通信できません（オフラインか、接続がありません）」。`stop_reason` が `refusal` → 「モデルが生成を断りました」、`max_tokens` → 「出力が長すぎて途中で切れました（ステージ数を減らすか、もう一度）」。
- `signal` で中断できる。
- `readFileAsAttachment(file)`（ブラウザ用。FileReader で base64。pdf → kind 'pdf'、image/png|jpeg|webp → 'image'、text/markdown/plain → { kind:'text', name, text }。それ以外は reject）。Node では使わないので `typeof FileReader` で守る。

## テスト

- `tests/author.test.js`: 偽の AI 出力（plan 1 つ、stage 2 つ。figure-choice は boxes 版と items 版、fill の word と number、term の問題）→ normalizePlan/normalizeStage → assembleUnit で errors が空、`validateUnit` も空。figure-choice が無いステージで choice が枠選びに変わる。boxes が 1 つなら choice に落ちる。`**` が閉じていないカードが直る。answer が options に無い choice は errors に出る。parseJson がフェンス付きでも読める。toContentJs を vm で評価すると `register` が呼ばれ、validateUnit が空。loadDrafts/saveDrafts（偽 storage。壊れた JSON → []）。exportDraftJson/importDraftJson の往復。
- `tests/author-api.test.js`: 偽 fetch が SSE（`event: content_block_delta` 数回 → `message_delta` → `message_stop`）を ReadableStream で返す → text がつながる、onProgress が増える、ヘッダに `anthropic-dangerous-direct-browser-access`、本文の `output_config.format.schema` が渡る。401 → メッセージ。400（output_config）→ 2 回目は schema なし。`max_tokens` で止まった → エラー。
- `npm test` 全件成功。
