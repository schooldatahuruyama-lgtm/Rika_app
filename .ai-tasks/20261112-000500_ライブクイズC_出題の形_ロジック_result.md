## 指示書とちがう点・判断したこと

1. **choice の問題にも `kind: 'choice'` を付けた**（questionFromProblem・customQuestion・safeQuestion の戻り値）。指示書は customQuestion だけ「kind を入れる」と書いていたが、形をそろえるため。既存テストの deepEqual 2 件に `kind` を足した。
2. **自由記述の答えが 41 文字以上なら切りつめず null**（指示書の「MAX_TEXT_ANSWER 文字まで」をテスト観点「41 文字 → null」に合わせて解釈）。
3. **customQuestion の text の重なりは `normalizeText` が同じものを重なりとみなす**（例: 「葉緑体」と「葉緑体。」は 1 つに）。正規化すると空になるもの（「。」だけ等）も落とす。
4. **safeQuestion は multi の answer を cleanAnswer で選択肢の順に並べ直して保持する**（'c,a' → 'a,c'）。text の answer は trim して保持。
5. **tally の counts**: text では選択肢が無いので `{}`。order では選択肢 id → 0 のまま（数えない）。
6. **数の答えの比べ**は `|値 − value| ≤ tolerance + 1e-9`（judge.js の EPS と同じ考え方）。
7. 気づいた点（未対応・画面側 D の範囲）: 今の画面 `js/ui-live-host.js:365` は `questionFromProblem` を使っているので、**画面 D ができるまでは教材の fill 問題が text として先生の問題一覧に出る**（いまの画面は選択肢の無い問題をうまく表示できない可能性がある）。また `js/ui-live.js:639`・`js/ui-live-host.js:516/587/594` は `q.answer` との直接比較なので、D で `isCorrect` に置きかえる必要がある。number の穴埋めは「100倍」のように単位まで打つと不正解になる（指示書どおり）。
