ユーザー指示: 「以下の人が作ったカフートの問題を参考に問題数を増やして」（Kahoot のプロフィール「中学理科 予習復習問題」。公開クイズ 100 本・1,692 問）。

## いちばん大事なこと（他人の作った問題の扱い）

- 参考にするのは、**ほかの先生が Kahoot で公開しているクイズ**。文章と選択肢はその人の著作物なので、**文をそのまま写さない・言いかえただけにしない**。使ってよいのは「何を問うか（ねらい）」「用語・数値の例」「よくある誤答の例」だけ。
- 書き方: 場面・言い回し・数値・選択肢の組み合わせを自分で組み立て直す。同じ事実を問う問題（例「酸素を発生させる薬品は？」）は事実が共通なので作ってよいが、**問題文は自分の言葉**で書く。
- controller が機械で確かめる: 新しいステージの文（問題文・選択肢・解説・ヒント・カード）と Kahoot の文に、記号・空白を除いて **16 字以上同じ並び**があれば指摘が出る。担当は自分でも実行して、指摘が 0 になるまで直す（ふつうの理科の決まり文句だけが一致する場合は、報告にその文を書いて残してよい）:
  ```
  node "C:\Users\yan12\AppData\Local\Temp\claude\6ceb39c66ba68078\06597260-147f-4081-8b2f-691841b121f6\scratchpad\kahoot\overlap.js" "C:\Users\yan12\Documents\keita\AI開発\理科アプリ" 16
  ```
- 画像を見て答える問題（「これは何？」の写真など）は、**図を `js/figures.js` の部品で描き直せる内容だけ**使う（器具の部分、回路、断面、グラフ、天体の配置など）。写真の同定（植物の名前当てなど）は使わない。
- Kahoot のサイトにはアクセスしない（材料は下のファイルにある）。報告には「参考: Kahoot『<クイズの題名>』」とだけ書く。

## 反映の形（決めたこと）

1. ステージ id `<単元id>-kq<n>`（n は 1 から）、`title` は「クイズ n: <内容>」、`free: true`、`minutes` 5〜7。**入れる領域**は内容の合う分野の領域（各単元の `areas` のどれか）。領域の中の並びは 基本 → プリント → ドリル → クイズ の順。`areaId` はその領域の id。
2. ステージの数: 1 ステージは問題 10 問以上（problems 6 ＋ retryPool 4 以上）。参考にできる問題（文だけ ＋ 図で描き直せるもの）がおよそ 15 問あるごとに 1 ステージを目安にし、小さいクイズは内容の近いものをまとめる。**上限**（担当表）を超えない。参考が少ない単元は、参考にできる範囲だけで作る（無理に数を増やさない）。
3. ステージの中身はドリルと同じ: `lessons` 2〜3 枚（40〜160 字、用語は `**語**`、図は汎用の部品。写真・anim は付けない）、`warmup` 1 問（choice）、`problems` 6 問（用語問題 `term: true` 1 問、figure-choice か drag 1 問以上）、`retryPool` 4 問以上（各概念 2 問以上、用語問題 1 問）。
4. **回答の形**（ユーザー指示）: ステージごとに 選択式 50% 以下・記述（`word` ＋ `number`）3 問以上・図操作（figure-choice か drag）2 問以上（problems ＋ retryPool で数える。warmup は除く）。Kahoot は 4 択ばかりなので、意識して穴埋め・数値・図から選ぶ・並べる（drag）に組み替える。確認:
   ```
   node "C:\Users\yan12\AppData\Local\Temp\claude\6ceb39c66ba68078\06597260-147f-4081-8b2f-691841b121f6\scratchpad\drill_survey\kinds.js" "C:\Users\yan12\Documents\keita\AI開発\理科アプリ" kq
   ```
   （第 3 引数 `kq` でクイズのステージだけを数える。flag が空になること）
5. 概念は既存の id を使う（新しい概念は足さない）。`prompt` は 120 字以内、`region` は 2〜8 個。数値は `fill` の `number`（`tolerance` 0 か 0.1、`unit`）。
6. 既存の問題（基本・プリント・ドリル）と同じ問いをくり返さない。Kahoot にある「思考問題」「応用問題」（理由を問う、条件を変えて考える）を優先して取りこむ。
7. id: 問題 `<単元id>-kq<n>-p<k>`（用語 `-t<k>`、warmup `-w1`、retryPool `-r<k>`）、カード `<単元id>-kq<n>-c<k>`。
8. `docs/reports/content/<単元>.md` に「クイズ（Kahoot を参考に、2026-11-22 追加）」の節を、ドリルの節と同じ形で足す（カードの要旨、問題の表、「参考: Kahoot『題名』」、「自信のない点」）。冒頭の領域の行に 1 行足す。

## 端の場合

- `.ai-tasks/20261121-152500_ドリル問題_共通.md` の「端の場合」をそのまま守る（数の答えは数、空欄 1 つ、選択肢 3〜4 で正解 1 つ、region は重ならない、など）。
- Kahoot の「複数選択」は、アプリには複数正解の形がないので、1 つを問う choice か、`multi` ではなく figure-choice・fill に組み替える。「並べかえ（jumble）」は drag（順に置く）か、「正しい順に並んでいるものを選ぶ」choice に。
- Kahoot の正解が理科として疑わしいものは採用せず、報告の「自信のない点」に書く。
- 同じクイズに同じ事実の問題がくり返しあっても、アプリでは 1 問にまとめる。
- 1 ステージの中で `word` の答えが同じ語になる問題を 3 問以上並べない。
- 違反や失敗の見せ方はアプリの決まりどおり（責めない解説）。

## 守ること

- 編集してよいのは担当の `content/<単元>.js`・`docs/reports/content/<単元>.md`・自分の報告ファイルだけ。`js/*`・`tests/*`・`index.html`・`sw.js`・`content/readings.js`・既存のステージは触らない。
- `npm test` を実行し、担当の単元に関する失敗がないこと（`tests/ruby.test.js` の網羅率だけ許容。`node tools/ruby-missing.js --all` の自分の単元の語を報告に書く）。
- `content/light.js` は `tests/content-light.test.js` の検査がある（STAGE_COUNT 14、TERM_ALLOW）。light にステージを足すと落ちるので、落ちた内容と「ステージの用語の一覧」を報告に書く（テストは controller が直す）。
- 自分のポート（8890 番台 ＋ 担当番号）の `python -m http.server` と headless Edge で、新しいステージを 1 つ以上通す。headless Edge を止めるときは **コマンドラインに `--headless` をふくむ msedge だけ**を止める（利用者の Edge を止めない）。終わったら http.server も止める。
- git 操作なし。サブエージェントなし。パッケージ追加なし。
