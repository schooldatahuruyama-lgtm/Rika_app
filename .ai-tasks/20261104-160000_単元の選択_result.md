## 指示書と違えた点

1. **`js/units.js` の mascot の取り方**: 指示書は「`recommend.js` の書き方に合わせる」だが、`index.html` の並び（指示どおり units.js は recommend.js の直後）では `js/mascot.js` が units.js より後に読み込まれるため、読み込み時に `root.RikaQuest.mascot` を取ると undefined になる。`mascot.js` が `figures()` でしているのと同じく、使うときに取る関数 `mascot()` にした。
2. **単元ボタンの先生の絵**: 指示書は `svgBox(..., 'unit-teacher')` だが、`svgBox` は `div` を作り、`button` の中に `div` は置けない（HTML の決まり）。`span.unit-teacher`（`aria-hidden`）に同じ `<img>` 文字列を入れた。見た目・class は同じ。
3. **`content/curriculum.js` の項目を `Object.freeze`**: テスト 3「元を変えられない」を、配列だけでなく項目にも効かせるため。表の編集（ソースの書きかえ）には影響しない。
4. CSS は目安に加えて、`min-height: 64px`（指で押せる高さ）、`:hover`・`:focus-visible`（既存のボタンと同じ橙の outline）、`.unit-teacher img` の大きさ、行の高さを足した。`.progress-unit` の上の余白は、カード見出しの直後（`.card-title + .progress-unit`）も 0 にした（`:first-child` だけでは、最初の h3 の前に h2 があるため効かない）。
5. `renderHome` の `unit` は `unitId ? ctx.reg.unit(unitId) : null` とした（`reg.unit(null)` も null なので結果は同じ）。

## 気になる点

- **作業ツリーの `npm test` が 1 件失敗**（上記）。別の作業（汎用の図の部品）の途中の変更によるもの。そちらの作業が終わってから全体で `npm test` をやり直す必要がある。コミット時は `js/figures.js`・`tests/figures.test.js` をこの変更に混ぜないよう注意。
- `setUnit` は指示書どおり「profile.unitId を書いてから `save()` の結果を返す」。保存に失敗した場合、画面には「単元を変えられませんでした。」と出るが、メモリ上の unitId は変わっている（このセッションの間は新しい単元で動く）。保存できない環境向けのお知らせとしては少しずれる。必要なら、失敗時に元の値へ戻すか、`reportSave` と同じ文にするのがよい。
- 教材が 1 つも読み込まれていないとき、ホームの「今日のクエスト」は `todayQuest` が null を返すため「全部クリア！」になる（前からの動き。今回は「単元をえらぶ」ボタンが付く）。
- `ctx.unitId` は getter で、呼ぶたびに `units.list` を作り直す。今は単元 19 個なので問題ないが、単元をえらぶ画面は 1 回だけ読む形にしてある。
