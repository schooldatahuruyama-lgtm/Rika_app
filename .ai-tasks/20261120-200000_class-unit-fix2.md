# 実装指示書（修正 2）: クラスの単元 — 受け取りずみの印に時刻を付け、新しい方を残す

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。もとの指示書は `.ai-tasks/20261120-190000_class-unit.md` と `.ai-tasks/20261120-193000_class-unit-fix1.md`、レビューは `.ai-review/20261120-183635_round2.md`。

## 目的

レビュー round 2 の指摘（High）に対応する。修正 1 では「受け取りずみの印（`classUnitApplied`）がアカウント側とちがえば、アカウント側に合わせる」とした。しかし、端末側の方が新しい場合（端末 A が新しい単元 Y を受け取り、生徒が Z を選んで、まだ送っていない。その間に、古い単元 X のままの端末 B が記録を送った）にも、アカウント側（古い X）に戻してしまい、そのあと Y がもう一度当たって、生徒の選んだ Z が消える。

## 変える内容

### 1. `js/app.js`

- `applyClassUnit()` で `profile.classUnitApplied = unitId` にするとき、`profile.classUnitAppliedAt = Date.now()`（アプリの中で時刻を取っている今ある方法に合わせる）も入れる。印を消すとき（先生が「決めない」・教材にない id）は、`classUnitAppliedAt` も消す。保存に失敗して元に戻すときは、`classUnitAppliedAt` も元に戻す。
- `normalizeStore`: `classUnitAppliedAt` が、0 以上の有限の数でなければ消す。`classUnitApplied` が無いのに `classUnitAppliedAt` だけあるときも消す。
- 生徒が単元を選ぶ `setUnit` は変えない（印も時刻も変えない）。

### 2. `js/sync.js`（プロフィールを合わせる所）

修正 1 で足した決まりを、次に置きかえる。端末のプロフィールを残す場合（`profileDirty`）だけに当てる。

- 両方の印（`classUnitApplied`）が同じ（両方とも無い場合もふくむ）→ 端末側のまま。`classUnitAppliedAt` は、両方にあれば大きい方。
- 印がちがう → 「受け取った時刻」（`classUnitAppliedAt`。数でない・無いときは 0。印が無い側は、時刻があっても 0 として扱う）を比べる。
  - アカウント側の時刻の方が**大きい** → 合わせた結果の `classUnitApplied`・`classUnitAppliedAt`・`unitId` を、アカウント側の値にする（`unitId` がアカウント側に無ければ、端末側の `unitId` のまま）。
  - それ以外（端末側が大きい・同じ）→ 端末側のまま。
- アカウント側の印・時刻が、文字列・数でないとき → 無いものとして扱う。
- 端末のプロフィールを残さない場合（アカウント側を使う場合）は、今までどおりアカウント側。
- ほかの項目の合わせ方、`id` を端末側のままにする決まり、`changed` の知らせ方は変えない。

### 3. `README.md`

- 分かっている限界として 1 行足す: 「2 台の端末の時計が大きくずれていると、先生の単元が 1 回よぶんに当たり、生徒が選んだ単元が先生の単元に戻ることがあります（選び直せます）。」

## 端の場合

- 不正な入力: `classUnitAppliedAt` が文字列・負の数・`NaN`・`Infinity` → 無いもの（0）として扱い、`normalizeStore` で消す。
- 重複と境界:
  - （レビュー round 2 の場面）端末 A: 印 Y（時刻 200）・単元 Z・送っていない変更あり。アカウント側: 印 X（時刻 100）→ A は印 Y・単元 Z のまま。そのあとの単元の読みこみ（先生は Y）で切りかわらない。
  - （レビュー round 1 の場面）端末 B: 印なし・送っていない記録あり。アカウント側: 印 X（時刻 100）・単元 Z → B は印 X・単元 Z になる。先生が X のままなら切りかわらない。
  - 段階 3 の最初の版（時刻なし）で受け取った印どうし → 時刻は両方 0 で同じなので、端末側のまま（そのあとの読みこみで、先生の単元と比べ直される）。
  - 時刻が同じで印がちがう → 端末側のまま。
- 違反や失敗の見せ方: 変えない。

## テスト

- `tests/sync.test.js`: 上の合わせ方のすべての場合（印が同じ／ちがって端末が新しい／ちがってアカウントが新しい／時刻が同じ／片方に印なし／時刻が数でない／アカウント側に `unitId` なし）。送っていない記録が失われないこと。
- `tests/link.test.js`（アプリ全体）:
  - レビュー round 2 の場面: 端末は Y を受け取りずみ・Z を選択・未送信、アカウント側は古い X で記録だけ新しい → 同期と単元の読みこみのあと、単元は Z のまま・印は Y。
  - レビュー round 1 の場面（修正 1 のテスト）が、時刻つきでも通ること。
  - 単元を当てると `classUnitAppliedAt` が入り、「決めない」で印と一緒に消えること。保存の失敗で元に戻ること。
- `npm test` がすべて成功すること。
