# 指示書（共通）: ミニプリントで足したカードの図を精査する（写真・動く図の計画づくり）

作成: Claude Code（Fable）2026-11-06。担当: Opus ×3（学年ごと）。この指示書では **教材ファイルは変えない**。計画の文書だけを書く。
ユーザー指示: 「新しく増やした問題も画像とアニメーションを精査してください」（前回と同じ方針: 動物・植物・器具・実物は図より写真（生成画像＋文字）、動きで分かるものは動く図）。

## 対象

領域「ミニプリント」のステージ（id に `-mp` を含む）と新単元 `basics` の **解説カード 300 枚**（`content/<単元>.js` の `lessons`）と、図が核になっている問題の図（figure-choice・drag の figure。写真にしたほうが分かりやすいものだけ）。

## 判断の基準（前回 docs/image-plan.md・docs/anim-plan.md と同じ）

- **写真（生成画像）にする**: 生き物・からだ・器具・装置・岩石・雲や天気の写真・実験のようす など、実物の見た目が大事なもの。文字（名前・矢印・引き出し線）はアプリで重ねるので、画像には文字を入れない。
- **動く図にする**: 変化・流れ・向き（電流と磁界、前線の動き、波、分子の運動、天体の動き、消化や血液の流れ、力の作図の手順など）。
- **既存のものを使い回す**: `assets/images/<単元>/*.jpg`（110 枚。`docs/image-plan.md` に何の写真かの一覧）と、動く図の種類 88 本（`docs/anim-plan.md`・`docs/anim-guide.md`、`js/anim-*.js` の `register(kind…)`）。同じ内容なら新しく作らず使い回す（カード側に `photo('<id>')` か `anim: '<kind>'` を書くだけ）。
- **そのまま（簡略図のまま）**: 概念図・表・計算・回路図記号など、簡略図のほうが分かりやすいもの。

## 出力（1 ファイル。`docs/plans/mp-figures-<学年>.md`。担当: 1nen / 2nen / 3nen）

```
# ミニプリントのカードの図の精査（<学年>）

## まとめ
| 単元 | カード数 | 写真（新規） | 写真（使い回し） | 動く図（新規） | 動く図（使い回し） | そのまま |

## 写真（新規）
| # | カード id | 単元 | 画像 id（<単元>-mp<n>-c<k>） | 写すもの（生成の指示文。日本語。共通の頭「中学理科の教材用の図版を 1 枚。写真のようにリアルな質感、背景は白、文字・ラベル・矢印・数字は一切入れない、横長 4:3。」は書かず、続きだけ） | 重ねる文字（名前と位置の目安: 左上/右下 など） | 合格の基準（写真で確かめること 1 つ） |

## 写真（使い回し）
| カード id | 使う画像（assets/images/…） | 重ねる文字 |

## 動く図（新規）
| # | カード id | 単元 | kind（接頭辞つき。既存の命名に合わせる） | 何がどう動くか（2〜3 文。restT で静止図と一致させる方針も） | 分野のファイル（anim-physics/chem/bio/earth） |

## 動く図（使い回し）
| カード id | kind |

## 問題の図を写真にするもの
| 問題 id | 画像 id | 写すもの | region の置き方 |

## そのまま（理由は 1 語で: 概念図/表/計算/回路/作図）
（カード id を列挙するだけ）
```

- 判断に迷ったら「そのまま」にせず、理由を書いて写真か動く図に入れる（先生の方針は「写真のほうがよい」）。
- 画像 id はカード id と同じにする。使い回しのときは既存の id。
- 1 枚の写真に複数のものを並べる指示（「4 種を並べる」）は、前回と同じく可。
- 読むもの: 担当の `content/*.js` の `-mp` ステージ（と basics）、`docs/image-plan.md`（写真の一覧と指示文の書き方）、`docs/anim-plan.md`（動く図の一覧）、`docs/anim-guide.md`。

## 守ること

教材ファイル・js・tests を変えない。計画のファイル 1 本だけを書く。git 操作なし。ブラウザなし。サブエージェントなし。終わったら、まとめの表の数字を 100 字程度で返す。
