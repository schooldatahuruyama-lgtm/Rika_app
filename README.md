# 理科クエスト（試作1）

中学校理科の e-learning Web アプリの試作です。生徒がブラウザで問題に取り組み、学習の記録が手元（その端末のブラウザ）に残ります。

- 試作1 の教材は「光の世界」の 4 領域 × 2 ステージ = 8 ステージ（光の直進 → 反射 → 屈折 → 凸レンズ）。
- 問題は 5 形式: 選択式、穴埋め、図の場所を選ぶ、光線を引く、光学要素（物体・スクリーンなど）を動かす。
- 生徒は架空の生徒（ニックネームとアバター）だけを使います。実名は入れません。
- インストール不要、外部ライブラリなし（HTML・CSS・JavaScript だけ）。Chrome または Edge で使います。

## 開き方

- **かんたんに開く:** `index.html` をダブルクリックして Chrome または Edge で開く。ネット接続もサーバーも不要です。ただしこの開き方（`file://`）ではオフライン対応は効きません（アプリ自体はそのまま使えます）。
- **オフライン対応つきで開く:** このフォルダで次を実行し、Chrome または Edge で http://127.0.0.1:8765/ を開く。
  ```
  python -m http.server 8765 --bind 127.0.0.1
  ```
  Service Worker は https または localhost（127.0.0.1）でだけ動くため、同じパソコンで http://127.0.0.1 として開いたときにオフライン対応が効きます。ほかの端末から LAN の IP を http で開いた場合、アプリは使えますがオフライン対応は効きません。

## はじめての流れ

1. **プロフィールを作る:** ニックネーム（12 文字まで、実名は入れない）とアバターを選んで「プロフィールを作る」。先生が複数の生徒を演じられるよう、何人でも作って設定画面で切り替えられます。
2. **ホーム:** 「いまの単元」「今日のクエスト」「レベルと経験値」「連続学習」のカードと、「学習マップへ」「記録を見る」「設定」のボタン。
3. **単元をえらぶ:** ホームの「いまの単元」の「単元をえらぶ」で、中学 1〜3 年の単元一覧（学年ごと。各単元に担当の先生の絵）が出ます。教材のある単元だけ押せて、まだ教材のない単元は「準備中」です。選んだ単元は生徒（プロフィール）ごとに保存され、ホームの今日のクエスト・学習マップがその単元になります。記録画面には教材のあるすべての単元の進捗と理解度が出ます。
4. **学習マップ:** 領域とステージを選ぶ → ステージ入口で「解説から学ぶ」か「問題から挑戦」を選ぶ。
5. **見た目と読みやすさ（設定画面）:** 「アクセントカラー」で画面の色（あお・みずいろ・みどり・むらさき・ピンク）を、「ふりがな」で漢字に読みがなを付けるか（なし・つける）を選べます。押すとすぐ変わり、生徒（プロフィール）ごとに保存されます。正解の緑・おしいのオレンジ・星の色は変わりません。

## 記録について（大事）

- 記録はその端末のブラウザ（localStorage）だけに保存されます。ブラウザのデータ削除や端末の変更で**消えることがあります**。
- 設定画面の「記録を書き出す」で JSON ファイル（`rika-quest-*.json`）にバックアップでき、「記録を読み込む」で元に戻せます。
- 書き出したファイルには学習記録が入るので、Git には入れない設定にしてあります。

## 先生用の確認画面

生徒の進捗・理解度・苦手な概念を一覧で見る、先生向けの画面です（サーバーはないので、記録ファイルで集めます）。

- **開き方:** 設定画面の「先生用」カードの「先生用の確認画面を開く（パスコード）」。プロフィールがなくても開けます。
- **パスコード（先生だけが開けるように）:**
  - 先生画面は、はじめから**初期パスコード**（4〜8 桁の数字）で守られています。初期パスコードは**配付時に先生に伝えます**（この README には書きません）。生徒がパスコードを決めたり切り替えたりする画面はありません。
  - 先生画面を開くと「パスコード」の入力だけが出ます。合えば開きます。5 回まちがえると 60 秒待つまで入力できません（画面を閉じても続きます）。
  - 先生画面を開いたあとは「先生画面を閉じる」で閉じます。ほかの画面へ移ったときも閉じ、次に開くときはまたパスコードが要ります。
  - **パスコードを変える:** 開いた先生画面の「パスコードを変える」で、今のパスコードを入力してから新しいパスコードを 2 回入力します。変えたパスコードは**その端末だけ**に保存され、ほかの端末は初期パスコードのままです。
  - **忘れたとき:** 設定の「すべて削除」で、その端末で変えたパスコードが消え、**初期パスコードに戻ります**（プロフィールと記録も消えるので、先に「記録を書き出す」で記録を残してください）。サーバーがないので、ほかに確かめ直す方法はありません。
  - 初期パスコードを変える（開発者向け）: `node tools/teacher-passcode.js <新しい 4〜8 桁の数字>` で出る 1 行を `js/config.js` の `teacher` に貼り、`sw.js` の `VERSION` を上げます。パスコードそのものはファイルに書きません。
  - パスコードは目安の鍵です。生徒がのぞき見しないためのもので、ブラウザの開発者ツールを使える人から記録を守るものではありません（初期パスコードの salt と hash はアプリのファイルに入っています）。
- **生徒の一覧:** この端末に保存されている全員の、単元・レベル・連続日数・最終学習（今日／きのう／n 日前／なし）・クリアしたステージ数・理解度（できた・もう少し・まだ の概念の数）・苦手な概念が表で出ます。行を押すと、その生徒の単元ごとの進捗と理解度、苦手な概念（誤答数 / 解答数）、最近の取り組み 20 件が下に出ます。
- **クラスのまとめ:** 「まだ」の生徒が多い概念を 10 件（人数と誤答率）。
- **ほかの端末の記録を合わせて見る:**
  1. 生徒の端末で、設定画面の「記録を書き出す」を押し、`rika-quest-*.json` を保存する。
  2. ファイルを先生の端末に集める（USB メモリ、学校の共有フォルダなど）。
  3. 先生の端末の確認画面で「記録ファイルを読みこむ」を押し、ファイルを選ぶ（まとめて複数選べます）。
  - 読みこんだ記録は確認画面の中で見るだけで、**この端末の学習記録には入りません**。ページを閉じる・再読み込みする・「読みこんだ記録を消す」を押すと消えます。
  - 同じ生徒（同じプロフィール）が複数のファイルにあるときは、いちばん新しく学習した記録を使います。
- **CSV で書き出す:** 一覧を `rika-quest-teacher-<日付>.csv`（Excel などで開ける）に書き出します。理解度・苦手は記録から計算した目安です。

## 試作品の検証項目の確かめ方

要件定義書の「試作品の検証項目」1〜6 を、次の手順で確かめられます。タブレット・スマホ幅は、Chrome/Edge の開発者ツール（F12）のデバイス表示で幅 768px と 375px にして見ます。

1. **学習マップで進める:** ホーム →「学習マップへ」。4 領域が縦の道に並び、どの領域の 1 つ目のステージからでも始められる。1 つ目をクリアすると 2 つ目が開き、ステージに状態（未着手・途中・クリア）と星（0〜3）が付く。
2. **解説から／問題から始める:** ステージ入口で「解説から学ぶ」（解説カード 3 枚 → 予想 1 問 → 問題）と「問題から挑戦」（すぐ問題）の両方を試す。問題の途中でも「解説を見る」で解説を開ける。
3. **5 形式の操作:** 「光はまっすぐ進む」（直進 1）に選択式・穴埋め・図の場所を選ぶ・物体を動かす、「反射の法則」（反射 1）と「屈折の向き」（屈折 1）に光線を引く、「焦点と光の集まり方」（凸レンズ 1）に光線を引く・スクリーンを動かすがある。指（マウス）でなぞる・動かす・タップして選ぶを確かめる。
4. **誤答 → 類題 → 学び直し → 復帰:** 反射 1 をクリアしてから「鏡に映る像」（反射 2）で 1 問目をわざと間違える →「おしい」と解説 → 同じ内容の類題が出る → また間違える →「反射の法則に戻って確かめよう」が出る。「戻る」で確認問題 2 問 → 正解すると元のステージの続きに戻る。「あとで」を選ぶと続きに進み、結果画面に「〜を確かめるのがおすすめ」と出る。
5. **正解率以外の取り組みが経験値になる:** 結果画面の「獲得した経験値」に内訳（答えた、正解、1 回目で正解、復習で正解、学び直し、解説を読んだ、ステージクリア、今日の学習）が出る。間違えても「答えた」「復習で正解」などで経験値が入ることを確かめる。記録画面には理解度の目安（まだ / もう少し / できた）が経験値とは別のカードで出る。
6. **オフラインで使い続けられる:** 上の「オフライン対応つきで開く」で一度開き、設定画面の「オフラインで使える教材」が「済」になるのを確かめる。サーバーを止めて（コマンドの画面で Ctrl+C）ページを再読み込みしても学習を続けられ、答えた記録が残る（サーバーを再開して開き直しても残っている）。

## オフライン対応のしくみ

- Service Worker は https または localhost（127.0.0.1）でだけ動きます。LAN の IP（例: `http://192.168.x.x:8765/`）を http で開いたときや `file://` では、オフライン対応は使えません（アプリ自体はそのまま使えます）。
- https か http://127.0.0.1 で開いたときだけ、Service Worker（`sw.js`）がアプリ本体（HTML・CSS・JS）と教材（光の世界）をこの端末のブラウザに保存します。その後は通信がなくても、同じ URL を開けば学習を続けられます。
- 何を保存するかは `sw.js` の `PRECACHE` に書いてあります。`index.html` に読み込むファイルを足したら、ここにも足してください（`npm test` が食い違いを見つけます）。

### 教材やプログラムを更新したとき

- 教材やプログラムを更新したら `sw.js` の `VERSION` を上げる（例: `2026-11-04-11` → `2026-11-04-12`）。
- 次にオンラインで開いたときに新しい版に入れ替わり（古い保存は消える）、もう一度開き直すと新しい版で動きます。記録（localStorage）は残ります。
- `VERSION` を上げ忘れると、ブラウザは古い版を使い続けます。

## 教材の内容について

教材の文章・図・問題はすべて自作です（教科書名・出版社名は書いていません）。理科としての正しさ（用語、図の角度、正解・解説の内容）は、**授業で使う前に先生が確認してください**。教材は `content/light.js` にまとまっています。

### 単元を足す手順

1. `content/light.js` と同じ形で `content/<id>.js` を作る（`unit.id` を `<id>` にする。担当の先生は `unit.mascot` に `'A'`〜`'F'`）。
2. `index.html` の `<script src="content/light.js">` の後に `<script src="content/<id>.js"></script>` を足し、`sw.js` の `PRECACHE` にも同じ順で `'content/<id>.js'` を足して、`VERSION` を上げる（`npm test` が食い違いを見つけます）。
3. `content/curriculum.js` の単元一覧の表に同じ `id` の行があれば、その学年の欄に出て押せるようになります（「準備中」が消える）。表にない `id` の単元は「その他」の欄に出ます。
- 単元一覧の表（`content/curriculum.js`）は先生が編集してよいファイルです。単元名・学年・分野・担当の先生を書きかえられます（項目の意味はファイルの冒頭に書いてあります）。

### ふりがなの辞書を増やす

ふりがなは `content/readings.js` の辞書（漢字の語 → 読み）で付けます（`js/ruby.js` が左から長い語を優先して当てはめる）。教材を足したり文を書きかえたりしたら:

1. `node tools/ruby-missing.js` を実行する。辞書にない漢字の語が、回数の多い順に出ます（`--all` で全件）。
2. 出てきた語を `content/readings.js` の `WORDS` に足す。複合語はまとめて 1 語（`'初期微動継続時間': 'しょきびどうけいぞくじかん'`）、送りがなのある語は語幹まで（`'動か': 'うごか'`）。同じ漢字で読みが変わるときは送りがなで区別します（`'重な': 'かさな'`、`'重い': 'おもい'`）。
3. `node tools/ruby-missing.js --split` で、辞書の短い語に分かれて読まれた並び（例: 辞書に「電流」がないと「電」＋「流（なが）」になる）も確かめ、誤読があれば複合語を足す。`--single` では 1 字の語として読まれた所が前後の文字つきで出るので、文脈で読みが変わる字（「行う」の 行、「葉の表」の 表 など）を確かめ、送りがなや前後の文字つきのキー（`'行う': 'おこなう'`、`'葉の表': 'はのおもて'`）を足す。
4. `npm test`（`tests/ruby.test.js` が、辞書の形と、教材の単元ファイル・画面の文字のそれぞれで漢字の 98% 以上に読みが付くことを確かめます。執筆中で辞書が追いつかない単元は、一時的に `tests/ruby.test.js` の `COVERAGE_EXCLUDE` に入れて除けます（今は空）。
